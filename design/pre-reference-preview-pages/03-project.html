Project

One codebase on one page: its sessions with their last line, its branches, and the CLAUDE.md Claude reads there. The page shows what Loom already holds and starts nothing by itself. One column on the canvas, the project's name on the window's header line, and the harness's mark on every session.

01

The head is the header

The project's mark, its name in title type and its folder sit on the window's header line, where a session's title would be. What you can do sits at the trailing edge: ⋯ and New session.

02

Sessions read like the sidebar

A row is the status, the harness's mark, the title and its last line, then the branch and the time. The list lies flat on the canvas between hairlines, and the pill comes on hover.

03

Cards hold the summaries

Presets and the past seven days are the only lifted things on the page: beside the list, or above and below it when the pane is narrow.

04

Three tabs, one at a time

Sessions, Branches and Instructions are view tabs. Branches and Instructions read in a column of at most 700, and the page opens on Sessions every time.

05

The model picks the harness

On a new session, the one chip lists Claude Code's and Codex's models together. The model you pick decides the harness the session starts on, and the session keeps it.

06

Nothing new runs

The page reads the catalog, the usage index, the git files and CLAUDE.md once per visit, and lets them go when it closes. Nothing is watched.

The repo workflow is in AGENTS.md. If it is not already in your context, read it at session start.

Main session: start with STATUS.md → AGENTS.md → ROADMAP.md; check DECISIONS.md before assuming scope or permissions. Subagent: your Brief is your task; read the docs it names plus DEVELOPMENT.md §2–§4 before building or testing.

Hard rules (details in AGENTS.md and DEVELOPMENT.md):

  • Real ~/.claude and ~/.codex, the installed Loom Dev app, the default dev catalog and the daily Loom app are never test material.
  • No parallel builds; heavy tests and on-screen measurements only when the user says the computer is idle.
  • Keep other agents' changes; never stash, reset, checkout or clean them. No commit, push or PR unless the user asks.
  • Only the main session writes STATUS, ROADMAP, DECISIONS and plans; subagents report Doc impact.
  • Docs and code in English; talk to the user in Turkish.

Parts

Each part of the page in its one look, with its states. The menus and the popover are the frames' own.

A session row
under 460: no branch

The status, the harness's mark, the title (13 medium) and its last line (12 secondary), the branch (mono 11.5, 170 wide) and the time (mono, 44 wide). The last line is the reason Loom holds, such as Allow, Asks, Plan ready or Failed; otherwise it is the first line of the transcript's end, read once per visit and only for a row that is drawn. A stale session dims its title.

05

What to react to

The content is the project page as built (DESIGN §10); this preview draws it in Ink and adds the harness. A yes, a no or "more like X" on each is enough.

  1. The head on the header line. The project's name in title type where a session's title would be, with no bar of its own. Right, or a smaller head in header type?
  2. The list on the canvas. Flat rows between hairlines, with cards only for the summaries. Or should the list be a card, as on Home?
  3. Presets. The mode's icon in its tone and the model with its harness's mark, the message in the tooltip. Enough, or should the mode's name show too?
  4. ⋯ on the page. The sidebar's project menu again, with the colour as swatches. Worth having here?
  5. The model picks the harness. A GPT model starts a Codex session, and only the chip's mark says so before you start. Clear enough?
  6. An empty project. A small hammerhead in place over the line. Fine, or keep empty pages without art?
  7. Open in editor beside CLAUDE.md is new. Keep it?
