# Loom visual contract and design rules

**Status:** The design and icons are accepted as fixed ([product contract](../LOOM-PRODUCT-CONTRACT.md) §3). This file is the canonical visual contract: references, the elements to keep, sizes and colors, and the status language. It states the *current* rule; where a rule comes from a user decision, the date follows in parentheses. For where each surface lives in code and how to verify it, see [UI-MAP.md](UI-MAP.md). The old Herdr Desktop behavior list moved to [LEGACY-INVENTORY.md](LEGACY-INVENTORY.md) (reference only). Brand identity: direction A · Night Fleece (6 Oct 2026, [D-22](../DECISIONS.md)); its rules and tokens are folded into [§6](#6-identity-a--night-fleece) and §3 (stage I, 7 Oct 2026). The [proposal](IDENTITY-PROPOSAL.md) is history. The legacy drawing code, terminal engine and architecture need not be reused as-is.

## 2. Elements to keep

1. Native red/yellow/green window buttons; top-left sidebar toggle, folder (group by project) and clock (recent activity) view selection, and a three-dot menu. The top bar (navbar) layout is pending a separate discussion with the user (5 Oct 2026); nothing here changes it.
2. A dark sidebar and an opaque dark terminal panel; thin border, soft corners, dense layout. The sidebar glass reads as glass: the dark tone at 0.6 lets the desktop show through softly (12 Oct 2026, the user's choice after a Liquid Glass trial, [D-44](../DECISIONS.md); before: tint 0.86 so no wallpaper color leaked, 5 Oct). The app is dark only.
3. Sidebar search field (always visible); day headings (Today, Yesterday, weekday, date) in the activity view.
4. Two-row session card. Top: small colored status indicator, title, relative time. Bottom: branch on the left; project name (activity view only) and the colored provider icon on the right. Selected card: light fill and thin border. The status label text is not drawn on the card.
5. Footer bar (D-32, 7 Oct 2026), 38 pt inside the sidebar: left a `+` menu (new Claude session, new Codex session while it exists in dev builds, new Claude session without a project while a session is selected, Add Project); in the middle a compact Claude usage chip (split layout, 12 Oct 2026: `1.2M today` left, and pinned to the right the plan window that runs out first when the Claude CLI reports plan limits, `5h` or `Wk`, a 34×4 meter of the share remaining and the remaining percent, e.g. `5h ▬▬ 62%`; no money; under 20 % remaining the percent and the meter fill take the attention orange; when narrow the meter drops first, then the tokens are cut with an ellipsis and the limit is never cut; states `Indexing…` and `No usage yet`; hidden when there is no usage index; the token split and both plan windows in the tooltip, the tokens and the bottleneck window in the accessibility label; click opens Settings at Usage); right a gear that opens Settings. Buttons keep 28×26. Settings is one dark 680×520 window with a top switcher General · Usage · About (Usage scrolls; About shows version, data folder and the Claude profile in use, read only). The sidebar is resizable; most of the width goes to the terminal.
6. Above the terminal: colored provider icon, session title, status indicator and label, a Stop button when stoppable, and a three-dot actions menu. The terminal text is the real CLI; it is never replaced by a custom chat UI.
7. The existing ram icon is kept: [ICNS](../assets/Loom.icns), [PNG](../assets/Loom.png), [SVG](../assets/Loom.svg), [raw mark](../assets/Loom-mark.svg), [menu-bar mark](../assets/Loom-menubar.svg). Files were copied without redrawing. Provider icons are in [assets/harness](../assets/harness); originals and sources in [assets/brand](../assets/brand/README.md).
8. Accessibility: honor Reduce Transparency (opaque sidebar). Reduce Motion: the small working indicator keeps animating (see section 4); any other motion must follow Reduce Motion. Focus ring only with keyboard navigation (see UI-MAP).

Visual acceptance: compare against the reference at the same window size and scale; check sidebar, typography, icons, glass and terminal geometry. Glass leakage, hover and focus states cannot be seen in evidence screenshots; they need the user's eyes (see UI-MAP).

## 4. Status language

(User decisions 5 Oct 2026, UI feedback package G, [UI plan](../plans/cp5/UI.md); 6 Oct 2026 for Reduce Motion and Codex.)

- Indicators follow the Unpeel style: small and colored. The same language is used in the sidebar, the detail header and every other status surface.
- **Working** = small dots chasing around a rectangle (8 dots on a rounded rectangle, 12 pt, 10 steps per second). It is a render-server layer animation (`CAKeyframeAnimation`), so it costs the app no wakeups. It is static when the window is hidden or inactive, and in the sidebar when the sidebar is collapsed ([contract §10](../LOOM-PRODUCT-CONTRACT.md#10-resource-and-performance-acceptance)). By user decision (6 Oct 2026) it keeps animating when macOS Reduce Motion is on, like the system's own small progress indicators; other motion follows Reduce Motion.
- **Needs approval / Waiting for you** = orange dot. **Finished** (nobody looked yet) = blue dot. **Failed / Stop not verified / Problem** = red dot. **Idle, Ready, Stale, ended** = no indicator (Stale also dims the title). **State unknown** = hollow gray ring; **Identity unclear** = hollow orange ring. Exact mapping and derivation order: [UI-MAP.md](UI-MAP.md#status-to-visual-mapping).
- **Subagents under a card** (D-39, 12 Oct 2026; design "V3 · Tree with a guide line", [preview](feedback2-preview.html) section 2). A session that runs subagents shows them below its card, on a hairline guide under the card's indicator column; a session without subagents draws the card alone, unchanged. One row per **running** subagent, at most 3: the working chase (the card's, at 0.75 scale, same layers and rate, so no new animation), the agent type (primary, 11 medium), the description (secondary, ellipsized), the elapsed time on the right (secondary: "now", "2m", from the sidebar's minute tick, no timer of its own). More than 3 running: a "+N more" row that opens the rest ("Show fewer" closes). **Finished** subagents of the current turn fold into one secondary "N finished" row (check glyph, chevron); a click opens their rows (type, description, duration in seconds, e.g. "18s", static) and closes them again; a session with only finished subagents shows only that row. A subagent that a subagent started (depth above 1) indents one step on the same guide. A click on any subagent row selects the parent session (a subagent has no terminal). Finished ones go with the user's next real prompt (a hand-back of a background subagent or a task notification is not one) and with the end of the run; running ones stay until they stop or the run ends. Accessibility: each row reads "Subagent Explore, Find login flow handlers, running"; the fold rows read "N subagents finished" with an expanded or collapsed value; the chase is hidden from accessibility like every indicator. Finished rows are told apart by the check glyph and the type in secondary instead of primary; every text is primary or secondary, tertiary stays on the decorative check glyph.
- **A session that opens a session** (D-39, D-40, 12 Oct 2026; [preview](feedback2-preview.html) section 3, "S2 · Origin line"). An agent's request to open a session never starts anything by itself: a box above the requesting session's terminal asks "Open a new session?" with the project, title, ticket and the first lines of the message (the rest one click away, in a bounded scroll area), and two buttons, **Deny** and **Open Session**. Neither is the default action and Return never answers it; Return stays with the terminal. It is an orange callout like a provider request, and while it waits (or after a failed start, until dismissed) the requester's card, tab and project dot read **Needs approval**. A ticket that already has a session raises no attention: a neutral box "<ticket> already has a session: <title>" offers Show Session and Dismiss. Nothing changes the selection except Show Session; approving leaves the user where they are and the new session appears at the top of its project with its working indicator. The new session's card shows where it came from: an arrow glyph and "from <requester>" in the meta row **in place of the branch** when both sessions are on the same branch, otherwise the branch stays and the origin is in the tooltip ("Opened by <requester>"); a requester that no longer exists reads "another session". The detail facts add "Opened by". Text is primary or secondary only; the arrow is a monochrome SF Symbol.
- Project rows show no session count. A colored dot (red, then orange, then blue by priority) appears when a session in the project fails, needs attention or finished unviewed.
- In the project view a session card does not repeat the project name; the activity view shows it.
- A project row's right-click menu starts a new Claude session, and a new Codex session while Codex exists in dev builds. Codex is not part of the first production release (user decision 6 Oct 2026); its start path is exposed but no new Codex behavior is written (5 Oct 2026).
- The navbar (top bar) layout is pending a separate discussion; none of the above changes it.

## 6. Identity (A · Night Fleece)

(Chosen 6 Oct 2026, [D-22](../DECISIONS.md); folded in stage I, 7 Oct 2026. Sub-decisions in §5.)

| Area | Rule |
| --- | --- |
| Personality | A quiet night workbench for one power user running many agents. Competent and calm. Never cheerful at the user's expense. |
| Voice and copy | Sentence case for messages, labels and alerts; no exclamation marks, no emoji, no "Oops". Say what happened, what Loom did or did not do, and what the user can do. Exact provider names ("Claude", "Codex"). No metaphor, including empty states. Vocabulary: text the user reads says "session"; "conversation" appears only in code, protocol names and quoted CLI output (`scripts/check-user-wording.sh` guards LoomCatalogUI and loom-app). |
| Colour | Dark only. Two surfaces (sidebar glass, panel = terminal background). Three text tiers. One accent (`#8791CF`). Three status hues. One project colour class (below). White-alpha fills for controls (hover 9 %, pressed 14 %, control 6 %, selected 7 % with a 1 pt white 10 % stroke). No provider colour tokens: a provider's colour lives only in its official mark. |
| Project colour (D-48, D-50; 12 Oct 2026; [preview](project-colors-preview.html), "C · Edge" with "T5 · Tinted tabs") | A fixed palette of six soft tones, assigned to projects in this order: Rose `#E68EBA`, Orchid `#D194E6`, Aqua `#80D5DB`, Mint `#83D8B0`, Sage `#92C186`, Lemon `#CCE07B` (Increase Contrast stripe colours `#F5B2D4`, `#E6B7F5`, `#A0E9EE`, `#A2ECC9`, `#AADB9E`, `#E0F29C`). A project's tone is the least-used one among the projects, ties in palette order; the user can change it (project menu → Color, six tones and None). The class is used only for the **sidebar stripe** (3 pt, in the 8 pt list gutter 4 pt left of each project header and each of its cards, so they read as one rail), the **tab tint** (a wash of the tone on every tab: 10 %, 15 % on hover, and on the open tab 15 % over the selection fill with a 1 pt stroke of the tone at 36 %; a washed tab's secondary text and close glyph use `Text.secondaryOnTint` `#9297A8`; indicator and overflow chevron unchanged) and the **header stripe** (3×12 pt before the project name in secondary 11 pt medium, 6 pt gap, after the status label; a project set to None shows the name without a stripe). Never a dot, never in the indicator slot, never a text colour, never inside the terminal, no pill, no wash on a card, no underline. A session without a project, a project set to None and an unknown stored tone stay neutral. Settings → General → Project colors (default on) turns every part off, and off is exactly the look before the feature; stored tones are kept. Each tone is ≥ 3:1 as a stripe on the sidebar's worst case and ≥ 30° of hue from attention, unviewed, failure and the accent (`LoomThemeTests`-style checks in `ProjectColorUITests`). Increase Contrast: stripes 4 pt in the lighter colour, the open tab's stroke in that colour at 75 %; the tints stay. Reduce Transparency needs nothing (every tint sits on an opaque surface). Colour is never the only carrier: the project name is written next to the stripe in the sidebar and the header, and tabs carry it in the tooltip ("Project: <name>") and the accessibility label (", project <name>"). All values are `LoomTheme.ProjectColor`. The text tiers hold on the washes: primary at least 7:1 on every tab (the preview's 18 % on the open tab gave 6.5 for Lemon, so it is 15 %), secondary on tint at least 4.5:1 on a resting tab and 3:1 for the glyph on the open tab (plain secondary would be 3.7 to 4.0) |
| Contrast | `text.primary` ≥ 7:1 and `text.secondary` ≥ 4.5:1 on sidebar tint, selected card and panel; accent and status hues ≥ 4.5:1 on each; `text.tertiary` ≥ 2.5:1 and only for placeholders, disabled items and decorative marks (`LoomThemeTests`). |
| Typography | SF Pro for UI, SF Mono 14 for the terminal (11–20). Fixed sizes; weight carries hierarchy before size. Card title 13 medium (selected semibold); card meta 11 regular; day headings 11 semibold secondary; header title 13 semibold; status label 11 medium; empty-state title 20 semibold. |
| Iconography | SF Symbols, monochrome, regular, 13 pt in chrome; never palette-coloured. Provider marks are official art at 14/16/34 pt and never tinted. The Loom mark is the app icon, menu bar template and About mark. |
| Shape and spacing | 4 pt grid. Concentric radii: panel 10 ≥ card 10 ≥ search 8 ≥ control 6. Geometry from §3: 52 pt header, 26 pt centre line, 8 pt panel inset, 6 pt terminal inset. |
| Materials | Only the sidebar is glass (`.sidebar` behind-window material under the `#0B0E16` tint at 0.6); panel and terminal are opaque; Reduce Transparency swaps in the opaque tint. No wallpaper colour reads through. |
| Header | Transparent: panel colour, no divider, no band (O-03 default; the navbar layout is still an open item). |
| Motion | Persistent motion only as gated render-server layer animations (§4). One-shot transitions ≤ 200 ms ease-out (selection 120 ms, banners 200 ms), opacity only above the terminal (a height change would resize the PTY every frame). No glow, pulse or breathing; nothing animates inside the terminal panel. Appearances fade in (opacity only); dismissals are instant. Under Reduce Motion transitions become instant; the working chase keeps running (6 Oct 2026). |
| Status language | §4, through `IndicatorView` on every surface. No status words on cards (accessibility label only). Unviewed stays blue `#5C8CFF`. |
| Terminal framing | Panel colour = terminal background, so the CLI sits edge to edge; the header lives outside the terminal. ANSI 16 = VS Code Dark+, xterm 256 cube, steady block cursor. |
| Accessibility | Increase Contrast raises the hairline to white 30 %, secondary text to `#A9AEBF` (≥ 7:1) and the focus ring to 2.5 pt (`LoomTheme.ContrastStyle`, partly wired: chrome and row buttons, panel and selection strokes, headings, banners, messages). Clickable controls answer over at least 24×24 pt even when drawn smaller. Headings carry the header trait; project headers are buttons with an expanded/collapsed value. Return never approves a request while a live terminal is shown below it (Approve stays one click away). |
| Sound | None. |

Every new surface is checked against this section before review: theme tokens only, status through `IndicatorView`, copy in this voice, persistent animation only as a gated layer animation, Reduce Transparency handled, text at the contrast tier for its role.
