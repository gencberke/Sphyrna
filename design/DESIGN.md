# Loom visual contract and design rules

**Status:** The design and icons are accepted as fixed ([product contract](../LOOM-PRODUCT-CONTRACT.md) §3). This file is the canonical visual contract: references, the elements to keep, sizes and colors, and the status language. It states the *current* rule; where a rule comes from a user decision, the date follows in parentheses. For where each surface lives in code and how to verify it, see [UI-MAP.md](UI-MAP.md). The old Herdr Desktop behavior list moved to [LEGACY-INVENTORY.md](LEGACY-INVENTORY.md) (reference only). Brand identity: direction A · Night Fleece (6 Oct 2026, [D-22](../DECISIONS.md)); its rules and tokens are folded into [§6](#6-identity-a--night-fleece) and §3 (stage I, 7 Oct 2026). The [proposal](IDENTITY-PROPOSAL.md) is history. The legacy drawing code, terminal engine and architecture need not be reused as-is.

## 2. Elements to keep

1. Native red/yellow/green window buttons; top-left sidebar toggle, folder (group by project) and clock (recent activity) view selection, and a three-dot menu. The top bar (navbar) layout is pending a separate discussion with the user (5 Oct 2026); nothing here changes it.
2. A dark sidebar and an opaque dark terminal panel; thin border, soft corners, dense layout. The sidebar glass reads as glass: the dark tone at 0.6 lets the desktop show through softly (12 Oct 2026, the user's choice after a Liquid Glass trial, [D-44](../DECISIONS.md); before: tint 0.86 so no wallpaper color leaked, 5 Oct). The app is dark only.
3. Sidebar search field (always visible); under it a Home row (30 pt, V04) with the count of sessions that need you, the Dock badge's count (attention wash, light attention text, drawn only above 0); day headings (Today, Yesterday, weekday, date) in the activity view.
4. Two-row session card. Top: small colored status indicator, title, relative time. Bottom: for a card in the Active section the reason line (what the session waits for or did last: "Allow: <command>", "Asks: <header>", "Plan ready for review", the first line of the last message, "Failed: <cause>"), else the branch; on the right the project name (activity view only) and the colored provider icon, which keep their room when the line is long. The branch also stays in the detail header. The project view lists sessions as one 28 pt line: indicator, title, time (a pin glyph when pinned, a provider mark only for a provider other than Claude). Selected card or line: light fill and thin border. The status label text is not drawn on the card.
5. Footer bar (D-32, 7 Oct 2026), 38 pt inside the sidebar: left a `+` menu (new Claude session, new Codex session while it exists in dev builds, new Claude session without a project while a session is selected, Add Project); in the middle a compact Claude usage chip (split layout, 12 Oct 2026: `1.2M today` left, and pinned to the right the plan window that runs out first when the Claude CLI reports plan limits, `5h` or `Wk`, a 34×4 meter of the share remaining and the remaining percent, e.g. `5h ▬▬ 62%`; no money; under 20 % remaining the percent and the meter fill take the attention orange; when narrow the meter drops first, then the tokens are cut with an ellipsis and the limit is never cut; states `Indexing…` and `No usage yet`; hidden when there is no usage index; the token split and both plan windows in the tooltip, the tokens and the bottleneck window in the accessibility label; click opens Settings at Usage); right a gear that opens Settings. Buttons keep 28×26. Settings is one dark 680×520 window with a top switcher General · Usage · About (Usage scrolls as four cards, plan limits first, FB3-1; About shows version, data folder and the Claude profile in use, read only). The sidebar is resizable; most of the width goes to the terminal.
6. Above the terminal: colored provider icon, session title, then at fixed places on the right the state pill (indicator and label), the project chip with the Git branch, the inspector toggle (V09, its own 24 pt group) and one control group with Stop (when stoppable) and a three-dot actions menu. The terminal text is the real CLI; it is never replaced by a custom chat UI.
7. The existing ram icon is kept: [ICNS](../assets/Loom.icns), [PNG](../assets/Loom.png), [SVG](../assets/Loom.svg), [raw mark](../assets/Loom-mark.svg), [menu-bar mark](../assets/Loom-menubar.svg). Files were copied without redrawing. Provider icons are in [assets/harness](../assets/harness); originals and sources in [assets/brand](../assets/brand/README.md).
8. Accessibility: honor Reduce Transparency (opaque sidebar). Reduce Motion: the small working indicator keeps animating (see section 4); any other motion must follow Reduce Motion. Focus ring only with keyboard navigation (see UI-MAP).

**Text on a popover.** Four pairs fall short there (concept §6.1), each with a rule, held by `LoomThemeTests` and available as `LoomTheme.OnPopover`: tertiary is 2.36:1 (floor 2.5:1), so placeholders use secondary; base accent as text is 4.39:1, so popovers use the high accent (6.3:1); unviewed and failure as text are about 4.2:1, so they use their light variants; primary on the low accent is 4.33:1, so the low accent never carries text. On every other level primary reads at least 10.9:1 and secondary at least 4.9:1.

**Sidebar: Glass | Solid (D-57).** Settings → General → Sidebar (`UIPreferences.sidebarStyle`, default Glass, applies live) chooses between the behind-window material under the 0.6 tone and the same tone opaque. Reduce Transparency forces Solid whatever the setting says; the setting is not changed by it. Only the sidebar is ever glass; panel and terminal stay opaque.

Material, background and opacity change the final look, so these values alone do not guarantee a screenshot color. AppKit panels (alerts, open panels) follow `NSApp.appearance = darkAqua`, set at launch.

Visual acceptance: compare against the reference at the same window size and scale; check sidebar, typography, icons, glass and terminal geometry. Glass leakage, hover and focus states cannot be seen in evidence screenshots; they need the user's eyes (see UI-MAP).

## 4. Status language

(User decisions 5 Oct 2026, UI feedback package G, [UI plan](../plans/cp5/UI.md); 6 Oct 2026 for Reduce Motion and Codex.)

- Indicators follow the Unpeel style: small and colored. The same language is used in the sidebar, the detail header and every other status surface.
- **Working** = small dots chasing around a rectangle (8 dots on a rounded rectangle, 12 pt, 10 steps per second). It is a render-server layer animation (`CAKeyframeAnimation`), so it costs the app no wakeups. It is static when the window is hidden or inactive, and in the sidebar when the sidebar is collapsed ([contract §10](../LOOM-PRODUCT-CONTRACT.md#10-resource-and-performance-acceptance)). By user decision (6 Oct 2026) it keeps animating when macOS Reduce Motion is on, like the system's own small progress indicators; other motion follows Reduce Motion.
- **Needs approval / Waiting for you** = orange dot. **Finished** (nobody looked yet) = blue dot. **Failed / Stop not verified / Problem** = red dot. **Idle, Ready, Stale, ended** = no indicator (Stale also dims the title). **State unknown** = hollow gray ring; **Identity unclear** = hollow orange ring. Exact mapping and derivation order: [UI-MAP.md](UI-MAP.md#status-to-visual-mapping).
- **Subagents under a card** (D-39, 12 Oct 2026; design "V3 · Tree with a guide line", [preview](feedback2-preview.html) section 2). A session that runs subagents shows them below its card, on a hairline guide under the card's indicator column; a session without subagents draws the card alone, unchanged. One row per **running** subagent, at most 3: the working chase (the card's, at 0.75 scale, same layers and rate, so no new animation), the agent type (primary, 11 medium), the description (secondary, ellipsized), the elapsed time on the right (secondary: "now", "2m", from the sidebar's minute tick, no timer of its own). More than 3 running: a "+N more" row that opens the rest ("Show fewer" closes). **Finished** subagents of the current turn fold into one secondary "N finished" row (check glyph, chevron); a click opens their rows (type, description, duration in seconds, e.g. "18s", static) and closes them again; a session with only finished subagents shows only that row. A subagent that a subagent started (depth above 1) indents one step on the same guide. A click on any subagent row selects the parent session (a subagent has no terminal of its own) and opens its inspector on the Agents tab, where the subagent's transcript is read (V09); the terminal stays on screen. Finished ones go with the user's next real prompt (a hand-back of a background subagent or a task notification is not one) and with the end of the run; running ones stay until they stop or the run ends. Accessibility: each row reads "Subagent Explore, Find login flow handlers, running"; the fold rows read "N subagents finished" with an expanded or collapsed value; the chase is hidden from accessibility like every indicator. Finished rows are told apart by the check glyph and the type in secondary instead of primary; every text is primary or secondary, tertiary stays on the decorative check glyph.
- **A session that opens a session** (D-39, D-40, 12 Oct 2026; [preview](feedback2-preview.html) section 3, "S2 · Origin line"). An agent's request to open a session never starts anything by itself: a box above the requesting session's terminal asks "Open a new session?" with the project, title, ticket and the first lines of the message (the rest one click away, in a bounded scroll area), and two buttons, **Deny** and **Open Session**. Neither is the default action and Return never answers it; Return stays with the terminal. It is an orange callout like a provider request, and while it waits (or after a failed start, until dismissed) the requester's card, tab and project dot read **Needs approval**. A ticket that already has a session raises no attention: a neutral box "<ticket> already has a session: <title>" offers Show Session and Dismiss. Nothing changes the selection except Show Session; approving leaves the user where they are and the new session appears at the top of its project with its working indicator. The new session's card shows where it came from: an arrow glyph and "from <requester>" in the meta row **in place of the branch** when both sessions are on the same branch, otherwise the branch stays and the origin is in the tooltip ("Opened by <requester>"); a requester that no longer exists reads "another session". The detail facts add "Opened by". Text is primary or secondary only; the arrow is a monochrome SF Symbol.
- Project rows show no session count. A colored dot (red, then orange, then blue by priority) appears when a session in the project fails, needs attention or finished unviewed.
- A click on a project's name opens its page (V04); the chevron button beside it collapses and expands the project's sessions. The row of an open page is filled like a selected card.
- A draft with text is a one-line italic row in secondary, the height of a session line (28 pt), under its project in the project view and under a "Drafts" heading in the activity view; Discard is the hover ×. It has no indicator.
- The project view lists sessions as one-line rows that do not repeat the project name; the activity view shows it on its two-row cards.
- A project row's right-click menu starts a new Claude session, and a new Codex session while Codex exists in dev builds. Codex is not part of the first production release (user decision 6 Oct 2026); its start path is exposed but no new Codex behavior is written (5 Oct 2026).
- The navbar (top bar) layout is pending a separate discussion; none of the above changes it.

## 6. Identity (A · Night Fleece)

(Chosen 6 Oct 2026, [D-22](../DECISIONS.md); folded in stage I, 7 Oct 2026. Sub-decisions in §5.)

| Area | Rule |
| --- | --- |
| Personality | A quiet night workbench for one power user running many agents. Competent and calm. Never cheerful at the user's expense. |
| Voice and copy | Sentence case for messages, labels and alerts; no exclamation marks, no emoji, no "Oops". Say what happened, what Loom did or did not do, and what the user can do. Exact provider names ("Claude", "Codex"). No metaphor, including empty states. Vocabulary: text the user reads says "session"; "conversation" appears only in code, protocol names and quoted CLI output (`scripts/check-user-wording.sh` guards LoomCatalogUI and loom-app). |
| Colour | Dark only. Two surfaces (sidebar glass, panel = terminal background); Night Fleece 2 adds the inspector, canvas, card, raised and popover levels (§3) for the slices that draw them. Three text tiers. One accent (`#8791CF`, with a high and a low step). Three status hues, with light text variants, and a content-only success hue. One project colour class (below). White-alpha fills for controls (hover 9 %, pressed 14 %, control 6 %, selected 7 % with a 1 pt white 8 % stroke). No provider colour tokens: a provider's colour lives only in its official mark. Secondary text on a Settings card (the 6 % control tone over the panel) reads 5.4:1 in secondary `#9A9EB0` (Increase Contrast `#BCC0D0`); `Text.secondaryOnCardStyle` and `secondaryOnTint` keep their names and take the secondary value (before Night Fleece 2 they were a lifted `#9297A8`, because `#828799` read 4.0:1 there). |
| Project colour (D-48, D-50; 12 Oct 2026; [preview](project-colors-preview.html), "C · Edge" with "T5 · Tinted tabs") | A fixed palette of six soft tones, assigned to projects in this order: Rose `#E68EBA`, Orchid `#D194E6`, Aqua `#80D5DB`, Mint `#83D8B0`, Sage `#92C186`, Lemon `#CCE07B` (Increase Contrast stripe colours `#F5B2D4`, `#E6B7F5`, `#A0E9EE`, `#A2ECC9`, `#AADB9E`, `#E0F29C`). Never a dot, never in the indicator slot, never a text colour, never inside the terminal, no pill, no wash on a card, no underline. A session without a project, a project set to None and an unknown stored tone stay neutral. Settings → General → Project colors (default on) turns every part off, and off is exactly the look before the feature, except that the header chip (D-53) stays as a neutral chip with the project name and the branch; stored tones are kept. Each tone is ≥ 3:1 as a stripe on the sidebar's worst case and ≥ 30° of hue from attention, unviewed, failure and the accent (`LoomThemeTests`-style checks in `ProjectColorUITests`). Increase Contrast: stripes 4 pt in the lighter colour, the open tab's stroke in that colour at 75 %; the tints stay. Reduce Transparency needs nothing (every tint sits on an opaque surface). Colour is never the only carrier: the project name is written next to the stripe in the sidebar and the header, and tabs carry it in the tooltip ("Project: <name>") and the accessibility label (", project <name>"). All values are `LoomTheme.ProjectColor`. The text tiers hold on the washes: primary at least 7:1 on every tab (the preview's 18 % on the open tab gave 6.5 for Lemon, so it is 15 %), secondary on tint at least 4.5:1 on a resting tab and 3:1 for the glyph on the open tab (plain secondary would be 3.7 to 4.0); the header chip on its 10 % wash has primary at least 9.9:1 and `secondaryOnTint` at least 4.6:1 (`SessionHeaderTests`) |
| Contrast | `text.primary` ≥ 7:1 and `text.secondary` ≥ 4.5:1 on sidebar tint, selected card and panel, and on every Night Fleece 2 level (primary ≥ 10.9:1, secondary ≥ 4.9:1); accent and status hues ≥ 4.5:1 on each (a popover takes the rules in §3); `text.tertiary` ≥ 2.5:1 and only for placeholders, disabled items and decorative marks (`LoomThemeTests`). |

| Status language | §4, through `IndicatorView` on every surface. No status words on cards (accessibility label only). Unviewed stays blue `#5C8CFF`. |
| Terminal framing | Panel colour = terminal background, so the CLI sits edge to edge; the header lives outside the terminal. ANSI 16 = VS Code Dark+, xterm 256 cube, steady block cursor. |

| Sound | None. |

Every new surface is checked against this section before review: theme tokens only, status through `IndicatorView`, copy in this voice, persistent animation only as a gated layer animation, Reduce Transparency handled, text at the contrast tier for its role.

## 7. Chat view (V13)

The stream of a Claude session read as chat (`Sources/LoomCatalogUI/Chat/`; the spec is `plans/v2/CHAT-SPEC.md`). It is drawn by `ChatTranscriptView`, read only for a stopped session and a live tail for a running terminal one. Values live in `LoomTheme+Chat.swift` (`LoomTheme.Chat`); the rules below are the ones a change must keep. Rules marked T3 follow T3 Code (MIT, Copyright 2026 T3 Tools Inc.); no T3 code is copied.

| Item | Rule |
| --- | --- |
| Column | 700 pt reading column centred in the panel, 28 pt side padding; your message is a right-aligned bubble (user fill, hairline), Claude's prose has no bubble |
| Rows | One row per message, work step, group, fold, marker or card; a row's id is stable (entry id, or `fold:`, `group:`, `live:`, `changes:` plus the turn or first tool), so only changed rows redraw. Work rows are 26 pt high, 16 pt indent per level |
| Turn fold [T3] | A settled turn's work between your message and the final answer folds into one row, "Worked for 4m 12s · changed 5 files and ran 3 commands". It never folds while the turn is live, failed or interrupted, or when nothing is left to fold; plan cards and dividers stay visible. A new turn closes the previous turn's opened fold. Your own messages inside a folded turn stay visible too |
| Group summary [T3] | Two or more tools in a row are one line that names the two best kinds by (rank, first appearance) and counts the rest ("Changed 3 files, ran 2 commands and 4 other actions"); the latest tool decides its state. TodoWrite is never a row. Work that never finished in a settled turn reads as stopped |
| Live row | The one row at the end of a running turn: the chase, what Claude does now ("Editing a.py"), the clock (1 s, only while visible), and "No activity for Ns" after 40 s. Trailing tools of a live turn collapse into it |
| Views | Normal (thought as one line), Thinking (adds thinking blocks), Verbose (opens every fold and group); ⌃O cycles them, the chip at the top right shows the view, compact (the glyph and ⌃O) when the stream is under 700 wide. The view, open folds and the reader's place are kept per session for the last 64 sessions. ⌃O works only while the stream has focus, so a terminal beside it keeps the key |
| Content | Markdown without a dependency: a small block parser (paragraph, heading, list, quote, code, table, rule; nesting capped at 8) and `AttributedString(markdown:)` for inline text. Only http, https and mailto links open. Code blocks have Copy ("Copied" for 1.2 s) and a wrap toggle; syntax colours (VS Code Dark+) only for finished blocks of up to 20,000 characters; tool output over 16 lines scrolls; "Show all" reads the whole result from the transcript. "Show all" shows at most 1 MiB or 10,000 lines of a result, with a note where it was cut |
| Changed-files card | Under the final answer of a turn that edited files: "N files changed +A −R" from the edit records (no git), a tree with single-child folders merged and paths relative to the working folder. A zero count is left out, so a record without counts shows none. Counts use the success colour, never a status colour. It also shows for an interrupted turn that edited files |
| Scroll latch [T3] | Following keeps the end in view; Free leaves the view where the reader put it. The distance is measured from the true content bottom with the bottom inset taken off; within 40 pt of it the view follows again. Wheel up, scroller drag and ↑, Page Up, Home leave Following; programmatic scrolls never change the state. "Jump to latest" appears 150 ms after leaving the end and hides at once on return. Older turns load when the top is within one viewport and the top row holds its place. A message you just sent is held 24 pt from the top until the turn's first activity |
| Motion | New rows fade in over 150 ms; none under Reduce Motion. The clock and the chase run only while the window can be seen and a live row exists |
| Cost | Rows are virtualized (a view only for the rows near the viewport); heights are cached by row id and width; a delta applies at most about every 50 ms and redraws only the rows that changed; a hidden window or a closed view has no watcher and no timer |
| Copy | "session" in every user-visible string, never "conversation"; times and dates use the system locale and clock ("yesterday at 14:05"; `LoomDateFormat`, one place for every surface); percents are written "41%"; counts say what they count ("running", "sessions with usage") |
