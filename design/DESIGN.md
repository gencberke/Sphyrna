# Loom visual contract and design rules

**Status:** The design and icons are accepted as fixed ([product contract](../LOOM-PRODUCT-CONTRACT.md) §3). This file is the canonical visual contract: references, the elements to keep, sizes and colors, and the status language. It states the *current* rule; where a rule comes from a user decision, the date follows in parentheses. For where each surface lives in code and how to verify it, see [UI-MAP.md](UI-MAP.md). The old Herdr Desktop behavior list moved to [LEGACY-INVENTORY.md](LEGACY-INVENTORY.md) (reference only). Brand identity: direction A · Night Fleece (6 Oct 2026, [D-22](../DECISIONS.md)); its rules and tokens are folded into [§6](#6-identity-a--night-fleece) and §3 (stage I, 7 Oct 2026). The [proposal](IDENTITY-PROPOSAL.md) is history. The legacy drawing code, terminal engine and architecture need not be reused as-is.

## 2. Elements to keep

1. Native red/yellow/green window buttons; top-left sidebar toggle, folder (group by project) and clock (recent activity) view selection, and a three-dot menu. The top bar (navbar) stays transparent (O-03, closed by D-69 on 19 Oct 2026).
2. A sidebar and an opaque main panel in the chosen appearance (Dark by default, Light, or Match system; Settings → Theme, §6); the terminal face is dark in every appearance; thin border, soft corners, dense layout. The sidebar glass reads as glass: the sidebar tone at 0.6 lets the desktop show through softly (12 Oct 2026, the user's choice after a Liquid Glass trial, [D-44](../DECISIONS.md); before: tint 0.86 so no wallpaper color leaked, 5 Oct).
3. Sidebar search field (always visible); under it a Home row (30 pt, V04) with the count of sessions that need you, the Dock badge's count (attention wash, light attention text, drawn only above 0); day headings (Today, Yesterday, weekday, date) in the activity view.
4. Session card. Top: small colored status indicator, title, relative time. Bottom, always: the branch (a session opened by another one on the same branch shows its origin there instead), a pin glyph when pinned, and on the right the project name (activity view only) and the colored provider icon. A card in the Active section adds the reason line between the two (what the session waits for or did last: "Allow: <command>", "Asks: <header>", "Plan ready for review", the first line of the last message, "Failed: <cause>"), so it is one caption line taller while the session needs the user (D-69). The branch also stays in the detail header. The project view lists sessions as one 28 pt line: indicator, title, time (a pin glyph when pinned, a provider mark only for a provider other than Claude). Selected card or line: the pill's selected fill and a hairline, and a lighter fill under the pointer (§3). The status label text is not drawn on the card.
5. Footer bar (D-32, 7 Oct 2026), 38 pt inside the sidebar: left a `+` menu (new Claude session, new Codex session (disabled, with "Codex comes in a later version", in a build that cannot start it), new Claude session without a project while a session is selected, Add Project); in the middle a compact Claude usage chip (split layout, 12 Oct 2026: `1.2M today` left, and pinned to the right the plan window that runs out first when the Claude CLI reports plan limits, `5h` or `Wk`, a 34×4 meter of the share remaining and the remaining percent, e.g. `5h ▬▬ 62%`; no money; under 20 % remaining the percent and the meter fill take the attention orange; when narrow the meter drops first, then the tokens are cut with an ellipsis and the limit is never cut; states `Indexing…` and `No usage yet`; hidden when there is no usage index; the token split and both plan windows in the tooltip, the tokens and the bottleneck window in the accessibility label; click opens Settings at Usage); right a gear that opens Settings. Buttons keep 28×26. Settings is one 680×520 window that follows the appearance, with a top switcher General · Theme · Usage · Sessions · About (Usage scrolls as four cards, plan limits first, FB3-1; About shows version, data folder and the Claude profile in use, read only). The sidebar is resizable; most of the width goes to the terminal.
6. Above the terminal: colored provider icon, session title, then at fixed places on the right the state pill (indicator and label), the project chip with the Git branch, the inspector toggle (V09, its own 24 pt group) and one control group with Stop (when stoppable) and a three-dot actions menu. Both faces are the real CLI: the terminal face shows its terminal, and the Chat face draws its structured mode. One app-wide switch in Settings chooses the face (contract §3, D-69).
7. The existing ram icon is kept: [ICNS](../assets/Loom.icns), [PNG](../assets/Loom.png), [SVG](../assets/Loom.svg), [raw mark](../assets/Loom-mark.svg), [menu-bar mark](../assets/Loom-menubar.svg). Files were copied without redrawing. Provider icons are in [assets/harness](../assets/harness); originals and sources in [assets/brand](../assets/brand/README.md).
8. Accessibility: honor Reduce Transparency (opaque sidebar). Reduce Motion: the small working indicator keeps animating (see section 4); any other motion must follow Reduce Motion. Focus ring only with keyboard navigation (see UI-MAP).

**Panel levels per tone.** Settings → Theme → Main pane picks the tone (`PaneTone`: Night fleece, Workshop, Instrument). The tone changes the panel family (panel, canvas, inspector, card, raised, popover) in both appearances and, in Dark, the terminal's background. Each level sits at a fixed step from the panel (`Surface.levels(_:tone:)`), so the three tones keep one rhythm. Dark steps (red, green, blue): inspector -9 -9 -10, canvas -4 -4 -4, card +5 +5 +6, raised +13 +13 +14, popover +19 +19 +22. Light steps: inspector -9 -9 -9, canvas -4 -4 -4, card +5 +5 +6 (channels capped at `FC`), raised -6 -6 -6, popover +8 +8 +9 (capped at `FD`). In Light the card and popover are lighter than the panel and never pure white; the inspector and canvas are a step darker, and the raised level (a card's hover fill) is darker than the card.

A meter fills the share still left, from the leading edge, in neutral `Text.secondary` on the chip-meter track (white 10 %, ink 10 % in Light). It turns attention orange when under 20 % is left or when the window runs out before its reset (over pace). In `PlanPaceLine` a 2 pt primary tick marks where an even pace would leave the remainder now (the unelapsed share of the window), so a fill beyond the tick is a limit that lasts. **Sidebar: Glass | Solid (D-57).** Settings → Theme → Sidebar (`UIPreferences.sidebarStyle`, default Glass, applies live; it was in General until V26) chooses between the behind-window material under the 0.6 tone and the same tone opaque. Reduce Transparency forces Solid whatever the setting says; the setting is not changed by it. Only the sidebar is ever glass; panel and terminal stay opaque.

Material, background and opacity change the final look, so these values alone do not guarantee a screenshot color. AppKit panels (alerts, open panels) follow `NSApp.appearance`, which Settings → Theme → Appearance sets (Dark `darkAqua`, Light `aqua`, Match system none, so macOS decides); launch sets `darkAqua` only until the stored appearance is read, so the question about a damaged catalog, which comes before the model exists, is dark.

Visual acceptance: compare against the reference at the same window size and scale; check sidebar, typography, icons, glass and terminal geometry. Glass leakage and focus states cannot be seen in evidence screenshots; they need the user's eyes (see UI-MAP). A pill's hover can be held on with the `hover:` command (DEVELOPMENT §5) and shown in a screenshot; a real pointer is still the user's check. Not yet seen in Light: the Glass sidebar over a dark wallpaper (the Light worst case above assumes the material lifts to 0.70 gray), Glass leakage, focus states and the pill under a real pointer.

## 4. Status language

(User decisions 5 Oct 2026, UI feedback package G, [UI plan](../plans/cp5/UI.md); 6 Oct 2026 for Reduce Motion and Codex.)

- Indicators follow the Unpeel style: small and colored. The same language is used in the sidebar, the detail header and every other status surface.
- **Working** = small dots chasing around a rectangle (8 dots on a rounded rectangle, 12 pt, 10 steps per second). It is a render-server layer animation (`CAKeyframeAnimation`), so it costs the app no wakeups. It is static when the window is hidden or inactive, and in the sidebar when the sidebar is collapsed ([contract §10](../LOOM-PRODUCT-CONTRACT.md#10-resource-and-performance-acceptance)). By user decision (6 Oct 2026) it keeps animating when macOS Reduce Motion is on, like the system's own small progress indicators; other motion follows Reduce Motion.
- **Needs approval / Waiting for you** = orange dot. **Finished** (nobody looked yet) = blue dot. **Failed / Stop not verified / Problem** = red dot. **Idle, Ready, Stale, ended** = no indicator (Stale also dims the title). **State unknown** = hollow gray ring; **Identity unclear** = hollow orange ring. Exact mapping and derivation order: [UI-MAP.md](UI-MAP.md#status-to-visual-mapping).
- **Subagents under a card** (D-39, 12 Oct 2026; design "V3 · Tree with a guide line", [preview](feedback2-preview.html) section 2). A session that runs subagents shows them below its card, on a hairline guide under the card's indicator column; a session without subagents draws the card alone, unchanged. One row per **running** subagent, at most 3: the working chase (the card's, at 0.75 scale, same layers and rate, so no new animation), the agent type (primary, 11 medium), the description (secondary, ellipsized), the elapsed time on the right (secondary: "now", "2m", from the sidebar's minute tick, no timer of its own). More than 3 running: a "+N more" row that opens the rest ("Show fewer" closes). **Finished** subagents of the current turn fold into one secondary "N finished" row (check glyph, chevron); a click opens their rows (type, description, duration in seconds, e.g. "18s", static) and closes them again; a session with only finished subagents shows only that row. A subagent that a subagent started (depth above 1) indents one step on the same guide. A click on any subagent row selects the parent session (a subagent has no terminal of its own) and opens its inspector on the Agents tab, where the subagent's transcript is read (V09); the terminal stays on screen. Finished ones go with the user's next real prompt (a hand-back of a background subagent or a task notification is not one) and with the end of the run; running ones stay until they stop or the run ends. Accessibility: each row reads "Subagent Explore, Find login flow handlers, running"; the fold rows read "N subagents finished" with an expanded or collapsed value; the chase is hidden from accessibility like every indicator. Finished rows are told apart by the check glyph and the type in secondary instead of primary; every text is primary or secondary, tertiary stays on the decorative check glyph.
