# Loom UI map

Inventory of every user-visible surface and state, with the source that draws it. Rules and values are in [DESIGN.md](DESIGN.md); this file says where things live. Verified by reading code (nothing here was seen on screen unless stated). Update it when you change a surface. Paths are relative to the repo root; `CUI` = `Sources/LoomCatalogUI`, `APP` = `Sources/loom-app`, `TERM` = `Sources/LoomTerminal`.

Shape of the product UI: one native macOS 27 window, dark only (`darkAqua` forced on the window and `.preferredColorScheme(.dark)` on the roots), a sidebar beside one large terminal panel that hosts the real CLI. No chat UI. Claude and Codex rows exist; Codex is not in the first production release (user decision 6 Oct 2026).

## Window chrome (`APP/AppDelegate.swift` `makeWindow`, `APP/MainSplitViewController.swift`)

- Style: titled, closable, miniaturizable, resizable, full-size content; transparent title bar, hidden title, `isOpaque = false`, clear background, automatic window tabbing off. 1220×780 initial, 780×500 minimum.
- Traffic lights are native and not repositioned. An empty `NSToolbar("loom-main")` with `.unified` style and no separator exists only so AppKit centers them 26 pt from the window top. There is no real toolbar: the "navbar" is the sidebar header row (52 pt) plus the detail header row (36 pt row in a 52 pt block).
- `NSSplitViewController`: sidebar item 220-520 (collapsible), detail minimum 480, thin divider. Width is restored on first layout and persisted 250 ms after a user divider drag only; the sidebar item's `isCollapsed` is the one truth for hidden or shown: `SplitViewItemCollapse` observes it with KVO and `SidebarCollapseSync` (`CUI/SidebarCollapseSync.swift`) mirrors it into `CatalogModel.sidebarCollapsed` (Show button, button gap, persistence) after the saved state was restored; Hide, Show and Cmd+F on a collapsed sidebar all go through `onToggleSidebar`, which sets the opposite of the real state and reconciles again when the animation ends. The dev snapshot carries `sidebarItemCollapsed` next to `sidebarCollapsed`.
- The command palette overlay (V06) is a subview of the split view, added in `viewDidLoad` (`makePaletteOverlayView`), over both panes; it draws and takes clicks only while the palette is open.
- Full screen: the headers stop reserving space for traffic lights (`model.setFullScreen`).
- Window activity (`updateWindowActivity`): active = visible, not occluded, key, app active. It drives `model.windowIsActive`, viewed state and indicator animation.
- Close (red button, Cmd+W) only closes the window; the app and jobs keep running; Dock reopen re-presents it. Errors use `NSAlert` sheets (`showError`); Add Project uses `NSOpenPanel`.
- Quit (D-45, `AppDelegate.applicationShouldTerminate`, rules in `QuitConfirmation`, `CUI/SessionNavigation.swift`): a user-initiated quit (Cmd+Q, the Dock menu) with at least one session Working or Needs approval (an agent waiting on an open-session request counts; Ready, Waiting for you and Finished do not) first asks, as a sheet on the main window (window shown first when closed): "Quit Loom and stop N working sessions?" / "Loom stops every session it started. You can resume each one later." with **Cancel** (first button, the default: Return; Escape cancels too) and **Quit**. No question for a quit the system starts (logout, restart, shutdown: the quit Apple event's `keyAEQuitReason`), when nothing is working, or in an evidence run. Then Quit performs a verified shutdown. A failed shutdown shows an `NSAlert` (`quitAlert`): "Loom could not verify that its processes stopped." with the remaining count and errors, and a second paragraph saying Quit Anyway ends Loom without confirming that every session process stopped and that processes it could not stop may keep running. Buttons **Try Again** (default), **Keep Loom Open**, **Quit Anyway** (destructive; the next `applicationShouldTerminate` returns `.terminateNow`, no verified shutdown). A system-initiated quit whose shutdown cannot be verified is not held up: the report is still written to `shutdown.json`, no alert, the app terminates.
- Dock badge (D-45): `NSApp.dockTile.badgeLabel` is the number of sessions that need the user (the set of the Window menu's jump items), nil at 0, updated by `CatalogModel.onAttentionCountChange` whenever live state, a record or an open-session wait changes (no timer), cleared in `applicationWillTerminate`.
- Menu bar item (H1-F, D-49, D-52; [preview](menu-bar-preview.html); `APP/MenuBarController.swift`, `CUI/MenuBarState.swift`, `CUI/MenuBarFace.swift`, `CUI/MenuBarMark.swift`, `CUI/MenuBarRowText.swift`): an `NSStatusItem` made and removed with Settings → General → Show in menu bar. Its face is the Loom mark (`assets/Loom-menubar.svg`, its path embedded in `MenuBarMark`, no packaged asset; 18 pt wide in a 20 pt canvas). Idle is the plain template image (macOS tints it). The lower right corner is the badge slot: the working chase (9.6 pt, 8 dots, 10 steps per second, a `CAKeyframeAnimation` on layers over the image, added when the badge becomes working and removed in every other state; it keeps moving under Reduce Motion) or one status dot (7 pt), never both; the dot wins. With a badge Loom draws the image itself (a drawing handler that follows the bar's appearance: mark white on a dark bar, black on a light one) with the mark cut away around the badge. Dot class: `ProjectAttention.strongest` over the sessions that need the user; dark bar: Identity A status values; light bar: `#B05A00` attention, `#2A5FD6` unviewed, `#C9332E` failure; Increase Contrast: dot 8 pt, lighter on a dark bar and darker on a light one, chase trail floor 45 % instead of 16 %. Accessibility label "Loom", "Loom, 2 sessions working", "Loom, 1 session needs you, 2 working". `CatalogModel.menuBarSummary` / `onMenuBarChange` are derived beside the Dock count (same call sites, fired on a change only); the menu itself is built when it opens (`menuNeedsUpdate`): a **Needs you** section (class, then most recent, then id; status dot, title, project trailing in secondary text, the project keeps up to 112 pt, a long title is cut at its end) and a **Working** section (static chase glyph, most recent first), each at most 5 rows and then a plain "and N more…" item that only brings Loom forward; then New Claude Session (⌘N, the File menu's action), Open Loom, a separator, Settings… (⌘,, opens General) and Quit Loom (⌘Q, the normal quit path, so the quit question applies). Nothing at all: one disabled line "Nothing is working or waiting." A click on a session brings Loom forward (window reopened when closed) and selects it.
- Needs-approval banner (H1-F; `APP/ApprovalNotifier.swift`, `APP/SystemServices.swift`, rule in `ApprovalNotificationPlanner`): when a session turns Needs approval (a provider approval or an agent's open-session wait) while Loom is not the active app and Settings → General → Notify when a session needs approval is on, one `UserNotifications` banner: identifier = session id, title = the session title, body "<project> · Claude is waiting for your approval." (no project: "Claude is waiting for your approval."), no sound, default interruption level, no actions. Only that transition posts (nothing for failures, finished or working sessions). A click brings Loom forward and selects the session. The banner (delivered and pending) is removed when the session leaves Needs approval, at quit and as a leftover at launch. Permission is requested at launch when the setting is on and the status is not determined, and when the switch is turned on.
- Open at login (H1-F): Settings → General → Open at login (`SMAppService.mainApp`; default off, never registered unasked). The switch shows the system's status and it is read again whenever Settings shows and when Loom becomes active.
- Evidence flavor: `--evidence` swaps both system services for recording fakes (`Evidence/EvidenceSystemCommands.swift`); Loom never calls `UNUserNotificationCenter` or `SMAppService` there.

- The sidebar follows the selection (D-45, `SidebarList` is a `ScrollViewReader`; each card has `.id(row.id)`): when the selection changes by anything but a click in the list (tab strip, Next/Previous Session and Jump shortcuts, Show Session on an "already has a session" notice, a `/clear` move, a start), `CatalogModel.select` asks for a reveal (`revealRequest`): a collapsed project of the session is expanded in the project view, then the list scrolls the least that shows the card, without animation. ## Status to visual mapping

Source: `SessionIndicator` (`CUI/SessionDisplay.swift`), drawing `IndicatorView`/`ChaseDots` (`CUI/IndicatorView.swift`). Derivation order: stop failure > issue > ambiguous identity > a live session whose agent waits for the user's answer to an open-session request (`awaitingOpenApproval`, D-40: reads Needs approval) > live activity (a turn complete with pending provider work counts as Working) > an unviewed finish after the run ended > lifecycle.

| State | Label | Visual |
| --- | --- | --- |
| Working | Working | 8 dots chasing a rounded rectangle, 12 pt, text color, trail opacity 1 / 0.8 / 0.55 / 0.35, rest 0.16, 10 steps/s |
| waitingForApproval | Needs approval | 8 pt orange dot (a provider approval, or the session's agent waiting on an open-session request that is waiting or failed; cards, project dot and tabs agree because `SessionRowModel.indicator`, `attention(forProject:)` and tab eviction all pass `CatalogModel.awaitingOpenApproval`) |
| waitingForInput | Waiting for you | 8 pt orange dot |
| unknown | State unknown | hollow gray ring (1.5 pt) |
| failed / stopUnverified / problem | Failed / Stop not verified / Problem | 8 pt red dot |
| identityUnclear | Identity unclear | hollow orange ring |
| unviewedCompletion | Finished | 8 pt blue dot |
| ready / idle | Ready / Idle | none (Ready: a live run at its prompt, a seen finish or a Claude that just started or resumed) |
| stale | Stale | none; title dimmed |
| ended | no label | none |

Red, orange and blue dots differ by color only. The label text is shown in the detail header and accessibility label, not on the card. Animation gate: `indicatorsAnimate` (default false). Sidebar rows: window active and sidebar not collapsed (`SidebarView.indicatorsAnimate`); detail header: window active. No Reduce Motion code exists; the chase runs under Reduce Motion by user decision (6 Oct 2026). Viewed means the session is selected while the window is active.

## Detail pane (`CUI/DetailView.swift`, `CUI/DetailRoute.swift`)

- Inspector container (V02, V09; `CUI/InspectorContainer.swift`, state `CatalogModel.inspector` = `InspectorState`): a column (328 pt, `Rhythm.inspectorWidth`) right of the content in the same layout pass (`detailInspector(model:)`, below the header and the banners), or, when the content would keep under 480 pt (`LoomTheme.Inspector.minimumContent`) beside it, drawn over the content's trailing edge on the popover surface with its shadow, the content keeping its width: `InspectorPlacement` (closed, column, overlay; pure, `InspectorLayoutTests`). The content is one view in every placement; no SwiftUI `.inspector`, no animation (width equals PTY width, so a terminal resizes once, by the user's toggle only). Tabs Overview and Agents (`InspectorTabBar`: the open tab shows its name, the other its symbol and count). Overview (`InspectorOverview`): Session facts (status, why, project, branch, folder, last activity), Context (`ContextRing`) and, with subagents, an Agents line with "Show Agents". Agents: running and finished subagents as cards, or the open subagent's transcript (see Subagent panel); the empty list says "Agents show while the session runs." for a session with no run now (`InspectorAgents.emptyText`). Closed by default and remembered per session (`UIPreferences.inspectorOpen`); the tab is not remembered (a relaunch opens on Overview). Header toggle `InspectorToggleButton`, 24 pt, beside the control group; View > Toggle Inspector (Opt+Cmd+B). Tokens `LoomTheme.Inspector` (`CUI/LoomTheme+Inspector.swift`).
- Destination (V02b; `CUI/Destination.swift`, `CatalogModel.destination`): where the user is, one of Home, a session, a project's new-session draft (`draft(projectID:)`, nil project allowed) or a project page; nil is nothing selected. `selectedSessionID` is derived from it and every move goes through `CatalogModel.navigate(to:)` (`select`, `showHome()`, `showDraft(projectID:)`, `showProjectPage(_:)`). It is stored as `UIPreferences.destination` (`{"kind": "home" | "session" | "draft" | "project", "id": ...}`); a session is also still written as `selectedSessionID`, and a file from 0.4.4 or batch 1 that has only that key reads as the session destination. ## Verifying UI safely

Details: [DEVELOPMENT.md](../DEVELOPMENT.md) (isolation and evidence rules). Commands live in `APP/DevelopmentEvidence.swift`; launch flags in `Sources/LoomLaunchOptions/LaunchOptions.swift`.

- Launch a separate app copy with `--evidence <dir> --data-root <isolated dir> --fake-providers <fixtures>`. Evidence mode never uses the default catalog; `--data-root` without `--evidence` is refused. Without `--fake-providers`, titles, request text and terminal content are redacted and `screenshot` writes nothing. Seed data with `loom-catalog-fixture seed <data-root> <N> [projects]` (refuses an existing catalog). `scripts/cp5-b-acceptance.sh` is the template for a UI pass.
- Send commands with `loom_send_command <dir> <command>` from `scripts/dev-paths.sh` (a per-directory distributed notification). UI commands: `select:`, `search:`, `view-mode:<activity|projects>`, `toggle-sidebar`, `sidebar-width:`, `resize:<w>x<h>`, `toggle-fullscreen`, `toggle-project:`, `start:<claude|codex>:<project|none>`, `resume:`, `stop:`, `answer:`, `delete:<id>`, `delete-confirm`, `delete-cancel`, `delete-retry:<id>`, `delete-key`, `screenshot-sheet:<label>` (the delete sheet's content view), `begin-rename:`, `rename-text:`, `rename-commit`, `open-settings[:section]`, `close-settings`, `screenshot-settings:<label>`, `usage-select:<period>`, `usage-refresh[:<label>]`, `open-subagent:<session>:<agent>`, `close-subagent`, `inspector:<open|close|overview|agents>`, `palette-open`, `palette-menu[:home]`, `palette-type:<text>`, `palette-key:<up|down|return|cmd-return|escape>`, `palette-state:<label>`, `face:<chat|terminal>`, `new-session:<project|none>`, `draft-text:<project|none>:<text>`, `draft-discard:<project|none>`, `search-session-text:<on|off>`, `show-home`, `home-resume:<session>`, `home-project:<project>`, `project-page:<project>`, `project-tab:<sessions|branches|instructions>`, `project-preset:<project>:<index>`, `project-page-state:<label>`.
- Outputs land in `<dir>`: `screenshot:<label>` writes `screenshot-<label>.png` (content) and `.window.png` (with title bar and traffic lights) from the app's own views, no screen-recording permission; `snapshot:<label>` writes `state-<label>.json` (sidebar width, `sidebarStyle` (the setting), `systemReduceTransparency` and `sidebarMaterial` (what is drawn: opaque or glass), running chase indicators, selected indicator, terminal/runtime state; per activity row `hasReason`, never the reason's text; `subagentPanel{…, inspectorOpen, inspectorTab}`); `buttons:<label>` writes `buttons-<label>.json` (traffic-light hit tests and the 26 pt centerline sweep).
- Screenshots cannot show behind-window glass, animations, hover/focus, menus, sheets or tooltips (the evidence channel renders the Settings window itself: `screenshot-settings:<label>`); those need computer-use or the user.
- Never touch the user's installed Loom Dev app, its default catalog or `ui-preferences.json` under `~/Library/Application Support/Loom-Dev`, or `~/.claude` / `~/.codex`. The `.sh` acceptance scripts refuse to run while any Loom Dev instance is open; the Python runners only check their own package (see `scripts/README.md`). Packaging does a heavy release build; reuse an existing packaged app.
