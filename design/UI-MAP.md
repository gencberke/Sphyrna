# Loom UI map

Inventory of every user-visible surface and state, with the source that draws it. Rules and values are in [DESIGN.md](DESIGN.md), which is Ink (v3) since 20 Oct 2026 (D-74, D-75, D-76); this file says where things live and what the code draws today. Since the Ink tokens landed (V2-PLAN §13, I1) every colour the code draws is Ink's or Paper's, by role, in the three tones; the layout, sizes and shapes are still Night Fleece 2's (the contract before Ink: `git show 371aaf6:design/DESIGN.md`) until each surface moves. Each migration step updates the entries it moves, so the look described here is today's, not the target; an "Ink:" note says where the target differs. Verified by reading code (nothing here was seen on screen unless stated). Update it when you change a surface. Paths are relative to the repo root; `CUI` = `Sources/LoomCatalogUI`, `APP` = `Sources/loom-app`, `TERM` = `Sources/LoomTerminal`.

Shape of the product UI: one native macOS 27 window that follows Settings → Theme → Appearance (Ink by default, Paper, or Match system; `NSApp.appearance`, no colour scheme forced on the roots), a sidebar beside one large main panel that hosts the real CLI or, for a Claude session, the Chat view. A live terminal, the kept screen of an ended run and the development terminal are dark in every appearance (`DetailRoute.drawsDark`), because the CLIs choose their colours for a dark background. Claude and Codex rows exist; Codex is not in the first production release (user decision 6 Oct 2026).

## Window chrome (`APP/AppDelegate.swift` `makeWindow`, `APP/MainSplitViewController.swift`)

- Style: titled, closable, miniaturizable, resizable, full-size content; transparent title bar, hidden title, `isOpaque = false`, clear background, automatic window tabbing off. 1220×780 initial, 780×500 minimum.
- Traffic lights are native and not repositioned. An empty `NSToolbar("loom-main")` with `.unified` style and no separator exists only so AppKit centers them 26 pt from the window top. There is no real toolbar: the "navbar" is the sidebar header row (52 pt) plus the detail header row (36 pt row in a 52 pt block).
- `NSSplitViewController`: sidebar item 220-520 (collapsible), detail minimum 480, thin divider. Width is restored on first layout and persisted 250 ms after a user divider drag only; the sidebar item's `isCollapsed` is the one truth for hidden or shown: `SplitViewItemCollapse` observes it with KVO and `SidebarCollapseSync` (`CUI/SidebarCollapseSync.swift`) mirrors it into `CatalogModel.sidebarCollapsed` (Show button, button gap, persistence) after the saved state was restored; Hide, Show and Cmd+F on a collapsed sidebar all go through `onToggleSidebar`, which sets the opposite of the real state and reconciles again when the animation ends. The dev snapshot carries `sidebarItemCollapsed` next to `sidebarCollapsed`.
- The command palette overlay (V06) is a subview of the split view, added in `viewDidLoad` (`makePaletteOverlayView`), over both panes; it draws and takes clicks only while the palette is open.
- Full screen: the headers stop reserving space for traffic lights (`model.setFullScreen`).
- Appearance (V26; `AppDelegate.applyTheme()`, wired through `CatalogModel.onThemeChange` and `installTheme()`): sets `NSApp.appearance` from Settings → Theme → Appearance (Dark `darkAqua`, Light `aqua`, Match system `nil`), so the windows, alerts and open panels follow it; tells the live terminals to take the tone's Ink canvas in both appearances (`ConversationController.applyTerminalTheme()`) and sets the Settings window's background to the canvas. Launch sets `darkAqua` first and nothing else forces it: the question about a damaged catalog comes before the model exists, and `installTheme()` applies the stored setting right after the model is made. The roots no longer carry `.preferredColorScheme(.dark)`; the palette and the inspector follow the window's appearance (the inspector beside a terminal face is drawn dark with it).
- Window activity (`updateWindowActivity`): active = visible, not occluded, key, app active. It drives `model.windowIsActive`, viewed state and indicator animation.
- Close (red button, Cmd+W) only closes the window; the app and jobs keep running; Dock reopen re-presents it. Errors use `NSAlert` sheets (`showError`); Add Project uses `NSOpenPanel`.
- Quit (D-45, `AppDelegate.applicationShouldTerminate`, rules in `QuitConfirmation`, `CUI/SessionNavigation.swift`): a user-initiated quit (Cmd+Q, the Dock menu) with at least one session Working or Needs approval (an agent waiting on an open-session request counts; Ready, Waiting for you and Finished do not) first asks, as a sheet on the main window (window shown first when closed): "Quit Loom and stop N working sessions?" / "Loom stops every session it started. You can resume each one later." with **Cancel** (first button, the default: Return; Escape cancels too) and **Quit**. No question for a quit the system starts (logout, restart, shutdown: the quit Apple event's `keyAEQuitReason`), when nothing is working, or in an evidence run. Then Quit performs a verified shutdown. A failed shutdown shows an `NSAlert` (`quitAlert`): "Loom could not verify that its processes stopped." with the remaining count and errors, and a second paragraph saying Quit Anyway ends Loom without confirming that every session process stopped and that processes it could not stop may keep running. Buttons **Try Again** (default), **Keep Loom Open**, **Quit Anyway** (destructive; the next `applicationShouldTerminate` returns `.terminateNow`, no verified shutdown). A system-initiated quit whose shutdown cannot be verified is not held up: the report is still written to `shutdown.json`, no alert, the app terminates.
- Dock badge (D-45): `NSApp.dockTile.badgeLabel` is the number of sessions that need the user (the set of the Window menu's jump items), nil at 0, updated by `CatalogModel.onAttentionCountChange` whenever live state, a record or an open-session wait changes (no timer), cleared in `applicationWillTerminate`.
- Menu bar item (H1-F, D-49, D-52; `APP/MenuBarController.swift`, `CUI/MenuBarState.swift`, `CUI/MenuBarFace.swift`, `CUI/MenuBarMark.swift`, `CUI/MenuBarRowText.swift`): an `NSStatusItem` made and removed with Settings → General → Show in menu bar. Its face is the Loom mark (`assets/Loom-menubar.svg`, its path embedded in `MenuBarMark`, no packaged asset; 18 pt wide in a 20 pt canvas). Idle is the plain template image (macOS tints it). The lower right corner is the badge slot: the working chase (9.6 pt, 8 dots, 10 steps per second, a `CAKeyframeAnimation` on layers over the image, added when the badge becomes working and removed in every other state; it keeps moving under Reduce Motion) or one status dot (7 pt), never both; the dot wins. With a badge Loom draws the image itself (a drawing handler that follows the bar's appearance: mark white on a dark bar, black on a light one) with the mark cut away around the badge. Dot class: `ProjectAttention.strongest` over the sessions that need the user; dark bar: Identity A status values; light bar: `#B05A00` attention, `#2A5FD6` unviewed, `#C9332E` failure; Increase Contrast: dot 8 pt, lighter on a dark bar and darker on a light one, chase trail floor 45 % instead of 16 %. Accessibility label "Loom", "Loom, 2 sessions working", "Loom, 1 session needs you, 2 working". `CatalogModel.menuBarSummary` / `onMenuBarChange` are derived beside the Dock count (same call sites, fired on a change only); the menu itself is built when it opens (`menuNeedsUpdate`): a **Needs you** section (class, then most recent, then id; status dot, title, project trailing in secondary text, the project keeps up to 112 pt, a long title is cut at its end) and a **Working** section (static chase glyph, most recent first), each at most 5 rows and then a plain "and N more…" item that only brings Loom forward; then New Claude Session (⌘N, the File menu's action), Open Loom, a separator, Settings… (⌘,, opens General) and Quit Loom (⌘Q, the normal quit path, so the quit question applies). Nothing at all: one disabled line "Nothing is working or waiting." A click on a session brings Loom forward (window reopened when closed) and selects it.
- Needs-approval banner (H1-F; `APP/ApprovalNotifier.swift`, `APP/SystemServices.swift`, rule in `ApprovalNotificationPlanner`): when a session turns Needs approval (a provider approval or an agent's open-session wait) while Loom is not the active app and Settings → General → Notify when a session needs approval is on, one `UserNotifications` banner: identifier = session id, title = the session title, body "<project> · Claude is waiting for your approval." (no project: "Claude is waiting for your approval."), no sound, default interruption level, no actions. Only that transition posts (nothing for failures, finished or working sessions). A click brings Loom forward and selects the session. The banner (delivered and pending) is removed when the session leaves Needs approval, at quit and as a leftover at launch. Permission is requested at launch when the setting is on and the status is not determined, and when the switch is turned on.
- Open at login (H1-F): Settings → General → Open at login (`SMAppService.mainApp`; default off, never registered unasked). The switch shows the system's status and it is read again whenever Settings shows and when Loom becomes active.
- Evidence flavor: `--evidence` swaps both system services for recording fakes (`Evidence/EvidenceSystemCommands.swift`); Loom never calls `UNUserNotificationCenter` or `SMAppService` there.

- Header (52 pt, `SidebarHeader`): 76 pt gap for traffic lights (skipped in full screen), `sidebar.left` toggle ("Hide sidebar"), spacer, mode buttons folder (Group by project, Cmd+2) and clock (Recent activity, Cmd+1) with the selected one filled, and an `ellipsis` menu (Add Project..., Group by Project, Recent Activity). - Search (`SearchField`): always visible, 30 pt, placeholder "Search sessions", clear button. - Home row (V04, `HomeRow` in `CUI/SidebarView.swift`, between the search field and the list): 30 pt, a `house` symbol, "Home" and, only above 0, the count of sessions that need you (`HomeCountBadge`, the Dock badge's number, `CatalogModel.attentionCount`); a click opens Home (`showHome()`), the row is filled like a selected card while Home is the destination.
