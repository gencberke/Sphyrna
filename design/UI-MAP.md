# Loom UI map

Inventory of every user-visible surface and state, with the source that draws it. Rules and values are in [DESIGN.md](DESIGN.md); this file says where things live. Verified by reading code (nothing here was seen on screen unless stated). Update it when you change a surface. Paths are relative to the repo root; `CUI` = `Sources/LoomCatalogUI`, `APP` = `Sources/loom-app`, `TERM` = `Sources/LoomTerminal`.

Shape of the product UI: one native macOS 27 window, dark only (`darkAqua` forced on the window and `.preferredColorScheme(.dark)` on the roots), a sidebar beside one large terminal panel that hosts the real CLI. No chat UI. Claude and Codex rows exist; Codex is not in the first production release (user decision 6 Oct 2026).

## Window chrome (`APP/AppDelegate.swift` `makeWindow`, `APP/MainSplitViewController.swift`)

- Style: titled, closable, miniaturizable, resizable, full-size content; transparent title bar, hidden title, `isOpaque = false`, clear background, automatic window tabbing off. 1220×780 initial, 780×500 minimum.
- Traffic lights are native and not repositioned. An empty `NSToolbar("loom-main")` with `.unified` style and no separator exists only so AppKit centers them 26 pt from the window top. There is no real toolbar: the "navbar" is the sidebar header row (52 pt) plus the detail header row (36 pt row in a 52 pt block).
- `NSSplitViewController`: sidebar item 220-520 (collapsible), detail minimum 480, thin divider. Width is restored on first layout and persisted 250 ms after a user divider drag only; the sidebar item's `isCollapsed` is the one truth for hidden or shown: `SplitViewItemCollapse` observes it with KVO and `SidebarCollapseSync` (`CUI/SidebarCollapseSync.swift`) mirrors it into `CatalogModel.sidebarCollapsed` (Show button, button gap, persistence) after the saved state was restored; Hide, Show and Cmd+F on a collapsed sidebar all go through `onToggleSidebar`, which sets the opposite of the real state and reconciles again when the animation ends. The dev snapshot carries `sidebarItemCollapsed` next to `sidebarCollapsed`.
- Full screen: the headers stop reserving space for traffic lights (`model.setFullScreen`).
- Window activity (`updateWindowActivity`): active = visible, not occluded, key, app active. It drives `model.windowIsActive`, viewed state and indicator animation.
- Close (red button, Cmd+W) only closes the window; the app and jobs keep running; Dock reopen re-presents it. Errors use `NSAlert` sheets (`showError`); Add Project uses `NSOpenPanel`.
- Quit (D-45, `AppDelegate.applicationShouldTerminate`, rules in `QuitConfirmation`, `CUI/SessionNavigation.swift`): a user-initiated quit (Cmd+Q, the Dock menu) with at least one session Working or Needs approval (an agent waiting on an open-session request counts; Ready, Waiting for you and Finished do not) first asks, as a sheet on the main window (window shown first when closed): "Quit Loom and stop N working sessions?" / "Loom stops every session it started. You can resume each one later." with **Cancel** (first button, the default: Return; Escape cancels too) and **Quit**. No question for a quit the system starts (logout, restart, shutdown: the quit Apple event's `keyAEQuitReason`), when nothing is working, or in an evidence run. Then Quit performs a verified shutdown. A failed shutdown shows an `NSAlert` (`quitAlert`): "Loom could not verify that its processes stopped." with the remaining count and errors, and a second paragraph saying Quit Anyway ends Loom without confirming that every session process stopped and that processes it could not stop may keep running. Buttons **Try Again** (default), **Keep Loom Open**, **Quit Anyway** (destructive; the next `applicationShouldTerminate` returns `.terminateNow`, no verified shutdown). A system-initiated quit whose shutdown cannot be verified is not held up: the report is still written to `shutdown.json`, no alert, the app terminates.
- Dock badge (D-45): `NSApp.dockTile.badgeLabel` is the number of sessions that need the user (the set of the Window menu's jump items), nil at 0, updated by `CatalogModel.onAttentionCountChange` whenever live state, a record or an open-session wait changes (no timer), cleared in `applicationWillTerminate`. Not implemented: menu-bar status item (deferred by the contract).

## Sidebar (`CUI/SidebarView.swift`, `CUI/SidebarBackground.swift`)

- Background: `NSVisualEffectView(.sidebar, behindWindow, active)` with `LoomTheme.Surface.sidebar` at 0.6 over it (D-44); opaque `Surface.sidebar` when Reduce Transparency is on or the evidence override says opaque.
- Header (52 pt, `SidebarHeader`): 76 pt gap for traffic lights (skipped in full screen), `sidebar.left` toggle ("Hide sidebar"), spacer, mode buttons folder (Group by project, Cmd+2) and clock (Recent activity, Cmd+1) with the selected one filled, and an `ellipsis` menu (Add Project..., Group by Project, Recent Activity).
- Search (`SearchField`): always visible, 30 pt, placeholder "Search sessions", clear button. Searches title, provider and project only (not transcripts).
- Footer (38 pt, `SidebarFooter` in `CUI/SidebarFooter.swift`): `plus` menu (New Claude Session, New Codex Session, "New Claude Session Without Project" (only while a session is selected, since the plain entries then start in its project), Add Project...; new sessions go to the selected session's project via `contextProjectID`), the usage chip (`UsageChip`, 24 pt, reads only `UsageModel.chip`; split layout (12 Oct 2026): `1.2M today` on the left (the same total the Usage headline uses), on the right edge the plan window that runs out first (lowest remaining percent, tie to the earlier reset, a window past its reset ignored): name `5h` / `Wk`, a 34×4 meter of the remaining share (`UsageChipMeter`) and the percent, e.g. `5h ▬▬ 62%`; under 20 % remaining (`UsageChipContent.Limit.lowBelowPercent`) the percent and the meter fill take the attention orange; no money anywhere; without plan limits `1.2M today` only; when narrow the meter drops first, then the tokens are ellipsized and the limit is never cut; `Indexing…` / `No usage yet`; hidden without an index; `Indexing…` only while the index holds no usage yet, so a later launch keeps the chip hidden until its first refresh ends, and a failed first scan stays hidden (Settings shows why); "Today" is re-read when the local day changes; tooltip carries the token split and both windows (remaining percent, reset time), the accessibility label the tokens and the bottleneck window; click opens Settings at Usage) and a `gearshape` button for Settings. Both buttons 28×26.
- The sidebar follows the selection (D-45, `SidebarList` is a `ScrollViewReader`; each card has `.id(row.id)`): when the selection changes by anything but a click in the list (tab strip, Next/Previous Session and Jump shortcuts, Show Session on an "already has a session" notice, a `/clear` move, a start), `CatalogModel.select` asks for a reveal (`revealRequest`): a collapsed project of the session is expanded in the project view, then the list scrolls the least that shows the card, without animation. A card whose row no list holds (beyond the pages read) is skipped; nothing is paged. A click on a card, the card's Open in Tab and a subagent row never scroll (`selectFromList`, `revealInList: false`).
- Activity view (`ActivityList`): ordered and grouped by last activity (`sessions.last_activity_at`, not by views); day headings Today / Yesterday / weekday / "MMM d" / "MMM d, yyyy" (`DayGrouping`, `CUI/SessionDisplay.swift`, locale `en_US`); cards show the project name; pages load as the last row appears, and a page a reload outdated is read again (`loadMore` retries once the reload ends, so the bottom spinner cannot stay with `hasMore` true).
- Project view (`ProjectList`, `ProjectHeader`): folder icon, name, optional attention dot, collapse chevron, a `plus` button (`ProjectStartButton`: starts a Claude session in that project at once; Claude only; help and accessibility label "New Claude session in <project>"; disabled like the other start entries; not drawn where Claude cannot be started; same 22×20 drawn / 24×24 hit style as the ellipsis, row height unchanged), `ellipsis` menu, tooltip with the path. Tap toggles collapse. Right-click shows New Claude / New Codex Session; the ellipsis menu adds Move Up/Down, "... Here" start items and Remove Empty Project (disabled when the project has sessions). All new-conversation entries come from one component (`NewConversationButtons`). Starting in a collapsed project expands it; searching hides empty projects and forces projects open. "No sessions" under an empty loaded project; a "Sessions" section (tray icon) holds no-project sessions. Inside a project and in "Sessions" the newest-created session is first (`CatalogOrder.creation`, `created_at DESC`; use never moves a row; D-39). Cards omit the project name. Right-clicking the empty area of the list (the scroll content is at least as tall as the list, `SidebarList`) offers "New Claude Session Without Project" (the runtime uses the home folder; the same title as the footer entry, since the area includes gaps inside a project's group); cards and project headers keep their own menus. Not verified with a real right-click yet.
- Project attention dot: 7 pt, priority failure > attention > unviewed (`ProjectAttention`), visible when collapsed, accessibility label such as "A session needs you". No session count.
- Session card (`SessionCardView`): 12×16 indicator slot, title (13 pt, semibold when selected, secondary color when Stale), relative time of the last activity (now/5m/3h/2d/3w/1y; tooltip "Last activity <date>"; a prompt, a finished turn, start, resume and the user's Stop move it, viewing and idle stops do not; `now` ticks each minute while the window is visible, key or not); second row: branch (`arrow.triangle.branch`; for a session an agent opened (D-40) with `sessions.opened_by` set: `arrow.turn.down.right` and "from <requester title>" in place of the branch when both sessions are on the same branch (`SessionOrigin`, unit-tested), otherwise the branch stays and the tooltip reads "Git branch. Opened by <requester>"; a requester that no longer exists reads "another session", and its unknown branch means the card keeps its branch; requester rows and branches come from `CatalogModel.origin(of:)`, which reads loaded rows or an id-keyed cache filled with the list reload, never the catalog during a redraw), a pinned session's pin glyph (`pin.fill`, 10 pt, secondary color, tooltip "Pinned: kept out of session cleanup" where the cleanup review exists (development builds), plain "Pinned" in the daily app; CP4-G; not a pinned tab), project name (activity view only), 14 pt provider icon. Selected: selection fill + hairline stroke, radius 10. Context menu: Rename..., Open in Tab, Pin / Unpin (writes `sessions.pinned`, a cleanup retention exception; help text says it is not a pinned tab; CP4-G, both flavors), Mark as Read (enabled only for Waiting for you and Finished, `SessionIndicator.canMarkRead`; `SessionEventHub.markRead` clears the unseen finish and sets `waitingAcknowledged`, which shows Ready through the rest of the at-prompt period: finished, waiting for input, at prompt; work, an approval, a failure, a new unseen finish, a new run or run end end it; D-39), Resume, Stop (disabled by `canResume`/`canStop`), then the location group (`SessionLocationMenuItems`, `CUI/SessionMenuItems.swift`, also in the detail header's Session actions menu; D-45): **Reveal in Finder** (the working directory, selected in Finder; disabled when it does not exist), **Copy Claude Session ID** (the provider's id) and **Copy Resume Command** (`cd '<dir>' && claude --resume <id>`, POSIX single-quote escaping in `SessionCommandText`; the id is quoted too unless it is only letters, digits, `-`, `_`, `.`); the two copy entries are disabled for non-Claude rows and rows without a provider id; then, in every build, Delete Permanently... (`DeletionMenuItems`; disabled with the reason as a following greyed line for Codex and synthetic rows, a starting, resuming or stopping row and a row already being deleted) and Retry Deleting (only while the row has an unfinished deletion). While a delete runs the relative time reads "Deleting…". Default titles: "Claude · Project" (activity), "Claude session" (project view, including the projectless "Sessions" group), "Claude · No project" (activity view, no project). Accessibility label: "title, Provider, status label" (", opened by <requester>" for an opened session, ", pinned" when pinned).
- Subagent tree (`SessionListEntry` in `CUI/SidebarView.swift` puts `SubagentTreeView` of `CUI/SubagentTree.swift` under `SessionCardView`; D-39, design V3, both views): drawn only while `row.live.subagents` (core `SessionViewState.subagents`, built by `SubagentLedger` from the `SubagentStart` / `SubagentStop` hooks, each subagent's `meta.json` and `Stop.background_tasks`) is not empty, so a session without subagents is exactly the card. What it shows is `SubagentTreeContent` (a plain value, unit-tested): running rows (at most 3 then a "+N more" row that opens and closes), one "N finished" fold row that opens the finished rows, depth indent. Rows: 22 pt, hairline guide 15 pt from the list edge, small chase (`ChaseDots(scale: 0.75)`, gated by `indicatorsAnimate` like the card's), type, description, elapsed (`model.now`, minute tick) or duration. A click on a subagent row selects the parent session (`model.select`); the fold rows only toggle (their state is view state: `@State` in `SubagentTreeView`, so it is per card and not kept across a relaunch). No context menu of its own. Accessibility: one button per row with the label "Subagent <type>, <description>, running|finished"; fold rows "N subagents finished" / "N more running subagents" with an expanded or collapsed value. Data rules (core): only `SubagentStart`/`SubagentStop` of the run's own conversation; Claude's internal agents (empty `agent_type`) ignored; a background subagent seen in `Stop.background_tasks` shows as running even if its start was missed; only a subagent's own stop ends it; finished ones drop on the next real prompt (not on `<agent-message` or `<task-notification` hand-backs); all cleared with the run (new run, detach, run end). Not verified on screen with a real Claude.
- List states (`EmptyListHint`): spinner while loading; "No matching sessions / Search covers title, provider and project."; "No sessions yet. Add a project folder to begin." with a filled accent Add Project button

## Status to visual mapping

Source: `SessionIndicator` (`CUI/SessionDisplay.swift`), drawing `IndicatorView`/`ChaseDots` (`CUI/IndicatorView.swift`). Derivation order: stop failure > issue > ambiguous identity > a live session whose agent waits for the user's answer to an open-session request (`awaitingOpenApproval`, D-40: reads Needs approval) > live activity (a turn complete with pending provider work counts as Working) > an unviewed finish after the run ended > lifecycle.

| State | Label | Visual |
| --- | --- | --- |
| Working | Working | 8 dots chasing a rounded rectangle, 12 pt, text color, trail opacity 1 / 0.8 / 0.55 / 0.35, rest 0.16, 10 steps/s |
| waitingForApproval | Needs approval | 8 pt orange dot (a provider approval, or the session's agent waiting on an open-session request that is waiting or failed; cards, project dot and tabs agree because `SessionRowModel.indicator`, `attention(forProject:)` and tab eviction all pass `CatalogModel.awaitingOpenApproval`) |
| waitingForInput | Waiting for you | 8 pt orange dot |
| unknown | State unknown | hollow gray ring (1.5 pt) |
| failed / stopUnverified / problem | Failed / Stop not verified / Problem | 8 pt red dot |
| identityUnclear | Identity unclear | hollow orange ring |
| unviewedCompletion | Finished | 8 pt blue dot |
| ready / idle | Ready / Idle | none (Ready: a live run at its prompt, a seen finish or a Claude that just started or resumed) |
| stale | Stale | none; title dimmed |
| ended | no label | none |

Red, orange and blue dots differ by color only. The label text is shown in the detail header and accessibility label, not on the card. Animation gate: `indicatorsAnimate` (default false). Sidebar rows: window active and sidebar not collapsed (`SidebarView.indicatorsAnimate`); detail header: window active. No Reduce Motion code exists; the chase runs under Reduce Motion by user decision (6 Oct 2026). Viewed means the session is selected while the window is active.

## Detail pane (`CUI/DetailView.swift`)

- Panel: 10 pt radius, 1 pt hairline, 8 pt inset, terminal-colored fill over a sidebar-colored backdrop.
- Header (`DetailHeader`, row center 26 pt from window top): 66 pt gap only when the sidebar is collapsed and not full screen; `sidebar.left` "Show sidebar" button only while collapsed; 16 pt provider icon, title (semibold, one line), indicator, then "Starting — complete any prompts in the terminal" while starting, else the "Preparing Claude…" notice while a start has no card yet (header row only: nothing above the terminal changes height, so no PTY resize), else the colored 11 pt status label. Right side: system `.bordered` small "Stop" button when `canStop` (not `ChromeButtonStyle`), and an `ellipsis` "Session actions" menu (Rename..., Open in Tab, Resume, Stop, the same location group as the card (Reveal in Finder, Copy Claude Session ID, Copy Resume Command), and the same `DeletionMenuItems` as the card, Delete Permanently... in every build). While a delete runs the status label reads "Deleting…". Dev-only variant: "Synthetic terminal (development)".
- Banners (`Banners`, `BannerRow`): ownership notice (orange), status message (secondary), dismissible error (red) and info (secondary).
- Deletion banner (`DeletionBanner` in `CUI/DeletionViews.swift`, mounted under `Banners`; shown in every build, also where Delete is hidden, because a deletion the runtime recovered at launch must stay visible and retryable): one row per unfinished deletion, "Deleting this session isn't finished. <what failed>. Nothing else was touched." in the failure color with the session title below it (when known) and a tinted "Try Again" button; a deletion that is running (for example finishing after a launch) reads "Deleting <title>…" without a button; when launch recovery could not read its records the reason is shown as one red line. The runtime fences a session out of every list as soon as its deletion starts, so a failed deletion is only visible here, not as a card. Texts: `DeletionCopy`.
- Delete sheet (`DeleteConversationSheet`, 420 pt, attached to the main window like the rename sheet, opened by `model.deletions.confirmation`): title "Delete this session?", the session's title, the runtime's dry run in one paragraph (what is removed with the file count, size and Claude config folder; what is not removed; "It is running now, so Loom stops it first" when it has a live run), "Checking what Claude has kept for this session…" while the plan is made, the runtime's refusal in red when there is one, and a red note when a folder cannot be entered (the Delete button stays disabled then). Buttons: Cancel (cancel action) and a destructive "Delete Permanently" (`DestructiveButtonStyle`: failure fill, dark text; not the default action). Confirming closes the sheet and moves the selection away at once.
- Tab strip (`ConversationTabStrip` in `CUI/ConversationTabStrip.swift`, mounted by `DetailTop` directly under `DetailHeader` and above `Banners`, inside the panel; D-33; the header's 16 pt bottom spacing is dropped while the strip shows, so row and strip are 36 + 32 pt and the 52 pt block is unchanged with one tab, pinned by a layout test): 32 pt high, drawn only with two or more visible tabs (pinned tabs plus the selected session as one transient tab; not over the development terminal), so the panel is unchanged with one. Tabs are 24 pt high (radius 6), 4 pt apart, 8 pt side inset, 112 to 200 pt wide, and share the width equally: [12 x 16 indicator slot (`IndicatorView`)] 6 pt [title, 12 pt medium, one line] [16 pt close]. Selected = white 7 % fill with a 10 % hairline stroke and primary text; others secondary text, white 9 % fill and primary text on hover. The transient tab's title is italic; a stale tab's title is secondary. The close button (xmark, `Radius.bar`) is reserved on the selected tab only (4 pt trailing padding) and appears over the end of an unselected tab on hover; its fill is the pressed white 14 % (selected tab: only while the button itself is hovered). Click selects (`selectTab`, never starts or stops anything); a double click pins the transient tab (`openTab`); right click offers Open in Tab (transient only) and Close Tab; close only unpins, and the selected tab's right neighbor (else left) is shown. Overflow: tabs stop shrinking at 112 pt, the list scrolls horizontally (a 28 pt trailing fade, the selected tab revealed by the smallest scroll) and a 28 x 24 chevron button lists every tab (status label, check on the selected one) with a 6 pt dot for the strongest status among tabs scrolled out of view (failure over attention over unviewed, as a project row). Titles follow renames and indicators follow live state because every tab reads its `SessionRowModel`. Tokens: `LoomTheme.TabStrip`. Geometry rules and the chevron-dot priority are unit-tested (`TabStripLayout`). Open points: the design table gives the chevron as 24 x 24, the stage plan as 28 pt (built 28 x 24); hover visuals have no screenshot (evidence renders cannot hover).
- Provider requests (`RequestList`): orange-tinted box, hand icon, summary, failure text; Deny / Approve (default action) only when `isAnswerable`. Shown above the terminal and above the history view.
- Open-session requests (D-40; `OpenRequestBoxes` / `OpenRequestBox` in `CUI/OpenRequestViews.swift`, content value `OpenRequestBoxContent` in `CUI/OpenRequestDisplay.swift`; drawn by `RequestList` after the provider requests, so above the requesting session's terminal and its history view): for `kind .open` an orange-tinted box with `plus.square.on.square`, heading "Open a new session?", Project / Title / Ticket (if any) lines, the first message as a preview (first 4 lines, at most 480 characters; "Show full message" opens the whole text in a scroll area of at most 160 pt, "Show less" closes it), buttons **Deny** and **Open Session** (filled accent), neither the default action and no key equivalent, so Return belongs to the terminal. `.starting`: buttons disabled, "Opening…". `.failed(text)`: the text in the failure color and **Dismiss** (the request is spent and never retried). `kind .exists`: a neutral box (white 6 % fill, `info.circle`) "<ticket> already has a session: <title>" with **Show Session** (the only thing that selects: `model.showExistingSession`) and **Dismiss**. Approving does not select the new session; it appears at the top of its project with its working indicator, and a collapsed project is expanded. The model mirrors the runtime's list (`ConversationController.begin` follows `SessionRuntime.openRequestUpdates`); the requester's card shows Needs approval while a request is waiting or failed (Status table).
- Ended screen (D-45; `EndedScreenNotice` in `CUI/DetailView.swift`, kept screens in `ConversationController.ended`, rules in `EndedScreenPolicy`, `CUI/EndedScreens.swift`): when a run ends (the CLI exits, a failed resume, an expired login, /exit, the user's Stop) and its session is selected or a pinned tab, the terminal surface is kept instead of dropped, so what the CLI printed last stays readable (select and copy work). It is read-only: `TerminalSurface.keepAsReadOnly()` drops keys, pastes and drops silently (no error banner). Above it, after the provider requests, a slim notice (opacity-only fade, no height animation): "This session is not running." The Resume menu item and Cmd+R work as for the record view.
- Content (`DetailContent`, priority order): catalog startup error ("Loom could not open its catalog ..."); dev terminal (evidence only); selected row with a live terminal (`TerminalHost` in `TerminalContainerView`, 6 pt inset, focus pushed to the terminal on window entry); selected row whose run ended and whose last screen is kept (D-45, below); selected row without a terminal (`ConversationDetail`: 34 pt icon, 20 pt title, notices for stop unverified / problem / identity unclear / failed / "Finished while you were away", facts grid Status, Project, Opened by (only for a session an agent opened: the requester's title, or "Another session"), Working directory, Provider session, Created, Last activity, Last used (the last view or use), "Not running" text with Resume or "Reactivate and Resume" (a click or Cmd+R, not the default action, so Return after a keyboard tab switch launches nothing) / Stop / Rename... (a Codex record in the production build: the explanation line reads "Codex sessions can't be resumed in this version." and Resume is disabled), busy line "Resuming... / Starting... / Stopping...", max width 640); empty catalog ("Add a project to begin" with Add Project... Cmd+O, New Claude, New Codex buttons); else "No session selected".
- Rename sheet (`RenameSheet`, 420 pt): counter against 160 characters, failure text, Cancel / Save; hint "Longer titles are shortened. An empty title returns to the automatic one."

## Terminal surface (`TERM/TerminalSurface.swift`, `TERM/TerminalTheme.swift`)

- Palette (`TerminalTheme`): background sRGB (29, 28, 34), foreground (232, 230, 238), 16 ANSI colors from VS Code Dark+, 256-color strategy `.xterm` (the engine default washed colors out, UI item 7). `COLORTERM=truecolor` is set in the provider environment (`Sources/LoomCore/LaunchEnvironment.swift`).
- Font: `SFMono-Regular`, falling back to the system monospaced font; 11-20 pt, default 14. Steady block cursor, `xterm-256color`, scrollback 2,000 lines, Kitty/inline image stores 8 MiB per screen (1,024 images max), OSC cap 1 MiB, Sixel parsed but not advertised, clipboard read/write disabled, rendering suspended when not visible, accessibility label "Terminal".
- A kept screen of an ended run (D-45) is the same view, read-only: see "Ended screen" under Detail pane.
- Input: dropped files are inserted as quoted paths without Enter; HTTP(S) and existing local file links open, other schemes do not; an image-only clipboard is forwarded as Ctrl+V.

## Settings (`CUI/SettingsView.swift`, `CUI/UsageSettingsView.swift`, `SettingsWindowController`)

One reused, dark (forced `darkAqua`, `.tint(Accent.base)`), fixed 680×520 window with a transparent title bar (Cmd+, the gear, the usage chip; the chip opens it at Usage). A top switcher General · Usage · About (plus Sessions in development builds, see below) sits on the 26 pt centerline. General: terminal font size (11-20 pt, applies live) and the model's error message. Usage (`UsageModel`, from `ClaudeUsageIndex`): scope line, periods 24 h / 7 d / 30 d / 90 d, token headline with an estimated cost line, a compact "Plan limits" block (5-hour and weekly: used and remaining percent, reset time, "Updated" time; hidden when the Claude CLI cannot report them), an approximate five-hourly-cell activity block labelled "not your plan limit", totals by token type and cache share, neutral per-day (per-hour for 24 h) bars, a per-model table with share and estimated cost, and a footer with "Updated", "Prices as of" and a refresh button; states "Reading Claude's usage" and "No Claude usage yet". About: version, data folder (Reveal) and the Claude profile in use (read only). Sessions (`CleanupReviewView`, `CleanupReviewModel` in `CatalogModel+Cleanup.swift`, CP4-G; present only when `BuildIdentity.cleanupReviewEnabled`, i.e. development builds until DP-CP4-2 is decided; manual Delete Permanently... is in every build): runs `CleanupCoordinator` when the section opens, shows a quiet info line when the review is due (with Dismiss; dismiss or confirm records `last_cleanup_at`), "Can be deleted (N)" rows with a checkbox (nothing is checked by default), title, project, "Stale since" date and the CP4-A dry-run size, "Kept (N)" rows with the reason (pinned, running, waits until a date, worktree has changes, unfinished task), a footer with a re-review button and "Delete N Sessions" behind a confirmation alert. Confirming re-plans; only checked rows that are still eligible are deleted, one by one, each row showing Deleted / Failed / Not finished / Skipped. Only Claude sessions are offered. Provider install status and re-check are specified (`plans/CHECKPOINT-5-HISTORY.md` section 4.1) but not built. Usage follows the transcripts: one FSEvents stream over the profile's `projects` folder (`UsageTranscriptWatcher`) reports changes, which are read for just the changed files after a 2 s debounce while the main window is active or the Usage page is visible (Settings is a separate window and counts as a reader); otherwise the numbers are marked stale and one full read runs when a window shows again. Launch (after the first catalog load), window activation, Settings opening, a finished Claude turn (the event frame's turn count, so a skipped frame does not matter) and the refresh button still refresh. Plan limits come from the Claude CLI's own `get_usage` control request (`ClaudePlanLimitsFetcher`, a short headless `claude -p` stream-json process with hooks disabled, no MCP servers and no session kept; no model turn): asked when the first window shows, when the Usage page opens, after a finished turn if the last ask is 2 minutes old, and when a window shows again after 5 minutes, never with no window visible, never two at once. The profile is `CLAUDE_CONFIG_DIR` from Loom's own environment, else `~/.claude` (never a login shell).

## Accessibility

Present: labels on chrome buttons, search, mode buttons (selected trait), cards, project attention dot, the ended-screen notice (a container with identifier `ended-screen-notice`); indicators are hidden from accessibility (the card label carries the status); Reduce Transparency swaps the sidebar to opaque. Focus ring: `ChromeButtonStyle` draws a 1.5 pt accent (`Surface.focusRing`) ring only when the button is focused and Full Keyboard Access is on (one shared `KeyboardNavigation` flag, refreshed on `didBecomeKey`); `.focusEffectDisabled()` suppresses the system effect. Reduce Motion: see the status mapping above. Absent: Differentiate Without Color and Increase Contrast handling, Dynamic Type (all sizes fixed). No full audit is claimed.

## Design tokens in code

`CUI/LoomTheme.swift` is the one source of visual values (no `CatalogTheme` any more); views carry no `Color(red:)`, `Color.white`, `.system(size:)` or literal corner radius, enforced by `scripts/check-theme-literals.sh`. Namespaces: `Surface` (sidebar, backdrop, panel = `TerminalTheme.background`, `sidebarTintOpacity` 0.86, hairline white 0.10, selected 0.07, control 0.06 / hover 0.09 / pressed 0.14, focus ring = accent), `Text` (primary `#E0DBEB`, secondary `#828799`, tertiary `#5A5F70`), `Accent` (`base` `#8791CF`, `onAccent` = sidebar tone for text on accent fills), `Status` (attention, unviewed, failure, working = primary, `tintOpacity` 0.10), `Opacity` (disabled 0.4), `Radius` (panel 10, card 10, control 6, search 8, callout 8), `Line`, `Typography` (fixed-size fonts by role; named so because `Type` cannot be a nested type name), `Space` (paddings and gaps by role, terminal inset 6), `Layout` (`headerHeight` 52, `detailRowHeight` 36, `sidebarButtonsGap` 76, `detailButtonsGap` 66, search 30, footer 38, chrome button 26×24, footer buttons 28×26, project menu 22×20, indicator slot 12×16, pip 8, project dot 8, chase geometry), `Motion` (chase 10 fps, 8 dots, trail, rest). Colors are also kept as `RGB` data so `LoomThemeTests` can compute contrast. `AccentButtonStyle` (`CUI/DetailView.swift`): `filled` (accent fill, dark text) for Resume/Reactivate, Approve, Save and Add Project; `tinted` for the header Stop. Rules: DESIGN.md §6. `CUI/IndicatorView.swift` holds `IndicatorView`, `ChaseDots`, status label colors and `IndicatorEvidence`; `CUI/ProviderIcon.swift` the provider icons. `CUI/UIPreferences.swift`: sidebar default 300 / range 220-520, terminal font default 14 / range 11-20; stored per bundle in `ui-preferences.json` inside the data root (viewMode, selectedSessionID, sidebarWidth, sidebarCollapsed, terminalFontSize; bad values fall back to defaults, an unreadable file is moved aside). ## Verifying UI safely

Details: [DEVELOPMENT.md](../DEVELOPMENT.md) (isolation and evidence rules). Commands live in `APP/DevelopmentEvidence.swift`; launch flags in `Sources/LoomLaunchOptions/LaunchOptions.swift`.

- Launch a separate app copy with `--evidence <dir> --data-root <isolated dir> --fake-providers <fixtures>`. Evidence mode never uses the default catalog; `--data-root` without `--evidence` is refused. Without `--fake-providers`, titles, request text and terminal content are redacted and `screenshot` writes nothing. Seed data with `loom-catalog-fixture seed <data-root> <N> [projects]` (refuses an existing catalog). `scripts/cp5-b-acceptance.sh` is the template for a UI pass.
- Send commands with `loom_send_command <dir> <command>` from `scripts/dev-paths.sh` (a per-directory distributed notification). UI commands: `select:`, `search:`, `view-mode:<activity|projects>`, `toggle-sidebar`, `sidebar-width:`, `resize:<w>x<h>`, `toggle-fullscreen`, `toggle-project:`, `start:<claude|codex>:<project|none>`, `resume:`, `stop:`, `answer:`, `delete:<id>`, `delete-confirm`, `delete-cancel`, `delete-retry:<id>`, `delete-key`, `screenshot-sheet:<label>` (the delete sheet's content view), `begin-rename:`, `rename-text:`, `rename-commit`, `open-settings[:section]`, `close-settings`, `screenshot-settings:<label>`, `usage-select:<period>`, `usage-refresh[:<label>]`.
- Outputs land in `<dir>`: `screenshot:<label>` writes `screenshot-<label>.png` (content) and `.window.png` (with title bar and traffic lights) from the app's own views, no screen-recording permission; `snapshot:<label>` writes `state-<label>.json` (sidebar width, material, running chase indicators, selected indicator, terminal/runtime state); `buttons:<label>` writes `buttons-<label>.json` (traffic-light hit tests and the 26 pt centerline sweep).
- Screenshots cannot show behind-window glass, animations, hover/focus, menus, sheets or tooltips (the evidence channel renders the Settings window itself: `screenshot-settings:<label>`); those need computer-use or the user.
- Never touch the user's installed Loom Dev app, its default catalog or `ui-preferences.json` under `~/Library/Application Support/Loom-Dev`, or `~/.claude` / `~/.codex`. The `.sh` acceptance scripts refuse to run while any Loom Dev instance is open; the Python runners only check their own package (see `scripts/README.md`). Packaging does a heavy release build; reuse an existing packaged app.
