# Loom UI map

Inventory of every user-visible surface and state, with the source that draws it. Rules and values are in [DESIGN.md](DESIGN.md); this file says where things live. Verified by reading code (nothing here was seen on screen unless stated). Update it when you change a surface. Paths are relative to the repo root; `CUI` = `Sources/LoomCatalogUI`, `APP` = `Sources/loom-app`, `TERM` = `Sources/LoomTerminal`.

Shape of the product UI: one native macOS 27 window, dark only (`darkAqua` forced on the window and `.preferredColorScheme(.dark)` on the roots), a sidebar beside one large terminal panel that hosts the real CLI. No chat UI. Claude and Codex rows exist; Codex is not in the first production release (user decision 6 Oct 2026).

## Window chrome (`APP/AppDelegate.swift` `makeWindow`, `APP/MainSplitViewController.swift`)

- Style: titled, closable, miniaturizable, resizable, full-size content; transparent title bar, hidden title, `isOpaque = false`, clear background, automatic window tabbing off. 1220×780 initial, 780×500 minimum.
- Traffic lights are native and not repositioned. An empty `NSToolbar("loom-main")` with `.unified` style and no separator exists only so AppKit centers them 26 pt from the window top. There is no real toolbar: the "navbar" is the sidebar header row (52 pt) plus the detail header row (36 pt row in a 52 pt block).
- `NSSplitViewController`: sidebar item 220-520 (collapsible), detail minimum 480, thin divider. Width is restored on first layout and persisted 250 ms after a user divider drag only; the sidebar item's `isCollapsed` is the one truth for hidden or shown: `SplitViewItemCollapse` observes it with KVO and `SidebarCollapseSync` (`CUI/SidebarCollapseSync.swift`) mirrors it into `CatalogModel.sidebarCollapsed` (Show button, button gap, persistence) after the saved state was restored; Hide, Show and Cmd+F on a collapsed sidebar all go through `onToggleSidebar`, which sets the opposite of the real state and reconciles again when the animation ends. The dev snapshot carries `sidebarItemCollapsed` next to `sidebarCollapsed`.
- Full screen: the headers stop reserving space for traffic lights (`model.setFullScreen`).
- Window activity (`updateWindowActivity`): active = visible, not occluded, key, app active. It drives `model.windowIsActive`, viewed state and indicator animation.
- Close (red button, Cmd+W) only closes the window; the app and jobs keep running; Dock reopen re-presents it. Errors use `NSAlert` sheets (`showError`); Add Project uses `NSOpenPanel`.
- Quit (D-45, `AppDelegate.applicationShouldTerminate`, rules in `QuitConfirmation`, `CUI/SessionNavigation.swift`): a user-initiated quit (Cmd+Q, the Dock menu) with at least one session Working or Needs approval (an agent waiting on an open-session request counts; Ready, Waiting for you and Finished do not) first asks, as a sheet on the main window (window shown first when closed): "Quit Loom and stop N working sessions?" / "Loom stops every session it started. You can resume each one later." with **Cancel** (first button, the default: Return; Escape cancels too) and **Quit**. No question for a quit the system starts (logout, restart, shutdown: the quit Apple event's `keyAEQuitReason`), when nothing is working, or in an evidence run. Then Quit performs a verified shutdown. A failed shutdown shows an `NSAlert` (`quitAlert`): "Loom could not verify that its processes stopped." with the remaining count and errors, and a second paragraph saying Quit Anyway ends Loom without confirming that every session process stopped and that processes it could not stop may keep running. Buttons **Try Again** (default), **Keep Loom Open**, **Quit Anyway** (destructive; the next `applicationShouldTerminate` returns `.terminateNow`, no verified shutdown). A system-initiated quit whose shutdown cannot be verified is not held up: the report is still written to `shutdown.json`, no alert, the app terminates.
- Dock badge (D-45): `NSApp.dockTile.badgeLabel` is the number of sessions that need the user (the set of the Window menu's jump items), nil at 0, updated by `CatalogModel.onAttentionCountChange` whenever live state, a record or an open-session wait changes (no timer), cleared in `applicationWillTerminate`.
- Menu bar item (H1-F, D-49, D-52; [preview](menu-bar-preview.html); `APP/MenuBarController.swift`, `CUI/MenuBarState.swift`, `CUI/MenuBarFace.swift`, `CUI/MenuBarMark.swift`, `CUI/MenuBarRowText.swift`): an `NSStatusItem` made and removed with Settings → General → Show in menu bar. Its face is the Loom mark (`assets/Loom-menubar.svg`, its path embedded in `MenuBarMark`, no packaged asset; 18 pt wide in a 20 pt canvas). Idle is the plain template image (macOS tints it). The lower right corner is the badge slot: the working chase (9.6 pt, 8 dots, 10 steps per second, a `CAKeyframeAnimation` on layers over the image, added when the badge becomes working and removed in every other state; it keeps moving under Reduce Motion) or one status dot (7 pt), never both; the dot wins. With a badge Loom draws the image itself (a drawing handler that follows the bar's appearance: mark white on a dark bar, black on a light one) with the mark cut away around the badge. Dot class: `ProjectAttention.strongest` over the sessions that need the user; dark bar: Identity A status values; light bar: `#B05A00` attention, `#2A5FD6` unviewed, `#C9332E` failure; Increase Contrast: dot 8 pt, lighter on a dark bar and darker on a light one, chase trail floor 45 % instead of 16 %. Accessibility label "Loom", "Loom, 2 sessions working", "Loom, 1 session needs you, 2 working". `CatalogModel.menuBarSummary` / `onMenuBarChange` are derived beside the Dock count (same call sites, fired on a change only); the menu itself is built when it opens (`menuNeedsUpdate`): a **Needs you** section (class, then most recent, then id; status dot, title, project trailing in secondary text, the project keeps up to 112 pt, a long title is cut at its end) and a **Working** section (static chase glyph, most recent first), each at most 5 rows and then a plain "and N more…" item that only brings Loom forward; then New Claude Session (⌘N, the File menu's action), Open Loom, a separator, Settings… (⌘,, opens General) and Quit Loom (⌘Q, the normal quit path, so the quit question applies). Nothing at all: one disabled line "Nothing is working or waiting." A click on a session brings Loom forward (window reopened when closed) and selects it.
- Needs-approval banner (H1-F; `APP/ApprovalNotifier.swift`, `APP/SystemServices.swift`, rule in `ApprovalNotificationPlanner`): when a session turns Needs approval (a provider approval or an agent's open-session wait) while Loom is not the active app and Settings → General → Notify when a session needs approval is on, one `UserNotifications` banner: identifier = session id, title = the session title, body "<project> · Claude is waiting for your approval." (no project: "Claude is waiting for your approval."), no sound, default interruption level, no actions. Only that transition posts (nothing for failures, finished or working sessions). A click brings Loom forward and selects the session. The banner (delivered and pending) is removed when the session leaves Needs approval, at quit and as a leftover at launch. Permission is requested at launch when the setting is on and the status is not determined, and when the switch is turned on.
- Open at login (H1-F): Settings → General → Open at login (`SMAppService.mainApp`; default off, never registered unasked). The switch shows the system's status and it is read again whenever Settings shows and when Loom becomes active.
- Evidence flavor: `--evidence` swaps both system services for recording fakes (`Evidence/EvidenceSystemCommands.swift`); Loom never calls `UNUserNotificationCenter` or `SMAppService` there.

## Sidebar (`CUI/SidebarView.swift`, `CUI/SidebarBackground.swift`)

- Background: `NSVisualEffectView(.sidebar, behindWindow, active)` with `LoomTheme.Surface.sidebar` at 0.6 over it (D-44); opaque `Surface.sidebar` when Reduce Transparency is on or the evidence override says opaque.
- Header (52 pt, `SidebarHeader`): 76 pt gap for traffic lights (skipped in full screen), `sidebar.left` toggle ("Hide sidebar"), spacer, mode buttons folder (Group by project, Cmd+2) and clock (Recent activity, Cmd+1) with the selected one filled, and an `ellipsis` menu (Add Project..., Group by Project, Recent Activity).
- Search (`SearchField`): always visible, 30 pt, placeholder "Search sessions", clear button. Searches title, provider and project only (not transcripts). A settled search (120 ms debounce) is one cancellable query over the whole catalog (`SessionCatalog.searchSessions`): the activity view gets one list in activity order, the project view each project's first page in creation order (collapsed projects included, so every project with a match shows), grouped in memory; a newer keystroke cancels an older read and an older result never replaces a newer one. Paging ("load more") continues per list from the result's cursors.
- Footer (38 pt, `SidebarFooter` in `CUI/SidebarFooter.swift`): `plus` menu (New Claude Session, New Codex Session, "New Claude Session Without Project" (only while a session is selected, since the plain entries then start in its project), Add Project...; new sessions go to the selected session's project via `contextProjectID`), the usage chip (`UsageChip`, 24 pt, reads only `UsageModel.chip`; split layout (12 Oct 2026): `1.2M today` on the left (the same total the Usage headline uses), on the right edge the plan window that runs out first (lowest remaining percent, tie to the earlier reset, a window past its reset ignored): name `5h` / `Wk`, a 34×4 meter of the remaining share (`UsageChipMeter`) and the percent, e.g. `5h ▬▬ 62%`; under 20 % remaining (`UsageChipContent.Limit.lowBelowPercent`) the percent and the meter fill take the attention orange; no money anywhere; without plan limits `1.2M today` only; when narrow the meter drops first, then the tokens are ellipsized and the limit is never cut; `Indexing…` / `No usage yet`; hidden without an index; `Indexing…` only while the index holds no usage yet, so a later launch keeps the chip hidden until its first refresh ends, and a failed first scan stays hidden (Settings shows why); "Today" is re-read when the local day changes; tooltip carries the token split and both windows (remaining percent, reset time), the accessibility label the tokens and the bottleneck window; click opens Settings at Usage) and a `gearshape` button for Settings. Both buttons 28×26.
- The sidebar follows the selection (D-45, `SidebarList` is a `ScrollViewReader`; each card has `.id(row.id)`): when the selection changes by anything but a click in the list (tab strip, Next/Previous Session and Jump shortcuts, Show Session on an "already has a session" notice, a `/clear` move, a start), `CatalogModel.select` asks for a reveal (`revealRequest`): a collapsed project of the session is expanded in the project view, then the list scrolls the least that shows the card, without animation. A card whose row no list holds (beyond the pages read) is skipped; nothing is paged. A click on a card, the card's Open in Tab and a subagent row never scroll (`selectFromList`, `revealInList: false`).
- Activity view (`ActivityList`): ordered and grouped by last activity (`sessions.last_activity_at`, not by views); day headings Today / Yesterday / weekday / "MMM d" / "MMM d, yyyy" (`DayGrouping`, `CUI/SessionDisplay.swift`, locale `en_US`; grouped once per list change and calendar day, `SessionListModel.daySections(today:)` keyed by `CatalogModel.today`, so the minute tick does not regroup); cards show the project name; pages load as the last row appears, and a page a reload outdated is read again (`loadMore` retries once the reload ends, so the bottom spinner cannot stay with `hasMore` true).
- Project view (`ProjectList`, `ProjectHeader`): folder icon, name, optional attention dot, collapse chevron, a `plus` button (`ProjectStartButton`: starts a Claude session in that project at once; Claude only; help and accessibility label "New Claude session in <project>"; disabled like the other start entries; not drawn where Claude cannot be started; same 22×20 drawn / 24×24 hit style as the ellipsis, row height unchanged), `ellipsis` menu, tooltip with the path. Tap toggles collapse. Right-click shows New Claude / New Codex Session; the ellipsis menu adds Move Up/Down, "... Here" start items and Remove Empty Project (disabled when the project has sessions). All new-conversation entries come from one component (`NewConversationButtons`). Starting in a collapsed project expands it; searching hides empty projects and forces projects open. "No sessions" under an empty loaded project; a "Sessions" section (tray icon) holds no-project sessions. Inside a project and in "Sessions" the newest-created session is first (`CatalogOrder.creation`, `created_at DESC`; use never moves a row; D-39). Cards omit the project name. Right-clicking the empty area of the list (the scroll content is at least as tall as the list, `SidebarList`) offers "New Claude Session Without Project" (the runtime uses the home folder; the same title as the footer entry, since the area includes gaps inside a project's group); cards and project headers keep their own menus. Not verified with a real right-click yet.
- Project colours (D-48; `CUI/ProjectColorViews.swift`, `LoomTheme.ProjectColor`; DESIGN §6): with Settings → Project colors on, `ProjectHeader` and `SessionCardView` (both views) carry `projectStripe(tone)`, an overlay that draws a 3 pt (4 pt under Increase Contrast) rounded stripe 4 pt left of the row's leading edge, so card geometry does not change; the header's stripe runs from 11 pt below the row top to 1 pt above its bottom, the card's over its full height. The tone comes from `CatalogModel.projectTone(forProject:)`, a dictionary (`projectTones`) filled when `projects` is read; nil while the setting is off, for the "Sessions" group, None and unknown tones. The selected card keeps its fill and hairline. The project's `ellipsis` menu and its right-click menu gain a **Color** submenu (`ProjectColorMenu`; hidden while the setting is off): six rounded-square swatches (`ProjectSwatch`) with the tone names, a divider, **None** (hollow swatch), a checkmark on the current one (none for an unknown stored tone); a choice calls `CatalogModel.setProjectTone`, which writes `projects.color` and re-reads the projects (no list reload). Not verified on screen: the stripes' alignment as one rail, the swatches in the menu.
- Project attention dot: 7 pt, priority failure > attention > unviewed (`ProjectAttention`), visible when collapsed, accessibility label such as "A session needs you". No session count.
- Session card (`SessionCardView`): 12×16 indicator slot, title (13 pt, semibold when selected, secondary color when Stale), relative time of the last activity (`CardTimeLabel`, the only part of a card that reads the minute tick: now/5m/3h/2d/3w/1y; tooltip "Last activity <date>", formatted once per activity time and kept with the row, `SessionRowModel.activityTooltip`; a prompt, a finished turn and start move it; viewing, Stop, resume and idle stops do not (FB4-1); `now` ticks each minute while the window is visible, key or not); second row: branch (`arrow.triangle.branch`; for a session an agent opened (D-40) with `sessions.opened_by` set: `arrow.turn.down.right` and "from <requester title>" in place of the branch when both sessions are on the same branch (`SessionOrigin`, unit-tested), otherwise the branch stays and the tooltip reads "Git branch. Opened by <requester>"; a requester that no longer exists reads "another session", and its unknown branch means the card keeps its branch; requester rows and branches come from `CatalogModel.origin(of:)`, which reads loaded rows or an id-keyed cache filled with the list reload, never the catalog during a redraw), a pinned session's pin glyph (`pin.fill`, 10 pt, secondary color, tooltip "Pinned: kept out of session cleanup" where the cleanup review exists (development builds), plain "Pinned" in the daily app; CP4-G; not a pinned tab), project name (activity view only), 14 pt provider icon. Selected: selection fill + hairline stroke, radius 10 (read from the row's own `isSelected` flag, set by `CatalogModel.select` on the old and the new row: a selection change redraws those two cards, a minute tick only the time labels; counted by `SidebarRenderTests` through `SidebarRenderProbe`). Context menu: Rename..., Open in Tab, Pin / Unpin (writes `sessions.pinned`, a cleanup retention exception; help text says it is not a pinned tab; CP4-G, both flavors), Mark as Read (enabled only for Waiting for you and Finished, `SessionIndicator.canMarkRead`; `SessionEventHub.markRead` clears the unseen finish and sets `waitingAcknowledged`, which shows Ready through the rest of the at-prompt period: finished, waiting for input, at prompt; work, an approval, a failure, a new unseen finish, a new run or run end end it; D-39), Resume, Stop (disabled by `canResume`/`canStop`), then the location group (`SessionLocationMenuItems`, `CUI/SessionMenuItems.swift`, also in the detail header's Session actions menu; D-45): **Reveal in Finder** (the working directory, selected in Finder; disabled when it does not exist), **Copy Claude Session ID** (the provider's id) and **Copy Resume Command** (`cd '<dir>' && claude --resume <id>`, POSIX single-quote escaping in `SessionCommandText`; the id is quoted too unless it is only letters, digits, `-`, `_`, `.`); the two copy entries are disabled for non-Claude rows and rows without a provider id; then, in every build, Delete Permanently... (`DeletionMenuItems`; disabled with the reason as a following greyed line for Codex and synthetic rows, a starting, resuming or stopping row and a row already being deleted) and Retry Deleting (only while the row has an unfinished deletion). While a delete runs the relative time reads "Deleting…". Default titles: "Claude · Project" (activity), "Claude session" (project view, including the projectless "Sessions" group), "Claude · No project" (activity view, no project). Accessibility label: "title, Provider, status label" (", opened by <requester>" for an opened session, ", pinned" when pinned).
- Subagent tree (`SessionListEntry` in `CUI/SidebarView.swift` puts `SubagentTreeView` of `CUI/SubagentTree.swift` under `SessionCardView`; D-39, design V3, both views): drawn only while `row.live.subagents` (core `SessionViewState.subagents`, built by `SubagentLedger` from the `SubagentStart` / `SubagentStop` hooks, each subagent's `meta.json` and `Stop.background_tasks`) is not empty, so a session without subagents is exactly the card. Not verified on screen with a real Claude.

## Status to visual mapping

Source: `SessionIndicator` (`CUI/SessionDisplay.swift`), drawing `IndicatorView`/`ChaseDots` (`CUI/IndicatorView.swift`). Derivation order: stop failure > issue > ambiguous identity > a live session whose agent waits for the user's answer to an open-session request (`awaitingOpenApproval`, D-40: reads Needs approval) > live activity (a turn complete with pending provider work counts as Working) > an unviewed finish after the run ended > lifecycle.

| State | Label | Visual |
| --- | --- | --- |
| Working | Working | 8 dots chasing a rounded rectangle, 12 pt, text color, trail opacity 1 / 0.8 / 0.55 / 0.35, rest 0.16, 10 steps/s |
| waitingForApproval | Needs approval | 8 pt orange dot (a provider approval, or the session's agent waiting on an open-session request that is waiting or failed; cards, project dot and tabs agree because `SessionRowModel.indicator`, `attention(forProject:)` and tab eviction all pass `CatalogModel.awaitingOpenApproval`) |
| waitingForInput | Waiting for you | 8 pt orange dot |
| unknown | State unknown | hollow gray ring (1.5 pt) |
| failed / stopUnverified / problem | Failed / Stop not verified / Problem | 8 pt red dot |
| identityUnclear | Identity unclear | hollow orange ring |
| unviewedCompletion | Finished | 8 pt blue dot |
| ready / idle | Ready / Idle | none (Ready: a live run at its prompt, a seen finish or a Claude that just started or resumed) |
| stale | Stale | none; title dimmed |
| ended | no label | none |

Red, orange and blue dots differ by color only. The label text is shown in the detail header and accessibility label, not on the card. Animation gate: `indicatorsAnimate` (default false). Sidebar rows: window active and sidebar not collapsed (`SidebarView.indicatorsAnimate`); detail header: window active. No Reduce Motion code exists; the chase runs under Reduce Motion by user decision (6 Oct 2026). Viewed means the session is selected while the window is active.

## Detail pane (`CUI/DetailView.swift`)

- Panel: 10 pt radius, 1 pt hairline, 8 pt inset, terminal-colored fill over a sidebar-colored backdrop.

Narrow rows (`HeaderFlowPlan`): the title shortens first, then the chip gives up its branch, then the project name shortens (chip floor 56 pt); the pill and the group never shorten and stay in the row. The row stays 36 pt. Dev-only variant: "Synthetic terminal (development)". Not verified on screen: hover and pressed fills, the focus ring, the ⋯ menu, the chase inside the pill.
- Banners (`Banners`, `BannerRow`): ownership notice (orange), status message (secondary), dismissible error (red) and info (secondary).
- Deletion banner (`DeletionBanner` in `CUI/DeletionViews.swift`, mounted under `Banners`; shown in every build, also where Delete is hidden, because a deletion the runtime recovered at launch must stay visible and retryable): one row per unfinished deletion, "Deleting this session isn't finished. <what failed>. - Delete sheet (`DeleteConversationSheet`, 420 pt, attached to the main window like the rename sheet, opened by `model.deletions.confirmation`): title "Delete this session?", the session's title, the runtime's dry run in one paragraph (what is removed with the file count, size and Claude config folder; what is not removed; "It is running now, so Loom stops it first" when it has a live run), "Checking what Claude has kept for this session…" while the plan is made, the runtime's refusal in red when there is one, and a red note when a folder cannot be entered (the Delete button stays disabled then). ## Verifying UI safely

Details: [DEVELOPMENT.md](../DEVELOPMENT.md) (isolation and evidence rules). Commands live in `APP/DevelopmentEvidence.swift`; launch flags in `Sources/LoomLaunchOptions/LaunchOptions.swift`.

- Launch a separate app copy with `--evidence <dir> --data-root <isolated dir> --fake-providers <fixtures>`. Evidence mode never uses the default catalog; `--data-root` without `--evidence` is refused. Without `--fake-providers`, titles, request text and terminal content are redacted and `screenshot` writes nothing. Seed data with `loom-catalog-fixture seed <data-root> <N> [projects]` (refuses an existing catalog). `scripts/cp5-b-acceptance.sh` is the template for a UI pass.
- Send commands with `loom_send_command <dir> <command>` from `scripts/dev-paths.sh` (a per-directory distributed notification). UI commands: `select:`, `search:`, `view-mode:<activity|projects>`, `toggle-sidebar`, `sidebar-width:`, `resize:<w>x<h>`, `toggle-fullscreen`, `toggle-project:`, `start:<claude|codex>:<project|none>`, `resume:`, `stop:`, `answer:`, `delete:<id>`, `delete-confirm`, `delete-cancel`, `delete-retry:<id>`, `delete-key`, `screenshot-sheet:<label>` (the delete sheet's content view), `begin-rename:`, `rename-text:`, `rename-commit`, `open-settings[:section]`, `close-settings`, `screenshot-settings:<label>`, `usage-select:<period>`, `usage-refresh[:<label>]`.
- Outputs land in `<dir>`: `screenshot:<label>` writes `screenshot-<label>.png` (content) and `.window.png` (with title bar and traffic lights) from the app's own views, no screen-recording permission; `snapshot:<label>` writes `state-<label>.json` (sidebar width, material, running chase indicators, selected indicator, terminal/runtime state); `buttons:<label>` writes `buttons-<label>.json` (traffic-light hit tests and the 26 pt centerline sweep).
- Screenshots cannot show behind-window glass, animations, hover/focus, menus, sheets or tooltips (the evidence channel renders the Settings window itself: `screenshot-settings:<label>`); those need computer-use or the user.
- Never touch the user's installed Loom Dev app, its default catalog or `ui-preferences.json` under `~/Library/Application Support/Loom-Dev`, or `~/.claude` / `~/.codex`. The `.sh` acceptance scripts refuse to run while any Loom Dev instance is open; the Python runners only check their own package (see `scripts/README.md`). Packaging does a heavy release build; reuse an existing packaged app.
