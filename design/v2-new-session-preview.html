N1 · Draft session chosen · D-59

A new session starts as an empty chat with one question, not a form. You say what you want; everything else has a remembered default that you change in place. This is how T3 Code starts a thread, and Claude's desktop app is close to it.

  • One way in: ⌘N, the sidebar's compose button, "+" on a project, the palette, the menu bar and Home all open this draft, in the project you were last in. Home's start box is the same composer.
  • The project is in the question. Click its name to pick another.
  • The composer is the session's own: mode and model sit where they stay after the start, as last used in this project. One strip under it holds the branch.
  • Presets are one-click first messages; "Plan first" starts in plan mode. Save as preset appears once you have typed something.
  • Already open: the project's live sessions, so you can continue one instead of starting a copy.
  • Nothing runs before you send. An empty draft is invisible, and each project keeps at most one; once you type, a draft row appears in the sidebar. ⌘↵ starts the session and opens a fresh draft.
Underneath: today's launch path. The first send starts Claude with that message; the draft and its choices are Loom-only state until then. Defaults: your pick in the draft, then the last used in this project, then Loom's settings, then the CLI's own default.

N1 · Typing a ticket key

The draft reads what you type. A ticket key fills in what the old sheet asked for, and you correct only what is wrong.

  • Project: a key whose prefix belongs to a project moves the draft there and says why.
  • Ticket line: inside the composer, the ticket's title and whether it already has a session; when it has one, the line offers Open instead (today's open-session check).
  • Branch: stay on the current one, a new branch named from the ticket, or a new worktree. The choice is a small menu on the strip's chip, not a field.
  • Title comes from the ticket (or your first line) and can be renamed later.
Underneath: ticket prefixes and the duplicate check already exist in the catalog (D-40). Loom creates the branch or worktree in the session's folder right before the first send.

N1 · After the first send

Sending turns the draft into the session in place. Nothing jumps: the composer settles at the bottom and the work starts above it.

  • The question and the strip leave. Project and branch now live in the header, where every session shows them. Mode and model stay in the composer, because you may change them mid-session.
  • The session appears at the top of Active and of its project, with the working indicator; the draft row is gone.
  • The first marker records how it started: model, effort, mode and the new branch.
Underneath: one launch, one process, as today. A draft you leave without sending stays as a draft row until you clear it.

N2 · Quick launcher

A small floating box, like Spotlight, over whatever you are looking at. Type, press Return, and the session starts in the background while you stay where you were.

  • Fast for side tasks: start a question in another project without leaving the session you are watching.
  • Same defaults as N1: project and branch chips, mode, model, presets.
  • Cost: a second composer to build and keep in step with the main one; little room for long first messages, images or a ticket preview.

Against N1: quicker for "fire and forget", weaker for real tasks. It can come later as an extra on top of N1 (the same parts), so it need not be either-or.

Underneath: the same launch path; ⌘↵ opens the new session, ↵ leaves it running in the sidebar.

N3 · Inline in the sidebar

"+" on a project header opens a one-line field at the top of that project. Type the first message and press Return; the project's remembered defaults do the rest.

  • Lightest of the three: no new screen and no overlay; the session appears exactly where it will live.
  • Limits: the sidebar is narrow. No room for a long message, attachments, the branch choice or the ticket preview, so anything beyond the defaults needs N1 anyway.

Against N1: good for a quick question in a known project, too cramped for real work. Like N2, it could sit on top of N1 later.

Underneath: the "+" on project headers exists today (D-37); it would gain the inline field.
