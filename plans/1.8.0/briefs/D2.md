# D2: Codex's reader and deletion

**Goal.** Sphyrna reads a Codex session's rollout as it reads a Claude transcript:
- the last lines (Peek, Home);
- palette search;
- context and token usage (the Overview and the usage index);
- the files it edited (Changes' session scope);
- mentions.

Deleting a Codex session goes through the harness: `codex delete` plus the existing verification, in the persisted deletion
state machine. This is FEEDBACK-6 FB6-14 steps 3–4 and FB5-7's Codex token parser.

**Starts after** D1.

**Read.**
- P0's `SPIKE.md` §6 (the rollout's place and shapes) and §7 (`codex delete`).
- SPEC §5.1 (verified deletion, the seven steps), §8.2 (Overview, Changes' scopes), §6.4 (palette search's read limits).
- In `v2`, `Sources/LoomCore/`:
  - `ClaudeTranscriptReader.swift`, `ClaudeTranscriptFile.swift`, `ClaudeUsageIndex.swift`, `ClaudeUsageParser.swift`;
  - `TranscriptLineSplitter.swift`, `SessionUsage.swift`, `ProjectUsage.swift`;
  - `ConversationDeletion.swift`, `SessionCatalog+Deletions.swift`.
- Then `Sources/LoomCatalogUI/PaletteTranscriptSearch.swift`, `CatalogModel+Changes.swift`, `UsageCodexTokens.swift`.

**Write set.**
- A transcript reader protocol in `LoomCore` (`TranscriptReader.swift`) with `ClaudeTranscriptReader` conforming, and a new
  `CodexRolloutReader.swift`.
- `CodexUsageParser.swift`; the usage index's provider key.
- The deletion files above.
- The consumers in `LoomCatalogUI` only as far as they call the protocol.
- Tests (fixtures of a rollout, with no user data); SPEC §5.1 and §8.2's Codex lines.

**Approach.**
1. **The reader protocol:** last lines, a bounded search, usage, edited files and context, each with the same read bounds as
   Claude's (SPEC §6.4, §12.1). Claude's reader moves behind it with no behaviour change, and a test pins Claude's outputs
   before and after.
2. **`CodexRolloutReader`:** locates the rollout from the recorded session id and cwd per P0. It reads only the tail it needs,
   never the whole file on the main actor.
3. **Usage:** the index gets a provider key. Codex's tokens by model and type are counted from the rollout (FB5-7), with cost
   only where the pricing is known; otherwise tokens only, as today's Codex card says.
4. **Deletion:** a harness-owned step.
   - For Claude: today's allowlist.
   - For Codex: `codex delete <id>` run in a run scope, then verify that P0's listed paths are gone.
   - A failed or partial delete stays in the state machine and resumes after a crash, as today. The catalog row goes only
     after verification.
5. **Harnesses with no reader** (opencode, agy, pi): their surfaces say "Not read for <harness> yet" instead of empty data.

**Done when.**
- With a rollout fixture, Peek, palette search, Overview usage and Changes' session scope show Codex data.
- Deletion of a fake Codex session runs every step and verifies. A kill in the middle resumes on the next launch.
- Claude's outputs are unchanged (the pinning test).
- One real `codex delete` in the isolated home removes exactly P0's listed paths.

**Checks.** The transcript, usage, palette search and deletion suites (`grep -l "ClaudeTranscriptReader\|ConversationDeletion"
Tests/*/*.swift`), new `CodexRolloutReaderTests` and `CodexDeletionTests`; then `--tests`.
