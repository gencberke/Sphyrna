# F2: Changes' comments reach a terminal session

**Goal.** Comments written in Changes can be sent to the session they belong to while it runs in its terminal. Since D-100,
`Send to Claude` needs the Chat face (`changesSendAvailability` returns `.notChat`, `CatalogModel+Changes.swift:265`), so the
comments cannot leave Changes. This is FEATURES F11's gap.

**Starts after** F1 (it reuses the mailbox and the delivery).

**Read.**
- docs/FEATURES.md F11; SPEC §8.2 (Changes, comments); DESIGN §13.
- In `v2`: `Sources/LoomCatalogUI/CatalogModel+Changes.swift`, `ChangesState.swift`, `ChangesTab.swift`; F1's `SessionMailbox`
  and `MailboxDelivery`.
- For reference: Orca's "Annotate AI Diffs" (`grep -rln "annotat" ~/Documents/github/orca/src/renderer/src/components | head`).

**Write set.** `CatalogModel+Changes.swift`, `ChangesState.swift`, `ChangesTab.swift` (the send button and its states), a
`ChangesMessage.swift` that formats the comments, tests, and SPEC §8.2 with DESIGN §13's lines.

**Approach.**
1. **The message:** the comments become one message. Per file: its path, then each comment with its line number and the line's
   text, in the order of the file list. It is bounded by F1's 16 KiB; above that, the oldest comments are left out and the
   message says how many.
2. **The button:** "Send to <harness name>" (Send to Claude, Send to Codex) in Changes' footer, the default button, when the
   session is live and has at least one comment. `@user`'s click is the approval: there is no extra card, because the user is
   the sender.
3. **Delivery** is F1's: the mailbox, the pointer on the next Ready edge, and `inbox`. Changes shows "Sent · waiting for
   <title> to be ready", then "Delivered".
4. **After the send,** the comments stay until the user clears them, as today after Chat's send.

**Done when.** With fake providers, comments on two files are sent from Changes and arrive formatted after Ready. The button is
absent for a stopped session and with no comments. The Chat path still compiles but stays frozen.

**Checks.** The Changes suites (`grep -l "ChangesState\|changesSend" Tests/LoomCatalogUITests/*.swift`), new
`ChangesMessageTests`; then `--tests`.
