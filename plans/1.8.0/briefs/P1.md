# P1: the opencode, agy and pi spike

**Goal.** For each of `opencode` 2.1.4, `agy` 1.4.5 and `pi` 0.85.1, the versions installed on this Mac, find what Sphyrna
needs to:
- show it in the harness catalogue (C1);
- start it as a plain terminal session (E1–E3);
- possibly serve Remora with it (G1).

No product code changes.

**Needs from `@user` before it starts.**
- Their word on FEEDBACK-7 Q13.
- For each CLI that needs a login, an isolated profile they signed in to once. The agent proposes the profile folders under
  `~/.loom-dev/` and the environment variable each CLI reads, and asks; it never signs in itself.

**Read.**
- FEEDBACK-6 FB6-13, FEEDBACK-7 "Logic read for 1.8.0", and [P0.md](P0.md): the same questions, Codex's version.
- Orca, for comparison only: `~/Documents/github/orca/src/shared/agent-hook-listener-opencode-*.test.ts`,
  `agent-hook-listener-pi-compatible.test.ts`, `agent-hook-listener-antigravity.test.ts`, and the matching source under `src/main/`.
- T3 Code: `~/Documents/github/t3code/packages/provider-opencode/`, `packages/provider-pi/` (their `status.ts`, how they find the
  binary and read models).

**Write set.** `~/Library/Caches/loom-v2/evidence/r9/p1/` only (`SPIKE.md`, scripts, captured payloads with secrets removed).

**Questions, per CLI.**
1. **Identity:** the binary name, the usual install paths, how to read its version cheaply (`--version`, no network), the
   install command and the docs URL to show the user, and the sign-in command.
2. **Profile:** the folder of its config, auth and sessions, and the environment variable that moves it (for isolation).
3. **Launch:** a new interactive session in a folder with a first message, a model, an effort or reasoning level, and a
   permission mode. List the CLI's modes and which of them maps to Sphyrna's ask before edits, accept edits, plan and auto. Which
   mode is "full access", which Sphyrna never lets an agent choose.
4. **Models:** where the list of models comes from (a command, a file, an API that needs no model call) and the effort levels
   per model.
5. **Status:** hooks, plugins or events that report a turn's start and end, a permission request and an idle state, without
   writing the user's own config: flags, an environment variable or a plugin folder that Sphyrna owns. Otherwise the OSC
   titles it sets.
6. **Identity of a session:** how its id is known at start, and how to resume it.
7. **Storage:** where its transcripts live; whether it has a delete command; what removing a session would take.
8. **Processes:** does it start a server or a daemon that outlives the TUI?
9. **A one-shot run with no tools** (for G1): the command, and proof that no tool can run.

**Done when.** `SPIKE.md` has one section per CLI with all nine answers and their evidence, a verdict per CLI for E1–E3
("startable as planned", "startable without live status", or "show only"), a verdict for G1, and the real turns spent (at most
5 short turns per CLI).

**Checks.** Real runs only in `/private/tmp/loom-real/p1-*` with the isolated profiles. At the end, list the leftover processes
for each CLI: none of yours may remain.
