# F1: `send` between sessions

**Goal.** An agent in one Sphyrna session can send a message to another session. `@user` approves each send on a card in the
sender's session. The message waits in the target's mailbox. When the target is Ready, Sphyrna types one short pointer line
into its terminal; the target reads the message with `inbox`. This is FEEDBACK-6 FB6-16 part 2 with FEEDBACK-7 Q8 (Orca's
delivery).

**Starts after** D1 (so Claude and Codex can both be targets).

**Approach.**
1. **The CLI.** `"$SPHYRNA_CLI" send <session id> --message-file <path>` (UTF-8, at most 16 KiB) asks over the control socket.
   It returns `pending`, then `sent`, `denied` or `failed`, as `open` does. `"$SPHYRNA_CLI" inbox` prints this session's unread
   messages and marks them read; `inbox --peek` leaves them unread.
2. **Approval.** The sender's session shows the request card: "Send to <target title>", with the sender, the target, its
   harness and the full text in a bounded scroll area. Deny is secondary and Send is the default; neither takes Return from
   the terminal. Rate limit: one pending send per session, at most 10 an hour. Nothing is sent without `@user`'s click.
3. **The mailbox.** Approved messages are stored per target (id, sender, time, text, read) under the data root with 0600 files.
   They are deleted with the target session (add to the deletion state machine's Sphyrna step).
4. **Delivery:**
   - when the target is Ready (its status, live, not Working or Waiting for you), type one line into its terminal, in the
     target harness's way of submitting a prompt: "Sphyrna: 1 message from <sender title>. Run `$SPHYRNA_CLI inbox` to read it.";
   - if the target is not Ready, wait for its next Ready edge; never type into a running turn or a permission prompt;
   - the target's card shows an unread badge until `inbox` runs;
   - a stopped target gets the pointer after Resume.
   - P0 may confirm that `codex queue` delivers to a running Codex session more safely. If it does, use it for Codex targets
     and record that in the report.
5. **Contracts:**
   - `crossSessionInbound: refuse` stays (Claude's own channel);
   - no transcript content crosses (only the text the agent wrote and `@user` approved);
   - the pointer adds one line to the target's context, which SPEC §12.2 must name as an allowed addition.

**Done when.**
- Fake providers: a send is approved, waits while the target works, is typed on Ready, and `inbox` reads it once.
- Deny leaves nothing. A deleted target's mailbox is gone.
- The skill description passes its guard.
- Real (Q13): Claude sends to Codex and Codex to Claude, each approved, each read. Count the turns.

**Checks.** `PluginContractTests`, `OpenSession*Tests`, the request card tests, new `SessionMailboxTests`,
`MailboxDeliveryTests` (Ready edge, never in a turn, rate limit) and `SendCommandTests`; then `--tests`.
