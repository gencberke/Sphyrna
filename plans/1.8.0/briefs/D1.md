# D1: Codex sessions

**Goal.** A Codex session behaves in Sphyrna as a Claude session does:
- it starts from a draft with the first message, model, effort and mode, in the stay, branch or worktree the draft chose;
- it runs in its owned terminal inside a run host;
- it shows honest status, stops verifiably and resumes;
- the production build lets it start.

This is FEEDBACK-6 FB6-14 step 2 and FEEDBACK-7 Q10.

**Approach.**
1. **The launch profile:**
   - the command from P0;
   - the first message;
   - `-m`, the effort, and the mode through P0's `-a` / `-s` mapping (full access only from the user's own choice, as for
     Claude);
   - `--no-daemon`, if P0 found the daemon escapes the run host;
   - the working folder from the draft's workspace setup, shared with Claude's.
2. **Status:**
   - P0's session-scoped hook route feeds `loom-hook` with Codex's events, mapped to the same states as Claude's: Working
     from UserPromptSubmit to Stop, Waiting for you on PermissionRequest, and background work as N background;
   - if P0 found no session-scoped route, the terminal title is the source (Working or idle), and Waiting for you is shown only
     if the title tells it;
   - never write `~/.codex` (Q10).
3. **Identity:** record Codex's session id in the catalog as soon as P0's source gives it; `resume` uses it with the same
   model, effort and mode. Copy Resume Command gives `codex resume <id>`.
4. **Ownership:** Stop and Quit verify the run scope empty, as for Claude. Add a test that a stopped Codex run leaves no
   process (fake provider) and a gate item for the real one.
5. **The production gate** opens for Codex: startable in the capability table. Home, menus and the palette offer New Codex
   Session from the catalogue (C2).
6. **The copy sweep:** the header, menus, notifications and banners use the harness's name or a neutral word. List each string
   changed.
