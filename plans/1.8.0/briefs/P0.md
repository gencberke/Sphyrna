# P0: the Codex spike

**Goal.** Answer, against the installed `codex` 0.164.0, the questions that decide how Codex sessions start, report status,
stop, resume, are read and are deleted in Sphyrna (D1, D2, F1, G1). This slice changes no product code: it writes a report and,
where useful, small scripts.

**Needs from `@user` before it starts.** Their word on FEEDBACK-7 Q13 (short real Codex turns). An isolated Codex home that
they have signed in to once:
```bash
CODEX_HOME=~/.loom-dev/codex-home codex login
```
The agent never runs `codex login` and never reads or copies the user's `~/.codex/auth.json`.

**Read.**
- FEEDBACK-6 FB6-14 ("What the code says" and "Proposals"), FEEDBACK-7 "Logic read for 1.8.0".
- In `v2`: `Sources/LoomCore/CodexHarness.swift`, `CodexAppServer*.swift`, `HarnessProbeCodex.swift`, `ProviderLaunchProfile.swift`,
  `ProviderResume.swift`, `Harness.swift`, `HarnessCapabilities.swift`, and SPEC §2–§4 (ownership, launch, status).
- Orca, for comparison only: `~/Documents/github/orca/src/main/codex/*hook*.ts`, `codex-hook-definition.ts`,
  `config-toml-trust.ts`.

**Write set.** `~/Library/Caches/loom-v2/evidence/r9/p0/` only (the report `SPIKE.md`, scripts, captured payloads with
secrets removed). Nothing in the repository.

**Questions to answer.** Each with the exact command used, what happened, and the evidence file.
1. **Launch:** the interactive command for a new session in a given folder with a first message, a model (`-m`), an effort
   (`-c model_reasoning_effort=…`), and each mode Sphyrna offers (ask before edits, accept edits, plan if any, auto). Map each to
   `-a` and `-s`. Which effort levels each model accepts, and where the CLI says so (the model list from `codex app-server` or
   `codex debug`?).
2. **The daemon:** does the TUI start or attach to a shared app-server daemon by default? With `--no-daemon`, does every process
   stay a child of the TUI, so a run host's coalition holds them all? What is left running after the TUI exits, in each case?
3. **Hooks without touching `~/.codex`:**
   - can a session get hook events from flags or files that Sphyrna owns: `-c 'hooks…'` inline, a `--profile`, a hooks file
     named by an environment variable, a `CODEX_HOME` overlay that symlinks the user's auth and config?
   - which events fire (SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, SubagentStop, Stop), and
     their payloads: the session id, cwd, transcript path, tool names;
   - does hook trust block them, and does `--dangerously-bypass-hook-trust` apply only to that run?
4. **The terminal title:** the OSC titles Codex sets while working, waiting and idle, usable as a fallback status.
5. **Identity:** how the session id is known at start (a hook payload, a flag that sets it, or the rollout file's name), and
   how `codex resume <id>` continues it with the same model, effort and mode.
6. **The rollout:** the folder and name pattern of a session's rollout file under the home. The first-line and per-turn record
   shapes needed for the last lines, tokens by model and type, context and edited files. Their size after a few turns.
7. **`codex delete <id>`:** what it removes on disk (list every path before and after). Does it refuse a running session?
8. **`codex queue --thread <id> --message …`:** does it reach a running TUI session, and when does the message show?
9. **A one-shot run with no tools** for Remora (G1): `codex exec` with a read-only sandbox and no approvals, streamed output, a
   system or instructions file, no MCP, no web search. Does any tool still run? Measure one call's time and tokens.
10. **Usage:** confirm that the existing app-server probe still answers limits on 0.164, with no model call.

**Done when.** `SPIKE.md` answers all ten questions, each with its evidence, a verdict for D1, D2, F1 and G1 ("works as
planned", "works with this change", or "blocked: …"), and the real turns spent (keep it under 15 short turns on the cheapest
model).

**Checks.** None in the repository. Every real run happens in `/private/tmp/loom-real/p0-*` with `CODEX_HOME` set to the
isolated home. At the end, list the leftover processes (`pgrep -fl codex`): none of yours may remain.
