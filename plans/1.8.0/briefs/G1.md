# G1: Remora on any connected harness

**Cut from 1.8.0 by D-122:** no second harness has a verified no-tools route; Remora stays on Claude. This brief stays for when one does.

**29Oct scope: supported Claude/Codex/opencode/agy routes only; Pi is deferred (D-113). Every offered backend still needs a verified no-tools path; the overnight budget does not relax that contract.**

**Goal.** Remora's brief and answers can run on any connected harness's model that passes a verified no-tools run, not only
on `claude -p`. Remora's model setting uses B4's panel, filtered to those models. This is FEEDBACK-6 FB6-22 part 2, under
D-103's rule: "a harness serves Remora only with a verified no-tools run".

**Approach.**
1. **`RemoraBackend`:** run a prompt pack (system part and stdin part) with a deadline and a budget, and stream the text. Each
   backend says whether it is verified no-tools.
2. **Claude:** today's call, its caching environment (D-84–D-86) and every guard unchanged. A test pins the argv and environment
   before and after.
3. **Codex:** P0's one-shot command with a read-only sandbox, no approvals, no MCP and no web search, in an empty temporary
   folder, with the isolated environment rules of today's Remora call. It streams output into the same reader. There is no
   prompt cache setting: note the cost difference in Remora's usage line.
4. **Verification:**
   - a backend is offered only if its descriptor marks no-tools verified (from the spikes) **and** a startup check of the CLI's
     version is within the tested range;
   - otherwise its models are dimmed in the panel with "Not verified for Remora".
5. **Settings → Remora:** the model row opens B4's panel in Remora mode (the rail shows only verified harnesses), then the effort
   step.
6. **The schedule, the budgets and the memory rules are unchanged.** The day's brief runs on the chosen backend.
