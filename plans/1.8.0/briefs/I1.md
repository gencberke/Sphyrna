# I1: the names, and a session's title at start

**Goal.** Two leftovers:
1. **The names.** The installed app becomes `/Applications/Sphyrna.app` with the executable `Sphyrna`, after a migration
   check that keeps the user's permissions, login item, Dock place and data. The bundle id `local.loom.desktop` and the data
   folder stay (D-83, D-103 Q4, FEEDBACK-7 Q12). The last user-visible "Loom" strings go.
2. **The title.** A session that starts with a Sphyrna title passes it to the CLI as the session's name, so the CLI's own list
   and Sphyrna's agree (FEEDBACK-6 FB6-16 part 1, not built in 1.7.1).

**Starts after** D1 (both launch profiles exist). Part 1 also needs `@user`'s word on Q12.

**Read.**
- FEEDBACK-6 FB6-17 and FB6-16; DEVELOPMENT §6 (packaging) and §10 (the clean loom tree, `promote.sh`, `build.sh`).
- In `v2`:
  - `scripts/package-dev-app.sh`, `scripts/release/build-loom.sh`, `scripts/release/promote.sh`, `scripts/release/allowlist.sh`;
  - `Package.swift` and `Package.release.swift` (product names);
  - the Info.plist sources;
  - `Sources/loom-run-host/` (its bundle's display name);
  - `Sources/LoomCore/ProviderLaunchProfile.swift` and `CodexLaunchProfile.swift` (D1).
- `scripts/check-user-wording.sh` and its allow file.

**Write set.**
- **Part 1:** the scripts above, the Info.plist sources, `Package.swift` and `Package.release.swift` (product names only; you are
  their only owner in this round), the wording guard, `DEVELOPMENT.md` §6 and §10, and a migration note in
  `scripts/release/README.release.md`.
- **Part 2:** the launch profiles, their tests, SPEC §3.

**Approach, part 1.**
1. **The migration check first** (no code change yet). In a copy, find what is keyed to the app's path or name and what to the
   bundle id:
   - TCC grants (keyed to the bundle id and the signing requirement, so expected to survive);
   - the login item (`SMAppService.mainApp`);
   - the Dock tile;
   - LaunchServices;
   - notification settings;
   - `NSUserDefaults`;
   - the run host's `LoomRunHost.app` inside the bundle;
   - any absolute path in the user's data (the catalog, preferences, the hook settings files Sphyrna writes for sessions).

   Write the findings to `evidence/r9/i1/MIGRATION.md`. If anything would be lost, stop and report: `@user` decides.
2. **Rename the products** so the build makes `Sphyrna.app` with the executable `Sphyrna`; the dev flavour becomes
   `Sphyrna Dev.app`. Keep module and target names (`LoomCore`, …) and the `loom` command name for the CLI helper unless the
   check says otherwise.
3. **The install step** in `build.sh` / `README.release.md`: quit the old app, move `/Applications/Loom.app` to the Trash only
   after the new app is in place, and re-register the login item if it was on.
4. The run host's display name is "Sphyrna Run Host" (FB6-12), and Activity Monitor shows it.
5. **The wording guard** fails on "Loom" in any user-visible literal outside the allow list. Remove the strings it finds.

**Approach, part 2.** When a session starts with a title (a draft the user named, or `open --title`), pass it with Claude's
`--name` and Codex's equivalent from P0 (if none, skip Codex and say so). A later rename stays Sphyrna's only.

**Done when.**
- A dev package builds as `Sphyrna Dev.app`, and `MIGRATION.md` covers every item of step 1 with its verdict.
- The wording guard passes with no new allows.
- A launch-argument test shows `--name "<title>"` for a titled Claude session.
- Nothing is installed into `/Applications`: that is the gate's, on `@user`'s word.

**Checks.** `scripts/check.sh --release-tree` (needed to prove the release flavour builds under the new name; you may run it
once, after `pmset -g therm` reads nominal), `LaunchContractTests`, `ProviderProfileTests`; then `--tests`.
