# A1: reorder projects with a live drag

**Goal.** In the sidebar's Projects view, the user holds a project head and drags it. The other projects slide apart to show
where it will land, and the new order is kept on release. The fix for FEEDBACK-7 FB7-3: the 1.7.x drag rides the pasteboard
and does not reorder in the installed app.

**Approach.**
1. **Replace the head's `.onDrag`** (pasteboard) with an in-list drag gesture. It starts past a few points of movement, so a
   click still opens the project page and a right-click still opens the menu.
2. **While dragging:**
   - the head (with its block collapsed visually, or the head alone) follows the pointer, lifted (elevation 2, a little
     opacity);
   - the other blocks slide by the dragged block's height to open a gap where it would land (150 ms; none under Reduce Motion);
   - the gap index comes from the pointer's position against the blocks' mid-lines, read from geometry the list already
     measures; no per-frame layout of the whole list;
   - near the scroll view's top or bottom edge, the list scrolls itself.
3. **Ending the drag:**
   - on release, call `moveProject(id, to:)` once;
   - Escape, losing the window's key status, or a release outside the list cancels the drag with no change;
   - a drop on its own place changes nothing.
4. **Remove the pasteboard path for projects:** `ProjectDrag`'s item provider, `ProjectBlockDrop`, and the
   `UTType(exportedAs: "local.loom.desktop.project-reference")`, which logs a fault on every launch. Keep `DragActivity` only as
   far as the session drag needs it.
5. **Accessibility:** Move Up and Move Down stay in the menus. The head gets accessibility actions "Move Up" and "Move Down".
6. **Logging:** the drag's start, its target gap and its end (moved, cancelled, unchanged) at notice level, with the project id's
   first 8 digits only.
7. **Evidence:** a command that performs the same reorder through the gesture's model path (not just `move-project-to:`), so the
   gate can check it.

**Done when.**
- Dragging any project above or below any other reorders it, and the order survives a relaunch.
- The other blocks move apart during the drag. Cancel paths leave the order as it was.
- Clicks and the context menu on the head still work.
- No `local.loom.desktop.project-reference` type remains, and the launch log has no type-declaration fault for it.
- The session drag (to tabs, the composer, a terminal) is unchanged.
