# F5 — launch and sidebar hot paths

Stage [F](../STAGE-F.md) · wave 2 · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice). Depends on F3 (`AppDelegate.swift`) and F4 (`ProcessSupervisor`, `SessionCatalog` files).

## Goal

Measure, then remove, the main costs between launch and a usable sidebar and on every list refresh — without changing what the user sees or any ownership guarantee.

## Context (verified in planning)

- `AppDelegate.swift:98-102`: `startupTask` awaits `startRuntime` and only then `model.start()`, which needs only the catalog and the hub (both exist earlier, `:56-71`). `startRuntime` loads every catalog row into the supervisor (`ProcessSupervisor.restoreCatalogSessions`, F8), snapshots the whole process table on the main actor to find Loom's own identity (`AppDelegate.swift:319`; `ProcessTable.record(pid:)` exists), writes run files, starts runtime and lifecycle. `model.start()` subscribes after snapshotting `catalogRevision`, so ordering is safe.
- `SessionCatalog(url:)` is opened on the main thread (`AppDelegate.swift:63`) including `PRAGMA quick_check` (`SessionCatalog.swift:~1033`), O(DB size).
- `CatalogModel.row(for:)` calls `GitBranch.read` (synchronous file reads walking up the path) for every row on every reload (`CatalogModel.swift:377-380`), `setWindowActive` re-reads every known path (`:467-472`), `apply` re-reads at turn completion (`:684-690`); `branches` is never pruned; `reload` sets `now = Date()` unconditionally (`:352`). Every realized card reads `model.now`, `model.branches`, `model.projects`, `model.selectedSessionID` (`SidebarView.swift:312-333`).
- `scheduleRefresh` (`CatalogModel.swift:731-748`) reloads all loaded rows of all visible lists on run/lifecycle frames.
- No signposts exist (`os_signpost`/`OSSignposter` absent).

## Scope

Write: `Sources/loom-app/AppDelegate.swift` (startup order and the self-identity lookup only), `Sources/LoomCatalogUI/CatalogModel.swift`, `Sources/LoomCatalogUI/GitBranch.swift`, new `Sources/LoomCatalogUI/BranchCache.swift`, a small `Sources/LoomCore/LoomSignposts.swift` (an `OSSignposter` with subsystem `local.loom.desktop`, category "PointsOfInterest"), the `SessionCatalog` open path (only if the measurement justifies it), tests in `Tests/LoomCatalogUITests` and `Tests/LoomCoreTests/CatalogScaleTests.swift`, `docs/ARCHITECTURE.md` §3 and §9. Out of scope: row-level refresh rewrite of `scheduleRefresh` (only if trivially safe; otherwise list it as a follow-up), lazy supervisor sessions (dropped), visual changes.

## Steps

1. Signposts: intervals for process start → catalog open → window shown → runtime started → first page loaded; and conversation selection → terminal view attached. Plus an evidence-free way to read them (`log show --signpost` / `xctrace` notes in your report) and a timing field in `CatalogModelStatistics` if useful for tests.
2. Baseline: build a release package in your worktree (`scripts/package-dev-app.sh` into `~/Library/Application Support/Loom-Dev/packages/run1-F5-before`) and record launch → first list paint at 0, 1,000 and 10,000 rows (seed with `loom-catalog-fixture seed <data-root> <N>` in an evidence run with `--data-root`), 5 runs each, median and spread. Record `quick_check` time at 10k separately (a small timing test or a probe).
3. Changes: `model.start()` concurrently with `startRuntime` (Quit still waits for both); `ProcessTable.record(pid: getpid())` for the self identity; `BranchCache` actor (background reads, keyed by path, refreshed at turn completion and window activation, results published to the model only when changed); no unconditional writes of `now`, `branches`, `projects`; catalog open off the main thread only if step 2 shows it matters, never letting a write happen before `quick_check` passes.
4. After: the same measurement on `run1-F5-after`; report before/after medians.

## Done when

- First list paint no longer waits for the runtime start (signpost evidence); no `GitBranch.read` on the main actor during reloads (test with an injectable reader that asserts it is off-main, or a counter); equal-value refreshes do not write observed properties (test).
- Launch numbers before/after recorded in `plans/experiments/run1-F5-launch.json` (value-free: counts, medians, spreads, commands).
- Existing `CatalogModelTests`, `ConversationControllerTests`, `SidebarStatusTests`, `CatalogScaleTests` green.

## Checks

`swift build`; the suites above; the two packages and the measurement (this slice may run window measurements; take the build slot for the package builds and for the measurement runs so no build heats the Mac meanwhile).
