No release blockers; these are the should-fix and minor items. ## Items

1. **Codex can still be resumed in production (F-A1 gap).** `CatalogModel.canResume` and `ConversationController.resume` do not check `startableProviders`; a Codex record in the production catalog (0.1.0 offered "New Codex Conversation") can be resumed through Resume, "Reactivate and Resume", Cmd+R or the menus, which launches `codex app-server` in `local.loom.desktop` (D-14, D-28). Fix: `canResume` requires `startableProviders.contains(provider)`; `ConversationController.resume` refuses the same way as `start`; the record view says why resume is not offered ("Codex conversations can't be resumed in this version." in DESIGN §6 voice). Tests in both identities (like F1's start tests). Update `docs/ARCHITECTURE.md` §8 and UI-MAP if they say resume is allowed for any provider.
2. **"Preparing Claude…" resizes the visible terminal.** The notice is a row in `Banners` above the tab strip and `DetailContent`, so starting a new conversation from a running one shrinks the visible terminal by a row and sends a PTY resize to the conversation being watched (and back again later). DESIGN §6: only opacity above the terminal. Fix: show the notice where it takes no layout space above the terminal — the fixed-height detail header row (where "Starting — complete any prompts…" lives) or a non-layout overlay. Also check: for Claude, the notice must clear when the launch returns or fails (`endStart`), and `cardCreated` is only called on the Codex path today — make the Claude path consistent. Regression test: the terminal container's height does not change while the notice shows (model-level: the notice is not part of the banner stack, or a layout test).
3. **Usage work while hidden, and on non-edge activity calls.** `UsageModel` refreshes on every finished turn even when the window is hidden; `AppDelegate` calls `windowActivityChanged(active)` on every occlusion/key/active notification, not only on a change; the launch refresh can race the first page and then rerun. Fix: while the window is inactive or hidden, a finished turn only marks usage stale; the next activation refreshes (skipping the cooldown when stale); drive activation from the change edge (`CatalogModel.setWindowActive` transition or a stored last value), and run the launch refresh once after the first page (no double pass). Tests with the fake index: hidden turn completions → zero refreshes until activation; repeated identical activity notifications → one refresh.
4. **Usage view flashes "No Claude usage yet".** `hasHistory` is written false, then true after an await, which swaps the report for the empty notice and resets the scroll. Fix: compute locally and assign once. Test.
5. **Chip and tab accessibility.** The chip's accessibility label omits the cost (DESIGN §2 item 5 says it carries the full figures): include it. In the tab strip, the selected tab's combined element contains the close button; VoiceOver activation may close instead of select: hide the close button from accessibility (the "Close Tab" action exists), add an activation action that selects the tab. Unit-check the labels where the code allows.
6. **Chip state edges.** "Today" goes stale after midnight until the next refresh: refresh usage on the day change while active (the U5 minute tick already sees midnight) — one call, no new timer. Every launch shows "Indexing…" with first-time copy because the report is nil at start: show the first-scan state only when the index has never completed a scan (persisted index state, e.g. the index database already has rows), otherwise keep the chip hidden or the last value until the first refresh ends. A persistent scan failure must not flip hidden → "Indexing…" → hidden on each activation: keep a stable failed state (chip hidden, Settings shows the failure).
7. **Formatter churn.** `UsageText.format` creates a `DateFormatter` per call; `DayGrouping.title` creates one per day heading (now every minute while active); `KeyboardNavigation.refresh` writes on every key-window change and re-renders every chrome button. Fix: cached formatters (per time zone/locale where needed); write the keyboard-navigation flag only on change.
8. **Return after a keyboard tab switch** (only if I3 did not already settle it): Resume / "Reactivate and Resume" is the default action; cycling tabs with Ctrl+Tab onto a stopped record and pressing Return launches Claude. If I3 kept `.defaultAction` on Resume, make Resume require an explicit click or Cmd+R (drop the default action), with a test or evidence.
