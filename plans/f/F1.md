# F1 — build identity and Codex hidden in production

Stage [F](../STAGE-F.md) · wave 1 · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice).

## Goal

One Swift owner of "is this the production app" and of the identity-derived names, and no Codex entry point in the production app (`local.loom.desktop`). Codex code stays compiled and paused (D-14, D-28); development builds (`local.loom.desktop.dev`) are unchanged.

## Context (verified in planning)

- Duplicated identity checks: `Sources/loom-app/AppDelegate.swift:113` (`==`), `:234` and `:402` (`!=`); `LaunchEnvironment.origin` receives the bundle id (`:430`); the command-channel prefix is hard-coded at `Sources/LoomLaunchOptions/LaunchOptions.swift:53`.
- Codex entry points: File menu "New Codex Conversation" Shift+Cmd+N (`AppDelegate.swift:637-640`), `newCodexFromMenu` (`:452-454`), menu validation (`:468-469`); `NewConversationAction.all` (`Sources/LoomCatalogUI/SidebarView.swift:384-391`) feeds the footer `+` menu (`:118`), the project "…" menu (`:259`) and the project context menu (`:274`); empty-state button (`Sources/LoomCatalogUI/DetailView.swift:181-182`). Evidence-only: `--codex-home` (`AppDelegate.swift:434-437`), `start:codex` (`DevelopmentEvidence.swift:196-206`).
- `Tests/LoomCatalogUITests/SidebarStatusTests.swift:57-62` asserts `NewConversationAction.all` holds both providers.
- Existing Codex rows still display (`SessionDisplay.swift:129`) — keep that (history stays visible).

## Scope

Write: new `Sources/LoomLaunchOptions/BuildIdentity.swift`; `LaunchOptions.swift` (channel prefix from the identity); `AppDelegate.swift` only at the sites above; `SidebarView.swift` (`NewConversationAction` filtering by the model's startable providers); `DetailView.swift` empty-state buttons; `CatalogModel.swift` (`init` parameter `startableProviders`, default all, and a read-only property); `ConversationController.swift` (`start` guard); tests in `Tests/LoomLaunchOptionsTests`, `Tests/LoomCatalogUITests` (`SidebarStatusTests` update, a `CatalogModelTests` or new small suite case). Out of scope: Codex code itself, evidence separation (F3), any visual change.

## Design

`BuildIdentity` (pure, `Sendable`): from a bundle identifier → `isProduction`, `dataDirectoryName` ("Loom" / "Loom-Dev"), `socketDirectoryName` (".loom" / ".loom-dev"), `commandChannelPrefix`, `startableProviders` (`[.claude]` in production, `[.claude, .codex]` otherwise — use a provider representation available to `LoomLaunchOptions` without new dependencies, e.g. raw strings mapped in `loom-app`, since `LoomLaunchOptions` has no dependencies). `AppDelegate` reads it once. Keep every current path and name byte-identical.

## Done when

- Production identity: menus, context menus, the `+` menu and the empty state list only Claude; Shift+Cmd+N does nothing visible (item absent); `ConversationController.start(.codex, …)` refuses with no side effect. Development identity: identical to today.
- Data root, socket dirs and channel names are unchanged for both identities (tests pin the strings).
- Unit tests cover both identities; the updated `SidebarStatusTests` and a new model test fail on today's code where the behavior is new.

## Checks

`swift build`; `swift test --filter LoomLaunchOptionsTests`; `--filter CatalogModelTests` and `--filter SidebarStatusTests` (window tests allowed in this run); `git diff --check`. Show the new test failing before the change (stash nothing: write the test first, run it, then implement).
