# F3 — evidence code only in development builds

Stage [F](../STAGE-F.md) · wave 2 · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice). Depends on F0, F1, F2 (all touch `AppDelegate.swift`, `scripts/check.sh`).

## Goal

About 880 of `loom-app`'s ~1,660 lines are evidence tooling that ships in the production binary, gated by `--evidence`. After this slice the release flavor contains none of it, dev packages keep every evidence capability, and the release flavor is compiled by `check.sh --full` so it never rots.

## Scope

Write: `Package.swift` (`loom-app` gets `swiftSettings: [.define("LOOM_EVIDENCE")]`), `Sources/loom-app/**` (new `Evidence/` directory holding `DevelopmentEvidence.swift`, `EvidenceResourcePool.swift`, the evidence `extension AppDelegate`, and new evidence-command files; a `DevelopmentSeams.swift` with the few call seams and no-op stubs under `#if !LOOM_EVIDENCE`), `scripts/release/promote.sh` (exclude `Sources/loom-app/Evidence`, strip the dev-only define in the drift normalizer, extend the dev-only path check), `scripts/check.sh` (`--full` adds the staged release-tree build: export the promote allowlist from `HEAD` into a temp dir outside `~/Documents` with `Package.release.swift` as `Package.swift`, `swift build -c release`; share the allowlist between promote and check, e.g. a sourced `scripts/release/allowlist.sh`), `DEVELOPMENT.md` §5 and §10, `docs/ARCHITECTURE.md` §7. Out of scope: library targets, behavior of a dev build.
