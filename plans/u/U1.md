# U1 — UsageModel and the Settings page

Stage [U](../STAGE-U.md) · wave 3 · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice). Depends on U0 (index), I1 (tokens), F3 (evidence file layout), UD (accepted design: the planner-reviewer names the chosen variants in the wave Brief).

## Goal

A real, dark Settings window with General, Usage and About, and one observable usage model that both Settings and the footer chip read. Usage refreshes only on events that already happen.

## Context ([U integration scan §1, §4, §5](../experiments/run1-planning-scans/U-integration.md))

- Today: `AppDelegate.showSettings` (`Sources/loom-app/AppDelegate.swift:~604-616`) builds a lazy 360×150 `NSWindow` with `NSHostingController(SettingsView(model:))`; Cmd+, at `:~622`; gear calls `model.onShowSettings?()` (wired `:~80`). `SettingsView.swift` is a 25-line font picker (`setTerminalFontSize`, `CatalogModel.swift:~487-491`) and a red error text. The main window forces `darkAqua` (`:~174`); Settings does not.
- Refresh triggers: `CatalogModel.apply` sees `.status(turnComplete)` (`CatalogModel.swift:~687-691`) from the Claude Stop hook; window activation `setWindowActive(true)` (`:~467-475`); Settings open; launch after first paint. The hook payload carries `transcript_path` (`ClaudeHook.swift:~365,395`) but it is not forwarded; forwarding it to tail one file is optional (do it only if small and safe).
- Config dir for the index: `ClaudeProfileLayout` (U0) with the toolchain's `profileDirectory` (evidence `--claude-config` at `AppDelegate.swift:~433`; fake providers use `<data-root>/claude-config`, `:~423-425`) and the resolved environment. Production must not resolve the terminal environment just for usage (that spawns a login shell): use the toolchain environment once it exists, else `~/.claude` only if `CLAUDE_CONFIG_DIR` is absent from Loom's own environment; document the rule.
- Evidence: `saveScreenshot` renders only the main window; add `open-settings[:section]`, `close-settings`, `screenshot-settings:<label>` (render the settings window's content view with the existing PNG helper), `usage-refresh` (ack after completion), and snapshot fields `settings{visible, appearance, section, contentSize}`, `usage{state, asOf, totals}`. Put new commands in a new file under `Sources/loom-app/Evidence/` with one dispatch line (F3 layout).

## Scope

Write: new `Sources/loom-app/SettingsWindowController.swift`; new `Sources/LoomCatalogUI/UsageModel.swift` (`@MainActor @Observable`: snapshot, state idle/indexing/ready/failed, selected period, `refresh(reason:)` debounced ~2 s after turn completion, no timers); `SettingsView.swift` rewrite (sections per the accepted UD design; tokens from `LoomTheme` only); `AppDelegate.swift` (showSettings → controller, usage model creation and wiring — one-line hooks); `CatalogModel.swift` (one optional `usage` reference and the turn-complete/activation hooks — one-line calls); new evidence file; tests (`UsageModelTests` with a fake index; settings section routing). Out of scope: footer (U2), tabs, price values (U0).

## Done when

- Cmd+, and the gear open one reused dark window (~680×520, resizable within sane limits); `onShowSettings` takes an optional section; font size applies live as before (`ProductPreferencesTests` green).
- Usage section renders the UD design from a `UsageSnapshot`; periods switch without re-reading files; "Updated …", "Prices as of …", and the estimate label present; indexing and empty states.
- No timers; refresh is debounced and coalesced; a refresh with no file growth reads no content (U0 evidence); index work never runs on the main actor (test or signpost).
