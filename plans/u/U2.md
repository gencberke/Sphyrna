# U2 — sidebar footer bar

Stage [U](../STAGE-U.md) · wave 3 (after U1) · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice). Depends on U1 (`UsageModel`), I1, UD.

## Goal

Today's bottom `+` menu and gear become one compact footer bar inside the sidebar that also shows compact Claude usage (D-32).

## Context

- `SidebarFooter` (`Sources/LoomCatalogUI/SidebarView.swift:~112-141`): 38 pt HStack, `plus` Menu (`NewConversationButtons(model:projectID: model.contextProjectID)`, Divider, "Add Project…") left, `gearshape` Button right (`model.onShowSettings?()`), `ChromeButtonStyle` 28×26. A collapsed sidebar hides it (Cmd+N, Cmd+, still work).
- Width budget at the 220 pt minimum: ~130 pt for the chip after paddings and two buttons → truncate, full text in tooltip and accessibility label.
- Design: the chip variant chosen from UD (named in the wave Brief).

## Scope

Write: new `Sources/LoomCatalogUI/SidebarFooter.swift` (moved and rebuilt), the mount line in `SidebarView.swift`, tests in `SidebarStatusTests` or a new `SidebarFooterTests` (chip text formatting, truncation rules, hidden when no data, accessibility label), `design/UI-MAP.md` sidebar footer line and `design/DESIGN.md` §2 item 5 (describing the D-32 footer; this is the decided change). Out of scope: Settings, tabs.

## Done when

- Same menu actions as today (Claude-only in production after F1); chip opens Settings at Usage; gear opens Settings; chip hidden while there is no data and shows an indexing state on the first scan.
- Screenshots at 300 pt and 220 pt sidebar widths match the UD design; no layout shift of the list when the chip text changes.
- Footer redraws only when the usage snapshot changes (the chip reads only `UsageModel`, not `CatalogModel` list state).

## Checks

`swift build`; `LoomCatalogUITests`; theme guard; screenshots on the U1/U2 package; `git diff --check`.
