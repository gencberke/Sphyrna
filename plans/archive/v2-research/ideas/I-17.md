# I-17: Attention-routing polish (ordering, roll-up, read/unread, Dock/menu bar, quit dialog, presence policy)

Card from the [Loom v2 idea catalog](../IDEAS.md). **Attention-routing polish (ordering, roll-up, read/unread, Dock/menu bar, quit dialog, presence policy)** · verdict **adopt-light** · cost M · value 3/5 · proposed by 7 reports: [cursor](../products/cursor.md), [attention-surfaces](../products/attention-surfaces.md), [supacode](../products/supacode.md), [paseo](../products/paseo.md), [codex-app](../products/codex-app.md), [warp](../products/warp.md), [power-user-workflows](../products/power-user-workflows.md).

> Most of I-17 already ships (severity Cmd+J, Dock badge, menu-bar Needs-you list, quit question, project roll-up dot, viewed-only-when-key); adopt only the real gaps (away-aware viewed and banners, opt-in finish/failure banner, quit sheet naming sessions, Dock menu, Mark Unread), and skip severity re-sorting of Active, quiet hours, per-turn lists and a mailbox.

## What the user gets

Triage rather than hunting: a severity-ordered Active section, a roll-up on collapsed projects, a trustworthy unread model, a Dock menu and menu-bar list of what needs you, a Quit dialog that lists Working sessions (Quit stops all of them), and notifications that stay quiet when you are already looking.

## Mechanisms found in the research

All derived from state Loom has, one reducer for sidebar, badge, Dock and menu bar so counts cannot disagree (Cursor's badge bugs 3.22/3.23). (a) Order Active by severity (error > needs approval > finished unviewed > working) then waiting-since, keep a hovered/selected row stable and re-sort on the next state change; collapsed project row shows roll-up priority needs-you > failed > working > finished-unviewed and a muted '+2 need you' line. (b) 'Viewed' clears only when the pane is visible AND focused; Mark unread (Cmd+Shift+U), Clear all unread (Shift+Esc), Cmd+J also cycling Finished-unviewed, per-turn unviewed list; compare-before-write read marks. (c) Dock icon menu built on demand listing needs-approval and unread sessions; menu-bar list blocked-first with 'N more', badge counting only what the list shows; Quit dialog that lists Working sessions and lets you jump instead of quitting, no delay when nothing runs. (d) Presence-aware policy: suppress sound/notification when the session is selected, the window is key and the screen unlocked; mute on lock/screensaver (distributed notifications); optional quiet hours and focus mode; a reminder ladder (approvals up to 3 nudges, finishes once) via one-shot timers that exist only while something is pending; approvals exempt from throttling.

## Debates and fact-check corrections

Cursor's Dock/menu-bar lists show UNREAD (finished) agents only, not needs-approval; the yellow dot is for cloud subagents, so Cursor is a weaker precedent than the report claimed; Loom can do better. Notifications: Hashimoto turns them off, Cherny relies on them (fact-check: single-agent vs multi-agent regimes, not a doctrine conflict). Supacode counts idle agents in its hoist (over-broad membership) and orders alphabetically (its visible weakness). Rows jumping under the cursor; each suppression rule can hide a real alert. Much of this may already exist in Loom (check first); a separate mailbox probably duplicates the Active section.

## Design in Loom

CHECKED FIRST - what Loom already has (so the idea is mostly a delta):
- One derivation already feeds the Dock badge, the menu-bar badge/summary and Cmd+J: CatalogModel.updateAttentionCount() (CatalogModel+Navigation.swift) builds attentionCandidates() from liveStates and calls AttentionOrder.count (Dock, via onAttentionCountChange) and MenuBarSummary.derive (menu bar + approval notifier, via onMenuBarChange). Fires on change only, no timer. The set is SessionIndicator.needsAttention for all three, so counts cannot disagree today. Dock count (all needing you) equals menu list (5 rows + 'and N more...').
- Severity order exists for navigation: AttentionOrder.rank = failure class(0) > needs approval(1) > waiting for you(2) > finished unviewed(3), then newest activity, then id (SessionNavigation.swift). Cmd+J / Shift+Cmd+J walk it; Finished-unviewed is already included.
- Menu bar menu already exceeds Cursor: 'Needs you' section (failure > attention > unviewed, newest first) and 'Working' section, 5 rows each + 'and N more...' (MenuBarState.derive, D-49/D-52).
- Quit question exists (D-45, QuitConfirmation.prompt/busyCount, AppDelegate.askBeforeQuitting): 'Quit Loom and stop N working sessions?', Cancel default, never for system-initiated quit, no question when nothing is busy. It does not name the sessions.
- Collapsed-project roll-up dot exists (CatalogModel.attention(forProject:), ProjectHeader: failure > attention > unviewed, 7 pt, visible when collapsed). It has no 'working' state and no count (DESIGN: 'Project rows show no session count').
- 'Viewed' is already strict: CatalogModel.updateViewing -> hub.setViewed only when windowIsActive (visible AND not occluded AND key AND NSApp.isActive, AppDelegate.updateWindowActivity) and not the dev terminal, and the selected session; list refreshes/frames never count. Mark as Read exists (card menu, waitingAcknowledged in SessionEventHub). Active section order is deliberately 'list activity order; a state change alone moves nothing; selected row held' (FB4-2, heldActiveID).
- Approval banner exists (ApprovalNotificationPlanner/ApprovalNotifier): only the transition into Needs approval, only while !NSApp.isActive, no sound, removed when answered/quit/launch, no timers. Single window, single process, in-memory read state.

REAL GAPS, in value order, each event-driven and bounded:
A. Away-aware 'viewed' and banners (spike first). Hole: Loom frontmost + selected session + user away (screen locked / screensaver / display asleep) means a finish is born 'viewed' (SessionEventHub.publish checks viewedSessionID) and the approval banner is suppressed (isAppActive = NSApp.isActive). Design: a tiny `PresenceState` in loom-app that flips on documented NSWorkspace.screensDidSleep/Wake and sessionDidResign/BecomeActive plus the (undocumented but long-stable) distributed notifications com.apple.screenIsLocked/Unlocked and com.apple.screensaver.didstart/didstop; while 'away' it feeds updateWindowActivity() as an extra false term (so setViewed(nil)), and ApprovalNotifier.isAppActive becomes 'model.windowIsActive' instead of NSApp.isActive. On return the existing edge re-asserts setViewed(selected). No polling, no idle-time query. If the spike shows occlusionState already flips on lock/screensaver, A shrinks to the one-line notifier change.
B. Opt-in 'Notify when a session finishes or fails' (default off, Settings -> General next to the approval switch). Generalise ApprovalNotificationPlanner into an AttentionNotificationPlanner over (previous, current) sets per class; post only on transition into Finished-unviewed/Failed, only when away or Loom not active, only for turns longer than a threshold (e.g. 60 s; hub knows working to turnComplete edge), identifier = session id so approval/finish replace each other, removed when viewed or marked read. Title = session title, body = 'project - Finished' (no assistant text on the lock screen). Fits the Hashimoto/Cherny split as a setting.
C. Quit sheet names what will stop: informativeText lists up to 5 titles (project - title) of Working/Needs-approval sessions; QuitConfirmation.prompt takes [MenuBarEntry]-like titles. Optional third button 'Show' selects the first and cancels the quit. Zero cost when nothing runs (prompt stays nil).
D. Dock menu: implement applicationDockMenu(_:) returning a menu built on demand from the same pure MenuBarMenu.items(for: model.menuBarState()) the status item uses (extract MenuBarController's menu building into a shared builder). Built only when the Dock menu opens.
E. Mark Unread (card menu + Window menu, Cmd+Shift+U) = hub change .unviewedCompletion(true) on a session at prompt; 'Mark All as Read' menu item (no Shift+Esc: Esc/Shift+Esc must reach the PTY, Claude uses Esc to interrupt). Hub already has both mutation paths.
F. Reminder ladder: later. If wanted, one Task.sleep per pending approval armed by the transition into Needs approval and cancelled on leaving it, nudges at ~5 and ~15 min only while Loom is not active/away; approvals never throttled. No timers exist otherwise.
G. Tidy: make AttentionOrder.rank and ProjectAttention one class enum (today the menu bar lumps approval and waiting-for-you as 'attention' and identityUnclear differs in rank), so order, dot and menu cannot drift (the Cursor 3.22/3.23 badge-bug lesson). XS.
H. Optional roll-up refinement: show the working chase/dot on a collapsed project when nothing needs you (Paseo rule). attention(forProject:) re-runs per ProjectHeader on every liveRevision change (O(live states) each) so implement as a cached per-project summary updated in updateAttentionCount. A '+2 need you' text line contradicts DESIGN 'no session count' and needs the user.

SKIP: severity re-sort of the Active section (contradicts the explicit 'a state change alone moves nothing' decision, creates the rows-jump-under-cursor/shortcut-target complaint Codex #36300 and cmux users report; with 2-6 rows the dots plus Cmd+J already triage); quiet hours/focus mode/mute-on-lock for sound (Loom posts no sound and macOS Focus already filters UNUserNotification banners); per-turn unviewed list (needs turn-boundary tracking, thin value at <=5 sessions); compare-before-write read marks (one window, in-memory state, Quit stops all runs); a separate mailbox (duplicates Active and the menu).

## Where it shows

No new surfaces. (A) invisible: a finish or approval that happens while the screen is locked now shows blue 'Finished' / banner instead of being silently 'viewed'. (B) one more switch in Settings -> General: 'Notify when a session finishes or fails' (off by default), banner 'Alpha - EDDP-123 fix' / 'alpha - Finished'. (C) the existing quit sheet gains a short list under the title: 'EDDP-1 auth fix (api) / spec review (docs) / +2 more'. (D) right-clicking the Dock icon shows the same Needs you / Working rows as the status item above the system items. (E) card context menu and Window menu: 'Mark as Unread' next to 'Mark as Read', plus 'Mark All as Read'. Sidebar order, Active section and project rows stay as they are (H is optional: a small chase glyph on a collapsed project that has only working sessions).

## Principle check

Resources: pass - everything is derived from existing hub frames; presence uses a handful of OS notifications (no polling); reminder timers (F) exist only while an approval is pending; Dock menu and quit list are built on demand. Predictability: pass if the rules are written in UI-MAP (viewed = visible+key+unlocked+selected; banners = transition + away/inactive); risk: every suppression rule can hide a real alert, so keep approvals unthrottled, always visible in sidebar/Dock/menu bar, and make B opt-in. Accurate status: pass and improves it (A removes false 'viewed'); risk: the undocumented com.apple.screenIsLocked names could change with macOS, so degrade to today's behaviour and keep the documented NSWorkspace sleep/session signals as the base. Fluency: pass (no new confirmations; quit sheet only gets more informative). Modularity: pass - pure planner/state types in LoomCatalogUI with tests, system hooks only in loom-app (SystemServices pattern); hub gets at most one injected change. CLI-update resilience: pass - nothing new depends on Claude; B uses the existing Stop-derived turnComplete; do not read new hook payload fields for banner text. Ownership: n/a (no process work). User authority: pass - banners only inform; no cross-session action. Principle violations to avoid: a repeating timer or idle-time poll for 'user present' (use events only), a global-settings or hook change, putting assistant text in lock-screen banners, auto-clearing 'Waiting for you' without the user's say (see decisions).

## Value for the user (3/5)

The original S/high-value framing overstates it for Loom because the Dock badge, menu-bar Needs-you list, severity Cmd+J, quit question, project roll-up dot and strict viewed rule already exist; the remaining pieces are polish. For a multi-session, long-run user the genuinely useful parts are away-aware viewed/banners and an opt-in finish/failure banner (the 'slow part was me noticing which one stopped' problem); the Dock menu, quit list and Mark Unread are small conveniences. Cost: each piece is S, but with pure-type tests, evidence and UI-MAP/DECISIONS updates the useful set is about M.

## Experiments before building

- S-1 Presence probe (decides A): in an isolated dev data root with --fake-providers (never the daily Loom.app, never real ~/.claude), log NSWindow.occlusionState, isKeyWindow, NSApp.isActive and the distributed notifications com.apple.screenIsLocked/Unlocked, com.apple.screensaver.didstart/didstop, plus NSWorkspace.screensDidSleep/Wake, while the user locks the screen, starts the screensaver and sleeps the display on this macOS 27 build. Decision: if occlusionState flips to not-visible on all three, A is the one-line notifier change (isAppActive = model.windowIsActive) and viewed is already honest; if not, add the PresenceState observers. Needs the user physically present; run only when the computer is idle per repo rules.
- S-2 idle_prompt reality check (decides decision 1): with an isolated CLAUDE_CONFIG_DIR and the current claude CLI, record whether Notification idle_prompt still arrives about 60 s after a finished turn and what it carries; confirms the 'Waiting for you after a turn you already read' behaviour (FEEDBACK-2/4) still applies today and how often the badge shows it.
- S-3 (only if B is adopted) measure real turn lengths from the user's own transcripts/usage index to pick the 'long turn' threshold, no new data collection.

## Questions for the user

- Waiting-for-you semantics: ~60 s after a finished turn you already looked at, Claude's idle_prompt turns the card orange 'Waiting for you' and it counts in the Dock badge, the menu's Needs you list, the project dot and Cmd+J (only the Active section ignores it; Mark as Read fixes it by hand, D-39). Should a turn you viewed be auto-acknowledged (badge then means real work for you, but you lose the nudge when Claude's last message was a question and you looked away) or stay as is? This single choice matters more for badge trust than any ordering change.
- Do you want finish/failure banners at all (D-52 deliberately limited banners to approvals), and if yes only when you are away or whenever Loom is not frontmost, and for turns longer than how many seconds?
- Reminder ladder for unanswered approvals (nudges at ~5 and ~15 min while you are away): wanted, or too noisy?
- Collapsed project rows: add a working glyph, and is a muted '+2 need you' line acceptable given DESIGN says project rows show no session count?
- Mark Unread / Mark All as Read: any shortcut preference (Shift+Esc is unsafe because Esc reaches the terminal)?
- Quit sheet: names only, or also a 'Show' button that cancels the quit and jumps to the first running session?
