# Superset (superset.sh, github.com/superset-sh/superset) — "agentic IDE" for running many CLI coding agents in parallel git worktrees. Site banner (2026-10-17) says it is "getting a new name soon".

Research note for the Loom v2 brainstorm ([index](../V2-BRAINSTORM.md)). Written by a research subagent on 2026-10-17 and fact-checked by a second one; the fact-check is at the end and wins over the report where they differ. Raw JSON: `../evidence/deep-dive-20261017.json`.

**In one line:** An Electron + xterm.js command center that gives every task its own git worktree, terminal and port set, tracks agent state through hooks, and wraps the work in a diff/PR review pane, a rich prompt overlay, CLI/MCP orchestration, cloud automations and a phone app. It has the widest feature surface of the category, and its public issue tracker is a long record of what that breadth costs in CPU, input lag and lost sessions.

**Category:** hybrid (terminal-first core, with a newer chat pane, a review pane and a browser pane attached; positioned by its own team and by HN users as "terminal-centric" against Conductor's "chat-centric")

## Adoption

GitHub data pulled 2026-10-17 via gh: 15,299 stars, 1,360 forks, repo created 2025-10-21, last push 2026-10-17, about 4,960 commits on main, 30 contributors from the API's first page (probably an undercount), 985 open issues/PRs. License is Elastic License 2.0 (source-available, not OSI open source).

Release cadence is very high. The desktop app went from 1.29.0 on 2026-09-13 to 1.38.0 on 2026-10-14, with a rolling canary build and a separate CLI release train. GitHub release-asset download counts range from about 15k to 166k per release (1.29.0: 166k, 1.30.2: 126k, 1.37.0: 90k). Those counts include auto-updater fetches, so they overstate unique users.

Launch signals: the Show HN post (item 46368739, about December 2025) scored 96 points with 90 comments. Product Hunt launch on 2026-03-01 reportedly scored 512 upvotes (secondary source, launchllama.co). Pricing per the Agentastic comparison page (a competitor): Pro is $20 per user per month and gates remote workspaces, Linear and team features. Superset's own docs mark Automations and Remote Access as Pro.

Reception is mixed. Positives: the persistence daemon, notifications, and being "terminal-first" (HN 48237245). Negatives from Reddit and HN: config friction, "all these apps look the same", and some users who went back to vanilla Claude Code or cmux. Competitor and comparison pages (Agentastic, ai-deck.app) call it "Electron", which is the main axis of differentiation for native rivals.

## Architecture

STACK. TypeScript/Bun Turborepo monorepo. Electron desktop app (apps/desktop: main, preload, renderer with React, TanStack Router and Query, zustand, Lingui i18n). xterm.js with WebGL rendering plus a stack of patches (apps/desktop/src/*-patch.test.ts: xterm-flushsync, webgl-atlas, ime, ligatures). A tiny native addon (packages/macos-process-metrics) feeds the Resources page. Mobile app is Expo/React Native. Cloud side: Next.js API, Postgres/Drizzle, Electric sync, a relay on Fly/Durable Objects.

PROCESS LAYERS (apps/desktop/docs/HOST_SERVICE_ARCHITECTURE.md; packages/pty-daemon/README.md).
1. Electron main spawns, adopts or releases a per-organisation host-service child process. It is a Hono + tRPC server (packages/host-service) with SQLite (better-sqlite3/Drizzle), and owns workspaces, git, the filesystem watcher, ports, hook ingestion, terminal WebSocket routes and chat.
2. host-service talks over a Unix socket (mode 0600, length-prefixed protocol with version handshake) to a long-lived pty-daemon: a detached Node process (not Bun, because node-pty does not work under Bun) that owns the PTYs through node-pty pinned to 1.2.0-beta.14 to avoid an fd leak. It keeps an in-memory ring buffer per session and supports fd-handoff so a new daemon binary can take over live PTYs (packages/host-service/src/daemon/DaemonSupervisor.ts, which I did not read; its behaviour is quoted from issue #7977 and the README).
3. host-service feeds PTY bytes into a headless xterm (@xterm/headless) so that on re-attach it can replay a "mode preamble" (kitty keyboard, bracketed paste, mouse, focus) before the byte ring. Reason: a Codex TUI lost Shift+Enter after a renderer refresh because the 64 KiB replay FIFO had evicted the enable sequence (plans/20260507-terminal-mode-replay.md).

AGENT CONTROL. Superset drives the real CLI in a PTY and never replaces its UI in the terminal pane.
- Wrappers in ~/.superset/bin/<agent> export SUPERSET_* env vars. Hook scripts are merged into each agent's GLOBAL config (~/.claude/settings.json and others) at every app start (HOOKS_INVESTIGATION.md).
- The hook script (packages/agent-setup/templates/notify-hook.template.sh) is bash. It parses JSON with grep/sed, POSTs to a host-service endpoint with curl, and no-ops when SUPERSET_TERMINAL_ID is unset. It drops events from a foreign harness and forwards subagent fields (agent_id, agent_type, transcript_path) separately.
- host-service keeps one TerminalAgentBinding per terminal in SQLite (packages/host-service/src/terminal-agents/store.ts, persistence.ts). It records lastEventType and lastEventAt, the agent session id, a resume candidate (endedAt/endReason), and an in-memory subagent roster capped at 64 per terminal that expires after 10 minutes of silence.
- The renderer DERIVES status (working, permission, review, idle) from the binding. The only renderer state is a per-terminal "seen at" timestamp using the host clock (plans/done/20260703-1507-derive-terminal-agent-status-from-host-binding.md). Interrupts (Esc/Ctrl+C) fire no hook, so the renderer posts a synthetic Stop.
- Text to a running agent goes through a host terminal.send: sanitise, wrap in bracketed paste, wait FOLLOW_UP_ENTER_DELAY_MS, send "\r" (terminal.ts around line 1276). A lint-style test forbids raw terminal.writeInput for text.

CHAT. A separate chat-v3 stack (packages/chat, chat-runtime, host-service/src/chat-v3) uses the Claude Agent SDK (pinned 0.3.286) and ACP and Codex adapters. It has a durable journal with (epoch, seq) cursors, one pure reducer for live and replay, approvals as transcript items, and FIFO queueing with an explicit steer. It is a pane type with a harness picker, not the main surface.

PERSISTENCE. Host SQLite (workspaces, terminal sessions, bindings), a renderer persisted query cache in IndexedDB and localStorage, the daemon's in-memory ring, and disk scrollback for crash restore. Claude's own JSONL is read for handoff and fork, found via transcript_path from the hook payload, then a computed project directory, then a scan by session id (docs/agent-session-handoff.md).

RESOURCE NOTES (all from their own docs and issues).
- Renderer RSS was about 1.5 GB with 18 terminals before parked-terminal eviction (cap 12; alternate-screen TUIs are exempt, so agent panes are never evicted).
- A generic worker_threads pool offloads git status (min(4, cpus-1) workers, idle reaped after 30 s).
- A port scanner polls lsof every 2.5 s (30 s when idle).
- Idle git and process fan-out scales with the number of workspaces (issues #4198, #6717, #6729, #8108).

## Core loop

A typical day:
1. Press ⌘N and write a prompt, optionally linking a PR or issue. The workspace opens immediately as "New workspace" while a background job names it and its branch from the prompt (docs/workspaces.mdx).
2. Superset runs `git worktree add` under ~/.superset/worktrees/<project>/<branch>, runs the setup commands from .superset/config.json in a terminal, and launches the chosen agent. By default the agent starts in parallel with setup.
3. Do something else. The sidebar shows per-workspace dots (working, needs input, finished), diff stats, a PR badge and detected ports. A notification, sound and dock badge fire on finish or on a permission request. ⌘; opens a "switch to active workspace" picker listing sessions that are waiting, finished-unseen or running.
4. Open the workspace, look at the Changes diff (focus mode, one file at a time), select lines and send a comment straight to the running agent's terminal, or use ⌘I to compose a longer multi-line prompt with @file mentions and pasted images.
5. Commit, push and open the PR from the Changes control. Review comments, checks and merge live in the Review/Pull requests pane. Delete the workspace after merge (archive-first deletion).
6. Power users script the loop. `superset ws create --agent claude --prompt ...`, `superset terminals read/send`, an orchestrate skill that fans work out to worker workspaces, and Pro cloud automations that create a fresh workspace on a schedule.
7. Quitting with ⌘Q leaves terminals alive in the daemon. A separate "Quit Superset Completely" ends them (docs/keep-agents-running.mdx).

## Features

### Worktree-per-task workspaces with setup/teardown/run scripts (parallel-worktrees, confidence high)

- **What the user sees:** ⌘N opens a prompt-first modal (new branch, existing branch, or PR). The workspace appears at once and is auto-named from the prompt. A setup terminal runs repo-defined commands, and a Run button starts the dev server in its own pane. 'Sessions' are project-less scratch workspaces, and existing worktrees can be imported. Deleting a workspace removes the row at once, then does the teardown.
- **How it works:** .superset/config.json holds setup/teardown/run arrays. Precedence: user override at ~/.superset/projects/<repo-path>/config.json, then the worktree file, then the repo file (docs/setup-teardown-scripts.mdx). The env exposes SUPERSET_ROOT_PATH, SUPERSET_WORKSPACE_PATH and SUPERSET_WORKSPACE_NAME. Commands are queued behind a shell-readiness gate (OSC 133 prompt markers), with a timeout fallback for unsupported shells (docs/V2_WORKSPACE_SETUP_SCRIPTS.md). Superset deliberately assigns no per-workspace ports. A 'pro tip' tells users to build a port-allocation file in their own scripts, and the HN founders said 'we only orchestrate when they run'. Deletion is archive-first: a tombstone is written as the commit point, then dirty-check, teardown and worktree removal run, with un-archive on any failure and startup reconciliation of interrupted deletes (apps/desktop/docs/WORKSPACE_DELETE_LIFECYCLE.md; code in packages/host-service/src/trpc/router/workspace-cleanup/).
- **Reception:** Founders claim about 2 s to spin up a worktree. Praised as 'close to the feeling of working directly on main' because it builds on the existing checkout instead of re-cloning (ai-deck.app). Commenters raised the unsolved parts, which are databases, docker and ports per worktree, and Superset's answer is 'write your own scripts'. Open bugs: a macOS major upgrade cleared all worktrees (#8209); 'SUPERSET_WORKSPACE_NAME documented but not set' (#8505); a multi-line teardown is split per line and silently not run (#7866); a loss of localStorage silently falls back to the legacy v1 dashboard and looks like 'all my worktrees disappeared' (#5498).
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/setup-teardown-scripts.mdx; https://github.com/superset-sh/superset/blob/main/apps/desktop/docs/WORKSPACE_DELETE_LIFECYCLE.md; https://news.ycombinator.com/item?id=46368739; packages/host-service/src/trpc/router/workspace-cleanup/workspace-cleanup.ts (named in the docs; not read)

### Persistent terminals via a detached pty-daemon (other, confidence high)

- **What the user sees:** Closing the window, ⌘Q, or installing an update does not stop agents. Reopening reattaches each terminal with scrollback. 'Quit Superset Completely' ends all sessions. A dead terminal offers 'New shell' with its last output still visible, and a crashed agent is auto-resumed with `claude --resume <id>`.
- **How it works:** A separate Node process (packages/pty-daemon) owns node-pty masters. host-service is a client over a 0600 Unix socket, and the daemon keeps an in-memory ring per session (README says 64 KB; docs/agent-session-handoff.md mentions a 2 MB output ring, so the number is not settled in what I read). Phase 2 adds fd-handoff so a new daemon binary adopts live PTYs. host-service adopts a running daemon at startup (DaemonSupervisor tryAdopt) and has a trustd health probe. Crashes restore scrollback from disk, and on a reboot the binding's endReason 'terminal-exited' makes the session a resume candidate (terminal-agents/types.ts).
- **Reception:** The most-loved differentiator in HN threads ('lovely stuff'; 'sessions stay alive when you kill or update the app'). It is also the largest source of their reliability bugs. Reporters say updates wiped all terminal sessions (#7977, 1.30.2: layout came back but every shell was blank; a triage comment suspects the adoption path kills a daemon whose startup trustd health flag was false). The daemon's input path wedged after about a day (#5792). A daemon adopted after a macOS logout stays in the dead login session (#8029). Scrollback.bin writes produced about 60k file events per minute and hurt machines with endpoint-security agents (#3215). In July 2026 the team swept performance and persistence issues into tracker issues #5602 and #5607.
- **Evidence:** https://github.com/superset-sh/superset/blob/main/packages/pty-daemon/README.md; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/keep-agents-running.mdx; https://github.com/superset-sh/superset/issues/7977; https://github.com/superset-sh/superset/issues/5792; https://github.com/superset-sh/superset/issues/3215

### Agent status from hooks, with a single host-side source of truth (attention-status, confidence high)

- **What the user sees:** Per-workspace indicators for working (braille spinner), needs input, finished-unseen ('review') and idle, plus an activity strip of running agents and open ports. Notification sounds, a dock badge, and a ⌘; picker 'Switch to Active Workspace' for sessions that are waiting, finished-unseen or running. A 'Clear Status' escape hatch exists for stuck indicators.
- **How it works:** The bash notify hook POSTs normalised events (Start, Stop, PermissionRequest, Attached, Detached) to host-service. The binding row is the state machine, and the renderer derives status in deriveTerminalAgentStatus.ts. review = Stop and lastEventAt greater than terminalSeenAt. Seen marks use only host clocks, to avoid skew bugs. Binding visibility is a SQL join against terminal_sessions.status='active', so dead terminals cannot be represented (the join replaced earlier 'prune' machinery). Staleness is handled with a 30 s staleTime and window-focus refetch, plus a 60 s refetch only while subagents are listed. A guard (SUPERSET_TERMINAL_ID) makes the global hook inert outside Superset terminals, but newer wrappers also drop events from a foreign harness because cursor-agent replays Claude's settings.
- **Reception:** Works well enough to be a headline feature, but the issue tracker shows the failure classes. (1) Status drops to review while a background subagent is still running, because every main Stop is treated as completion even though Claude's Stop payload carries background_tasks (#8120). (2) A nested `claude -p` inside a Bash tool call inherits the terminal's env and its SessionStart/SessionEnd replace the parent's binding and wipe the subagent roster (#8131; plans/agent-session-ownership.md proposes launch-generation ownership). (3) The synchronous bash hook ran multiple greps per field and one reporter measured 12.8 s per UserPromptSubmit, with recurring 30 s hook timeouts (#8245). (4) Registering hooks in the global ~/.claude/settings.json shows 'Hooks Stop' lines in non-Superset sessions and caused Grok/Droid hook failures outside the app (#8375, HOOKS_INVESTIGATION.md).
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/desktop/plans/done/20260703-1507-derive-terminal-agent-status-from-host-binding.md; https://github.com/superset-sh/superset/blob/main/packages/agent-setup/templates/notify-hook.template.sh; https://github.com/superset-sh/superset/blob/main/apps/desktop/src/renderer/hotkeys/registry.ts (OPEN_ACTIVE_WORKSPACE_SWITCHER, meta+;); https://github.com/superset-sh/superset/issues/8120; https://github.com/superset-sh/superset/issues/8131; https://github.com/superset-sh/superset/issues/8245; https://github.com/superset-sh/superset/blob/main/HOOKS_INVESTIGATION.md

### Changes / diff / Review pane with line comments sent to the running agent (review-git, confidence high)

- **What the user sees:** A right-sidebar Changes control shows diff stats and ship actions (commit, push, create PR). The pane has Files/Changes/Review tabs, split or unified diff, a focus mode that shows one file at a time with Prev/Next and sections (against base, commits, staged, unstaged), and a PR checks and review-thread view. In the Pull requests view you can select lines in the Code tab and send a comment to a running agent terminal or a new session, optionally also posting it to GitHub.
- **How it works:** The diff UI uses @pierre/diffs and @pierre/trees (virtualised tree and shadow-DOM rows, a worker pool of 8 for rendering). Git status/diff run in a host worker pool (packages/host-service/src/workers). The comment prompt is a plain string, 'In <path>:L<a>-L<b> (deleted lines): <comment>', built by formatAgentPromptWithFileContext and sent through terminal.send, so it lands in the agent as a normal user message (apps/desktop/src/renderer/hooks/host-service/useSendToTerminalAgent). Their older plan to make PR actions agent-driven (markdown skills choose the next step) is in apps/desktop/plans/20260420-1045-agent-driven-pr-flow.md.
- **Reception:** HN users value having 'the nice visual diff' that a TUI cannot do. Complaints are about cost and staleness: the Changes panel froze the renderer for 11 s or more on mount (#5521), large diffs hang the app (#5462), stale diffs after a commit (#7349), and the Changes sidebar caused terminal input lag with large change sets (#5300, closed). Their own measurements in MEMORY_AND_WORKERS_REVIEW.md: eight 20k-file worktrees under churn produced a 6.6 s renderer stall until the file list was virtualised (917 MiB peak RSS afterwards versus 1.7 GiB). Users also ask for use of Changes and Review without splitting the agent session (#8557).
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/diff-viewer.mdx; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/pull-requests.mdx; https://github.com/superset-sh/superset/blob/main/apps/desktop/src/renderer/hooks/host-service/useSendToTerminalAgent/useSendToTerminalAgent.ts; https://github.com/superset-sh/superset/blob/main/apps/desktop/docs/MEMORY_AND_WORKERS_REVIEW.md

### ⌘I rich prompt overlay for the terminal agent (chat-input, confidence high)

- **What the user sees:** ⌘I opens a multi-line composer overlay on top of the terminal pane (Ctrl+Shift+M on Windows and Linux). It supports @file mentions with fuzzy search, @plugin mentions, pasted images and attachments, and a draft that survives closing and switching terminals. Submit sends the text into the running agent's input.
- **How it works:** TerminalRichInput.tsx reuses the chat composer stack (PromptInput + a Tiptap editor). Drafts live in a module-level Map keyed by terminalId. On submit, attachments are first written into the worktree and the prompt gets shell-escaped relative paths appended, because a PTY only carries bytes (prepareTerminalSubmission.ts). Text is sanitised (strip escape/OSC/control, expand tabs), then host terminal.send wraps it in bracketed paste, writes it, waits a short delay and presses Enter. Sends are serialised per session so a concurrent send cannot land between text and Enter (terminal.ts ~1250-1300). Comment: 'Warp-style'.
- **Reception:** I found no public praise or criticism specific to ⌘I; it is not called out in release notes or community threads. The known weakness is delivery semantics: text sent to a busy Claude session, or one with a very large context, can land as an unsubmitted draft while the API reports success, and there is no way to confirm submission (#6243, closed). Related paste fixes: text must go as bracketed paste, not raw keystrokes (PR #7670). A reporter also complains that the prompt input bar 'jumps around or does not show' (#8248, unclear which prompt surface).
- **Evidence:** apps/desktop/src/renderer/routes/_authenticated/_dashboard/v2-workspace/$workspaceId/hooks/usePaneRegistry/components/TerminalPane/components/TerminalRichInput/TerminalRichInput.tsx; packages/host-service/src/terminal/terminal.ts (send path ~L1236-1310); https://github.com/superset-sh/superset/issues/6243; https://github.com/superset-sh/superset/issues/8248

### Lazy, refcounted git watching and a worker pool (the performance lessons) (other, confidence high)

- **What the user sees:** Not a feature: this is the engineering response to input lag, CPU burn and renderer freezes that accumulate with the number of open workspaces.
- **How it works:** GitWatcher (packages/host-service/src/events/git-watcher.ts) debounces worktree edits at 300 ms and .git-only batches at 1 s, ignores .git/objects, lfs, logs and FETCH_HEAD, drops events inside gitignored directories, and caps path tracking at 128 paths per batch before switching to one broad invalidation. A 30 s branch-sync interval that spawned about 5-7 git processes per workspace was found to cost 19 ms per op and linear in N (plans/v2-paths-worktree-perf-findings.md) and was moved to event-driven refresh with a 5-minute safety sweep. Watching is now refcounted so only workspaces someone holds interest in are watched (the sidebar comment cites #6729). Status snapshots run in a generic worker_threads pool with a limiter at concurrency 4 (raising it to 6 did not help). A common-dir fetch TTL stays on the main thread so parallel worktrees do not repeat fetches.
- **Reception:** Still open as users scale up. #4198: with an endpoint-security agent, many git subprocesses per cycle per workspace starved the renderer. #6004: `git status -u` (untracked=all) defeats git's untracked cache and costs about 50 times more on a 61k-file repo (0.03 s versus 1.9 s). #6717: about 19 short-lived processes every 2.5 s with 10 worktrees (the port and process scanner). #8108: with 209 workspaces over 7 hosts and about 20 agent TUIs, the renderer averaged 59-64% of a core, with 100-170% bursts every 2-3 s tied to per-workspace status queries, query-cache persistence to IndexedDB, and a setInterval spinner per working row; lowering the parked-terminal cap changed nothing because alternate-screen TUIs are exempt. #6610: a canary auto-update leaked the old host-service and orphans spun at about 90% CPU. #5379: one report of a macOS kernel panic attributed to Superset on Apple Silicon (cause unverified).
- **Evidence:** https://github.com/superset-sh/superset/blob/main/plans/20260717-host-service-git-worker-pool.md; https://github.com/superset-sh/superset/blob/main/plans/v2-paths-worktree-perf-findings.md; packages/host-service/src/events/git-watcher.ts; https://github.com/superset-sh/superset/issues/4198; https://github.com/superset-sh/superset/issues/6004; https://github.com/superset-sh/superset/issues/6717; https://github.com/superset-sh/superset/issues/8108

### Orchestration: CLI, MCP server, SDK, and automations (orchestration, confidence high)

- **What the user sees:** `superset ws create --agent claude --prompt ...`, `superset agents create`, `superset terminals read|send`, `superset browser ...`, plus an MCP server and a `superset:orchestrate` skill so one agent can fan out workers in separate workspaces and verify their reports. Pro Automations run a prompt on RRULE schedules (daily triage, dependency sweeps) and the result is a live workspace you can open and continue, with run history and Retry all.
- **How it works:** The CLI talks to the local host-service (and the relay for remote hosts). Automations are a cloud dispatcher that hands a prompt to a chosen device's host-service, which creates a workspace and launches the agent via terminal.launchSession (docs/V2_WORKSPACE_SETUP_SCRIPTS.md). Delivery is at-least-once and a 'created' status only means the workspace was created, not that the agent succeeded (docs/automations.mdx). Offline hosts fail the run. Workspaces created by automations are tagged 'automation' and filed in sidebar folders. AGENTS.md tells agents working inside the repo to use the CLI rather than hand-rolled worktrees.
- **Reception:** Marketing-heavy and Pro-gated, so organic user commentary is thin. Visible friction: 'continue-session' automations still open a new agent session every run (#7941); delivery cannot be confirmed (#6243); automation grouping and reordering requests (#8523); parallel CLI commands race a token refresh and can log every agent out (#8426). Founder positioning on HN: it is 'more terminal-first than Conductor' with a daemon, and the multi-agent top-level orchestrator was a stated future plan.
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/automations.mdx; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/orchestration.mdx; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/mcp-server.mdx; https://github.com/superset-sh/superset/blob/main/AGENTS.md; https://github.com/superset-sh/superset/issues/7941

### Chat v3: a chat pane next to the terminal (Claude Agent SDK, ACP, Codex) (chat-input, confidence medium)

- **What the user sees:** An optional chat pane type with a harness picker. It shows streaming messages, collapsed tool-call runs, inline approval cards (accept / accept for session / decline / cancel), AskUserQuestion and plan review, a message queue, mid-turn steer, and background-task chips across chats. The same chat session opens on the phone.
- **How it works:** packages/chat is a client-safe protocol and reducer (zod item vocabulary, upsert-by-id snapshots, a pure reducer used for both live and replay, derived timeline, outbox with client ids). packages/chat-runtime owns a journal with (epoch, seq) cursors and adapters for Claude (Agent SDK query() in streaming-input mode, canUseTool turned into approval items, optional pathToClaudeCodeExecutable so the user's installed CLI runs), Codex and generic ACP. host-service mounts it (packages/host-service/src/chat-v3). Eight protocol decisions were ratified on 2026-08-04, including 'edit history means fork, never truncate' and 'FIFO queue with an explicit steer' (plans/20260804-chat-protocol-decisions.md). The greenfield research doc says the industry converged on this shape and that Conductor's strength is chat polish and checkpoints.
- **Reception:** Too new to judge: PRs 8242, 8329 and 8339 landed 2026-10-06 to 10-09. Product communication stays terminal-first, and on HN the founders said the chat experience in Conductor 'is still a bit more polished' and that they would reach that level of polish later. Several plan documents say the earlier mastra-based chat was replaced because it polled at 250 ms and had no durable history.
- **Evidence:** https://github.com/superset-sh/superset/blob/main/plans/chat-ship-plan.md; https://github.com/superset-sh/superset/blob/main/plans/chat-ui-greenfield-research.md; https://github.com/superset-sh/superset/blob/main/plans/20260804-chat-protocol-decisions.md; packages/chat-runtime/src/harness/claude/createClaudeAdapter/createClaudeAdapter.ts

### Usage page: quota meters, multi-account profiles, machine resources (usage-cost, confidence high)

- **What the user sees:** A Usage page with official subscription quota meters per Claude/Codex/Grok/OpenCode login (session 5 h and weekly windows with time until reset, refreshed every 5 min), token and API-equivalent cost charts (7/30/90 days, per model, per workspace, top sessions), 'Add account' with a default-account radio, and a 'Machine resources' tab (live every 2 s) with a process table grouped by project down to individual terminal panes.
- **How it works:** Quota comes from provider usage endpoints using credentials stored on the host (packages/host-service/src/trpc/router/usage/claude.ts, codex.ts). Cost comes from the agents' local session logs. A second account is a separate config dir the CLI is pointed at (CLAUDE_CONFIG_DIR / CODEX_HOME), skills, plugins and MCP config are shared across accounts, and the wrapper re-resolves the default account at every agent start; a value the user exports wins (docs/usage.mdx).
- **Reception:** Their own X poll (17 respondents, 12 positive) found quota percentage and reset time matter more than raw tokens; people already use CodexBar, runway or /usage for this. One user wants quota shown inside the model dropdown so a new task can go to the account with the most headroom. Reported issues: the 90-day history times out after 110 s (#8564), Machine resources intermittently made the window unusable (#7648, closed), and OpenAI-endpoint trackers are a gray area under OpenAI's terms.
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/usage.mdx; https://github.com/superset-sh/superset/blob/main/plans/20260815-token-spend-twitter-feedback.md; https://github.com/superset-sh/superset/issues/8564; https://github.com/superset-sh/superset/issues/7648

### Session resume, fork and cross-agent handoff (context-knowledge, confidence high)

- **What the user sees:** A fork icon in the agent terminal header: 'Fork session' starts a native copy of the conversation in a split or new tab while the original keeps running; 'Continue with another agent' seeds a different agent with the last 36,000 characters of context and shows a character/token count first. A crashed or killed agent session is resumed automatically with 'Resuming...'.
- **How it works:** Fork shells out to the agent's own flags (`claude --resume <id> --fork-session`, `codex fork <id>`, `opencode --session <id> --fork`). The session id comes from the hook payload and is stored in the binding. Handoff reads Claude's JSONL located by (1) the transcript_path in the hook payload, (2) the computed project directory name, (3) a scan for projects/*/<id>.jsonl capped at 5,000 directories. It runs in a worker, falls back to the PTY output stream, then to the visible screen. Superset's docs say the Claude directory naming is 'not a documented contract' and note this explicitly (docs/agent-session-handoff.md).
- **Reception:** No public criticism found; a feature request exists for restoring all resumable sessions with confirmation (#7806, #3496). Caveat in their docs: a handoff sends terminal output to the target provider without redaction.
- **Evidence:** https://github.com/superset-sh/superset/blob/main/docs/agent-session-handoff.md; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/agent-sessions.mdx; packages/host-service/src/terminal-agents/harness-sessions/claude.ts (named in docs; not read)

### Browser pane with Design mode, and Pages (browser-preview, confidence medium)

- **What the user sees:** ⌘⇧B opens an in-app browser tab, and a detected port's link opens there. 'Design' arms an element picker. Clicking an element opens a prompt card, and the agent receives DOM, computed styles, React component info and a cropped screenshot with the note. Agents can drive the pane with `superset browser open|eval|screenshot|console|cdp`. 'Pages' lets an agent publish an HTML report or design as a shareable page where teammates pin comments to elements and an agent watching the page picks them up.
- **How it works:** The pane is an Electron webview. `superset browser cdp` exposes a CDP WebSocket scoped to that pane only, never the app itself. Hidden webviews are LRU-evicted (cap 3). Pages are published to the cloud with visibility (private, org, public link) and a comment watcher plan (plans/20260828-pages-comment-watcher.md).
- **Reception:** Design mode is recent (round-trip request #8447: queue notes on several elements and send them together). Known bugs: agent CDP clicks steal keyboard focus from the user's terminal (#8372); a pane stays over the window after HTML fullscreen (#7854).
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/browser.mdx; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/pages.mdx; https://github.com/superset-sh/superset/issues/8372; https://github.com/superset-sh/superset/issues/8447

### Remote hosts, relay and the iPhone/iPad app (Pro) (remote-mobile, confidence medium)

- **What the user sees:** Add any machine as a host (including `superset hosts add` over SSH), see its workspaces in the same sidebar, forward detected ports to localhost, and use an iPhone/iPad app to read terminals, send prompts, review diffs, merge PRs, or run cloud workspaces. The standalone CLI can keep a host running with the desktop closed.
- **How it works:** Each machine runs a host-service that registers with a cloud relay by outbound WebSocket tunnel. The relay buffers HTTP and forwards WebSocket frames, so streaming uses WebSocket with sequence cursors. The relay holds JWTs in the WS query string with a fresh token per reconnect (plans/chat-ui-greenfield-research.md). Enabling remote access in the desktop restarts the host service, which interrupts running terminals (docs/remote-access.mdx). The docs warn against exposing the primary workstation.
- **Reception:** HN: a user with a remote Mac mini as a Claude terminal was excited but reported typing lag over the relay and suggested mosh. A reported case of a ~212 ms per-keystroke path through relay edges (#6232). A host-id/port adoption bug lets an app adopt another macOS user's host on a reused port (#8551). Remote access is Pro-gated, and a native competitor (Agentastic) markets the same capability as free.
- **Evidence:** https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/remote-access.mdx; https://github.com/superset-sh/superset/blob/main/apps/docs/content/docs/keep-agents-running.mdx; https://github.com/superset-sh/superset/issues/8551; https://github.com/superset-sh/superset/issues/6232

## UX patterns worth borrowing

- Prompt-first new-workspace modal (⌘N): write the task first, branch and workspace name are generated in the background; workspace appears instantly and is named later (docs/workspaces.mdx).
- Right sidebar with a single 'ship' control: diff stats while dirty, the next sensible action when clean (commit, push, create PR), PR badge once a PR exists. The Files/Changes/Review tabs hold the detail.
- 'Switch to Active Workspace' picker (⌘;) listing only sessions that need you: waiting, finished-unseen, running. Loom's ⌘J is the same idea.
- Seen-marker model for 'finished': a Stop event newer than the per-terminal seen time shows as review, and focusing the pane marks it seen. Only the user-owned fact (seen time) is stored on the client.
- Draft-preserving overlay composer anchored to a terminal, keyed by terminal id, with @-mentions and image paste turned into worktree file paths.
- Diff focus mode: one file at a time, Prev/Next, section dropdown with counts ('2/5 in Staged').
- Archive-first destructive actions: the row disappears at once as a durable tombstone, work continues in the background, and it re-appears with the error and output tail if it fails.
- Activity strip on a sidebar row: agent chips only when more than one agent runs, ports inline, PR state persisted across restarts.
- Tags and folders for batches: automation- or CLI-created workspaces auto-group in a named sidebar folder, plus pinning and sort modes (manual, last active, date created) where 'last active' comes from a column the host stamps on each agent event.
- Command palette (⌘⇧K), quick open (⌘P), and a Resources view reachable from the palette.
- Per-account quota meters with time-until-reset as the first thing on the Usage page, with token and cost charts underneath.

## Anti-patterns

- Registering hooks in the agent's GLOBAL config and relying on an env-var guard: every unrelated session pays for it, shows hook lines in its own UI, and breaks when a harness is not migrated to the guarded form (HOOKS_INVESTIGATION.md, #8375).
- A synchronous bash+grep+curl hook on UserPromptSubmit: one reporter measured about 12.8 s per run and repeated 30 s timeouts; a status hook should finish in milliseconds and never add latency to a prompt (#8245).
- Treating every main-loop Stop as 'done': background subagents and workflows keep running after the turn ends, and Claude's Stop payload already lists them (#8120). Equally, a nested CLI that inherits the terminal environment must not overwrite the parent's binding (#8131).
- Reporting 'sent' as success when the agent has not submitted the text: busy or large sessions leave an unsubmitted draft (#6243). Superset's own docs warn about at-least-once automation delivery and 'created, not succeeded' run states.
- Polling and fan-out that scale with the number of workspaces rather than with what is visible: 30 s branch sync with 5-7 git processes per workspace, lsof every 2.5 s per terminal tree, GitWatcher on every non-archived workspace, one status query per sidebar row, a setInterval per spinner (#4198, #6717, #6729, #8108; plans/v2-paths-worktree-perf-findings.md).
- `git status -uall` (simple-git's default `-u`): defeats git's untracked cache and was measured at 50 times slower on a large repo (#6004).
- A persistence daemon that survives Quit and updates adds a large failure surface (adoption probes, fd-handoff, trustd checks, login-session binding, wedged input path). Users still report that updates wiped sessions (#7977, #5792, #8029). It buys reboot-free continuity at the price of orphan processes (#6610) and an unclear answer to 'what is still running?'.
- Unbounded caches and persisted UI state: search index with no eviction, localStorage layout for archived workspaces, and a query cache dehydrated to IndexedDB on every event (#8106, #5496, #8108). Alternate-screen TUIs exempt from eviction mean a memory cap does not help agent panes.
- Putting an unauthenticated local hook endpoint in front of state the UI trusts: the store comments that the hook endpoint is unauthenticated and bounds the roster, and sessions are bound by environment variables that children inherit.
- Feature sprawl behind a shared shell (tasks, Linear, pages, cloud sandboxes, connectors, voice, plugins marketplace) while core terminal quality bugs stay open; users note the products 'all look the same' and some return to vanilla Claude Code or cmux.
- Silent fallbacks that look like data loss: losing localStorage falls back to the old dashboard so 'all worktrees disappeared' (#5498); an OS upgrade or app update showing blank terminals (#8209, #7977).

## Ideas for Loom

### Side chat as a fork: add 'Fork session' on a card, which starts `claude --resume <id> --fork-session` in a second Loom-owned PTY shown as a child of the original card (like the subagent tree). Closing it throws it away and never touches the main thread. (cost M)

- **Inspired by:** Superset fork icon and docs/agent-session-handoff.md; agent-sessions.mdx fork table (Claude, Codex, OpenCode, Pi, Grok, Droid).
- **Gain:** Gives the long-standing wish for a ChatGPT-style side thread that shares the context but does not pollute the main conversation, using only a documented CLI flag. No new UI paradigm is needed: it is one more card with a lineage marker, and the user can ask a clarifying question or a risky what-if while the main agent keeps working.
- **Fit:** Fits well. It uses a CLI option rather than a pinned version, and Loom's CLI drift detection can already flag the flag as missing. The fork runs in its own run scope, so Stop and Quit remain verified. Costs nothing when idle because a closed fork keeps no live process (ended screen). Open questions: a fork replays the full context so it costs tokens and cache, and the session id of the source must be known (Loom already reads Claude's session registry). Not verified: whether a fork behaves well while the parent is mid-turn.
- **Risks:** Token cost of a fork on a big context, and confusion about which card is the 'real' thread. Needs a clear lineage badge and a one-key 'discard fork'. Claude must expose a stable session id before the first turn finishes.

### Composer overlay (⌘I-style) with per-session drafts and VERIFIED delivery: a native multi-line editor over the terminal for long prompts, @file completion from the session's cwd, image paste saved to a file and referenced by path, drafts kept per session. Send uses bracketed paste plus Enter, and the card shows 'submitted' only when the UserPromptSubmit hook for that session arrives within a short window, else 'not submitted yet, press Enter' with the draft kept. (cost M)

- **Inspired by:** TerminalRichInput.tsx, prepareTerminalSubmission.ts, terminal.ts send path; the failure described in issue #6243.
- **Gain:** Long, structured prompts and screenshots become comfortable without leaving the real CLI, and the same pipeline can later carry prompt queueing and diff comments. The verification step removes the silent-failure class Superset users hit.
- **Fit:** Strong fit if kept native and small: an NSTextView overlay that draws only while open, drafts in memory (persisted only on quit if the user wants), no polling, because confirmation comes from the existing hook event. It never replaces the CLI interface. Conflict: the CLI's own input handling (vim mode, slash-command completion) is unavailable in the overlay, so keep it optional and accept plain text only.
- **Risks:** Bracketed-paste behaviour differs between CLI versions and busy states; the confirmation timeout can false-alarm on slow hooks. Must not auto-retry the Enter, since a duplicate submit is worse than an unsubmitted draft.

### Read-only 'review lens' with line comments that become prompts: for the selected session show `git diff` against the merge base (files list, unified view, +N -M on the card) computed ON DEMAND (when the view opens and once after each Stop event), with a bounded size; select lines and write a comment that is sent through the composer pipeline as 'In path:L12-L15: ...'. (cost L)

- **Inspired by:** Superset Changes pane, focus mode and 'comment straight to an agent' (diff-viewer.mdx, pull-requests.mdx, useSendToTerminalAgent.ts).
- **Gain:** Closes the review loop that is Loom's largest gap without turning Loom into an IDE: see what the agent changed, point at the exact lines, and get the fix in the same session. Diff stats on the card let the user triage which finished session to open first.
- **Fit:** Achievable within principles if git work is strictly event-driven and bounded: no file watchers, no status per workspace on a timer, only the visible or just-stopped session, one `git --no-optional-locks diff --shortstat`/`--numstat` with `-uno`/normal untracked mode (never `-uall`, issue #6004), a hard cap on files and lines, and cancellation when the user leaves. Superset's top complaints (#4198, #6729, #8108) are exactly the fan-out Loom must avoid. Native diff rendering must stay virtualised.
- **Risks:** Scope creep toward commit/PR/CI; keep v1 read-only plus comments. Large generated files and binary diffs need hard truncation. A line number can drift if the agent edits after the comment is written; include a short context snippet.

### Make the attention model robust against the classes of bug Superset hit: (a) count the Stop payload's background_tasks (and any running subagents) before showing 'finished', so a session with background work stays 'working'; (b) bind hook events to a session id plus launch identity and ignore events from nested or foreign sessions that inherit the environment; (c) keep the hook itself tiny and fast (no per-field process spawns, short timeout, never blocking the prompt) and have it be a no-op outside Loom sessions; (d) show 'delivered' vs 'submitted' vs 'finished' as separate verified outcomes. (cost S)

- **Inspired by:** Issues #8120, #8131, #8245, #6243; plans/agent-session-ownership.md; HOOKS_INVESTIGATION.md.
- **Gain:** Accurate 'needs you' and 'finished' signals are the reason to trust the sidebar at all. Wrong 'finished' on a session that still has background agents sends the user back too early, and a slow hook makes every prompt slower.
- **Fit:** Directly serves 'accurate status' and 'resilience to CLI updates'. The main check is to audit Loom's current hook and registry handling against these four cases (unverified: I did not read Loom). It adds no resources, only a few comparisons.
- **Risks:** The exact field names in the Stop payload (`background_tasks`) come from an issue quoting Claude's hook docs; verify against the installed CLI through Loom's drift detection and degrade gracefully if absent.

### Lightweight 'new session in a worktree': a card action and an optional field in the loom:open-session skill that creates `git worktree add <path> -b <branch>` for the project, opens the session there, copies a user-defined short list of ignored files (like .env), optionally runs a project setup command once in a visible terminal, and later offers a verified 'remove worktree and branch' that refuses on dirty or unpushed work and reports exactly what it removed. (cost M)

- **Inspired by:** Superset workspaces, setup scripts and archive-first delete lifecycle (WORKSPACE_DELETE_LIFECYCLE.md); the HN thread asking about DBs and ports.
- **Gain:** Lets the user run two agents on the same repo without collisions, which is the core reason people adopt Superset, with the project, colour and branch metadata Loom already shows. A per-project file in the repo (for example .loom/setup) would make it repeatable.
- **Fit:** Fits if it stays a thin layer: plain git, no watchers, no port allocation and no database orchestration (leave that to the user's script, as Superset itself does). Deletion must follow Loom's verified-outcome rule: dry run, refuse on dirty state, and report the final state. Check whether the Claude CLI already has its own worktree option and prefer it if documented (not verified). Conflict: a worktree creates a second cwd, so Loom's project grouping needs to map worktree paths back to the project.
- **Risks:** Disk use and orphan worktrees after crashes (Superset had a startup reconcile for interrupted deletes); path-reuse hazards when a branch is recreated; users expecting Superset's full automation of dependencies and ports.

### Quota-aware launch and multiple accounts: show remaining quota per account in the new-session picker and let a project or a session pick an account profile by pointing the CLI at a different CLAUDE_CONFIG_DIR. Loom already reads plan-limit windows through the CLI's get_usage control request, so the picker can read the same data per profile. (cost M)

- **Inspired by:** Superset Usage page (quota meters, Add account, default account) and the token-spend feedback analysis showing quota percentage beats raw tokens.
- **Gain:** Removes a manual step for heavy users with two subscriptions ('start the next task on the account with the most headroom') and helps avoid hitting a limit in the middle of a long run. Fills a listed Loom gap (multiple accounts).
- **Fit:** Good fit: no polling (read on picker open and on a coarse timer only while visible, or from the existing FSEvents-based flow), no new service. Honest status rule: show 'unknown' for plans that do not expose limits. Constraint: CLAUDE_CONFIG_DIR profiles share or separate settings, skills and history in ways that must be verified per CLI version, and Superset notes that one conversation history is shared across accounts.
- **Risks:** Credential handling and ToS sensitivity (do not read credentials Loom does not need); a profile switch must apply only to new launches, as Superset also states for running agents.

### Authenticated cross-session read/send channel with verified outcomes: `loom:read-session` and `loom:send-to-session` skills over the existing authenticated socket, where the user approves each target and the result is reported as 'delivered' and later 'submitted' (confirmed by the hook), never as bare success. (cost M)

- **Inspired by:** Superset `terminals read|send`, `agents create`, the orchestrate skill and MCP server, and issue #6243 (delivered is not submitted).
- **Gain:** Lets a coordinator agent hand work to another open session, or ask what a sibling session found, without the user copy-pasting between cards. This is the planned cross-session channel, with Superset showing both the demand and the main failure mode.
- **Fit:** Matches 'cross-session actions only under the user's authority' and Loom's authenticated socket, which is stricter than Superset's unauthenticated local hook endpoint. Keep each approval scoped (this source, this target, this action) and rate-limited. Skip Superset's cloud-dispatch and relay parts entirely.
- **Risks:** Prompt-injection chains between sessions (a message from one agent steering another); the approval UI must show the exact text and the source session, and reads must be bounded.

### Do NOT copy: a daemon that survives Quit, per-workspace watchers/pollers, an lsof port scanner, and cloud automations. For ports, offer on-demand 'what is listening in this session's process tree' (libproc on the run scope's pids) only while the popover is open. For scheduled work, if ever built, run only while Loom is open at login, and say 'missed' honestly instead of promising cron semantics. (cost S)

- **Inspired by:** Superset pty-daemon and its issues (#7977, #5792, #8029, #6610); port-manager.ts (2.5 s lsof scan, 30 s idle); git-watcher.ts; automations.mdx limits.
- **Gain:** Avoids importing Superset's reliability and CPU problems. The practical gain is a clear, defensible line for what Loom will not do, and a cheap port view that is useful without a scanner.
- **Fit:** Directly consistent with 'no polling', 'process ownership' and 'Quit stops all sessions'. Resume of the same conversation already covers most of what the daemon is used for, without orphan processes. The cost is that a long-running job dies when the user quits; the ended screen and resume are the mitigation.
- **Risks:** Some users will want sessions to survive Quit (Superset's most praised feature). If that demand shows up, a separate opt-in helper with its own tests would be a different, much larger decision.

### Corrections

- Do not state that Claude Code sessions outside Superset show 'Hooks Stop' noise: HOOKS_INVESTIGATION.md lists Claude Code's hook as guarded; the documented leaks are Droid (unguarded path) and Grok (#8375, unset ${SUPERSET_HOME_DIR}).
- Do not present the '12.8 s per UserPromptSubmit' hook cost as typical: it is one machine's measurement, and the issue says the isolated runs did not reproduce the 30 s timeout and the reason is not established.
- Do not present '50x' for git status -uall as general: it is one reporter's number on a 61k-file repo. My test on a 30k-file synthetic repo showed about 3x (0.03 s vs 0.01 s).
- Ring buffer 'not settled' is resolved: the pty-daemon ring is 64 KiB (SessionStore) and the host-service catch-up ring is 2 MiB (terminal.ts CATCHUP_RING_CAP_BYTES). The plan doc's 64 KiB FIFO is the old host-service state.
- Pricing: cite superset.sh/pricing, not the competitor page. Pro is $20 per user per month, $15 when billed yearly ($180/yr), and includes remote access, automations, Linear, Slack, mobile. Free includes the CLI and desktop app with local workspaces.
- The Stop-payload field background_tasks is documented in Claude Code's official hooks reference (Stop and SubagentStop inputs, plus session_crons), so Loom can rely on it as a documented field; the report's caveat 'comes from an issue quoting the docs' can be dropped. The Superset fix (PR #8114) is still open, so the bug remains on main.
- The Product Hunt count (512), the 30-contributor count and the ~4,960 commit count remain unverified secondary data; do not use them for decisions.
- Cited HN item 48237245 is a single comment, not a thread; it expresses 'terminal-centric vs chat-centric' and praises per-task organisation and visual diffs, not specifically the daemon. The daemon claim comes from the founder's reply (sibling comment 48239812's neighbour 48237414).

### Missed by the report

- Billing and policy context: Anthropic's support article 'Use the Claude Agent SDK with your Claude plan' (support.claude.com/en/articles/15036540) says the June 15, 2026 split of Agent SDK, `claude -p` and third-party app usage from subscription limits was PAUSED (nothing changed), and on October 7, 2026 Max and Team plans got monthly API credits covering Agent SDK, `claude -p`, API and Managed Agents, while SDK / `claude -p` / third-party apps can still draw on subscription limits. A June HN comment (item 48126438 thread, quoted at 48239812) claiming Conductor usage is metered as 'programmatic usage' is therefore outdated. This matters because Superset's chat v3 uses the Agent SDK (query() with pathToClaudeCodeExecutable) while Loom drives the real CLI; the report never states this billing distinction.
- The Stop payload contract: Claude Code docs (code.claude.com/docs/en/hooks, 'Stop input') say background_tasks and session_crons arrays let hooks tell 'session is done' from 'paused waiting for background work'; they are present when the task registry is reachable and empty when nothing is in flight. Superset's open PR #8114 only counts background subagent and workflow tasks, ignoring shells, monitors and teammates because they can stay running indefinitely. The report lists the field but not this filtering rule, which is a design hint for Loom's status logic.
- TerminalAgentBinding already has backgroundTasks and queuedPrompts fields (packages/host-service/src/terminal-agents/types.ts), apparently used for chat sessions; the notify hook template does not forward background_tasks for terminal sessions.
- Pricing page also shows Enterprise (SOC 2 Type II, SAML SSO/SCIM, audit logs) and says Free is limited to 1 user.
- HOOKS_INVESTIGATION.md lists recommended mitigations (project-level .claude/settings.json in worktrees, env-scoped config, removing global entries on uninstall) which show Superset itself considers global hook registration a weakness; the report cites the problem but not their own proposed remedy.
- Release asset counts: several releases are far below the report's '15k floor' (v1.34.0 has 1,287), and counts include updater fetches, as the report already warns.
