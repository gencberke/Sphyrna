# cmux (manaflow-ai/cmux)

Research note for the Loom v2 brainstorm ([index](../V2-BRAINSTORM.md)). Written by a research subagent on 2026-10-17 and fact-checked by a second one; the fact-check is at the end and wins over the report where they differ. Raw JSON: `../evidence/deep-dive-20261017.json`.

**In one line:** Native Swift/AppKit macOS terminal on libghostty with a vertical workspace sidebar, hook-driven per-agent status and notifications, an inline approval feed, a socket/CLI control plane and a scriptable browser pane. It is the closest sibling to Loom, and also a cautionary tale: fast feature growth followed by long-running CPU, memory and restore failures.

**Category:** terminal-first (with a beta chat lens and a paid cloud/iOS tier growing around it)

Latest stable v0.65.2 (2026-10-16); roughly 25 stable releases since 0.63.2 (2026-04-06) per CHANGELOG.md. Show HN on 2026-02-19 reached #2 (thread: 198 points, 77 comments; https://news.ycombinator.com/item?id=47079718, https://cmux.com/blog/show-hn-launch). Endorsements on cmux.com from Mitchell Hashimoto, Peter Steinberger, Nick Schrock. A July 2026 comparison cites 25.1k stars (https://blog.debedb.com/2026/07/26/herdr-and-cmux-two-shapes-of-the-same-agent-multiplexer/), so growth slowed to about 3k stars in 12 weeks. Retention is mixed: r/cmux users report leaving for Herdr or Orca over CPU/memory (https://www.reddit.com/r/cmux/comments/1vhtfwq/is_cmux_resourcehungry_or_am_i_doing_something/), while a two-month comparison still picks cmux for local Mac work (https://coles.codes/posts/herdr-vs-cmux/).

## Architecture

Stack: Swift + AppKit/SwiftUI; libghostty (GhosttyKit submodule) renders terminals; WKWebView browser panes; about 60 local Swift packages under Packages/macOS; a Go remote daemon (daemon/remote); a Bun/TypeScript agent-chat sidecar (agent-chat/); web/ and Cloud services; an iOS app (ios/). Repo snapshot read: commit 3e7ed5a (2026-10-17). Monolith files: Sources/ContentView.swift is 18,385 lines, CLI/cmux.swift 46,139, Sources/AppDelegate.swift 20,958, Sources/TerminalController.swift 17,189, Sources/TerminalNotificationStore.swift 3,099.

How it drives agents: it does NOT use stream-json, the Agent SDK or ACP for the main terminal path. Real CLIs run in real Ghostty PTYs. A 2,459-line bash wrapper, Resources/bin/cmux-claude-wrapper, sits in PATH ahead of claude and execs it with --session-id and --settings carrying injected hooks (PermissionRequest timeout 125 s, sync; SessionStart/Stop/UserPromptSubmit/Notification timeout ~5-10 s; an async asyncRewake inbox-wait hook with timeout 86400). The user's own --settings are folded in. For Codex it edits ~/.codex/hooks.json or passes -c hooks.* flags, and for 15+ other agents it writes their hook or extension files (cmux hooks setup).

State detection is told, not inferred. Hooks call the cmux CLI, which talks over a Unix socket (peer-PID descendant check in Sources/TerminalController+SocketClientCapability.swift; Packages/macOS/CmuxControlSocket). Each terminal gets CMUX_SURFACE_ID/CMUX_WORKSPACE_ID env as the binding key; fallbacks are tty-to-surface and process-tree matching (docs/agent-session-tracking-spec.md, which also declares the principles: deterministic binding, no title or mtime heuristics, owned-process exit as backstop, transcript tail to correct a stuck Working). Mapping: userPromptSubmit/preToolUse/postToolUse -> working; permissionRequest/askUserQuestion/exitPlanMode/notification -> needsInput; stop -> idle; subagentStop -> unchanged; sessionEnd -> ended. Hook records land in ~/.cmuxterm/<agent>-hook-sessions.json. Other signals: OSC 9/99/777 notifications and OSC 7501 program status.

Persistence: session snapshot JSON autosaved every ~8 s (Sources/AppDelegate.swift, previous snapshot rotated to session-com.cmuxterm.app-previous.json); a Feed audit log at ~/.cmuxterm/workstream.jsonl; events at ~/.cmuxterm/events.jsonl; a SQLite FTS5 index for global search (Sources/Search/SearchIndex.swift). On relaunch it respawns each agent with its native resume command (sanitised launch flags). Agents live in the app's process tree, so an app crash or force-quit kills them; a tmux-backed option (cmux local-tmux) keeps them alive.

Resource notes: ports are scanned by kernel process-table reads in coalesced bursts triggered by shell 'kick' messages (Sources/PortScanner.swift). Branch/PR info comes from per-shell zsh/bash watcher loops plus a shared in-app GitHub PR poller. The sidebar uses a LazyVStack of Equatable rows with immutable snapshots (Sources/ContentView.swift:14443, TabItemView at :16093) and a 1 Hz TimelineView for custom sidebars (:13013). Agent Hibernation runs a 30 s repeating DispatchSourceTimer when enabled (Sources/App/AgentHibernationController.swift:178). The Claude inbox hook polls roughly every 2 s (docs/agent-messages.md).

## Core loop

Typical day: open a workspace per task (often a git worktree the agent created itself) with one or more Claude/Codex terminals plus a browser split on the dev server. The sidebar row shows branch, PR, cwd, ports and the latest notification text. Fire off prompts and move on. When an agent needs you, the pane gets a blue ring, the row gets a badge and a macOS banner appears (with inline Allow/Deny, option buttons or a typed reply). Press Cmd+Shift+U to jump to the latest unread; Ctrl+Cmd+U cycles to the next. Approve in the Feed (right sidebar, Ctrl-4) or in the banner, and focusing a pane marks it read. Use Cmd+Shift+P (palette), Cmd+1..8 for workspaces, Cmd+Opt+F for global search over transcripts and scrollback, the Vault for old sessions (search, resume, fork), Cmd+D splits, and the diff viewer for review. Scripting is layered on top: .cmux/cmux.json commands and layouts, the cmux CLI/socket, hooks and automations. On relaunch or reboot, agents are auto-resumed (with known failure modes). Heavy users add Cloud VMs or the iOS app.

## Features

### Notification rings, unread model, jump-to-latest-unread and notification panel (attention-status, confidence high)

- **What the user sees:** A blue ring on the pane that needs attention, a badge and the latest message text on the sidebar row, a Dock badge, a notifications panel/popover and a macOS banner. Cmd+Shift+U jumps to the most recent unread; Ctrl+Cmd+U marks the current item as oldest-unread and jumps to the next one. Focusing a pane marks its notifications read. There are mark-read/unread swipes, a 'Mark Workspace as Read' command, and settings to suppress banners for the focused surface or while the app is frontmost.
- **How it works:** Sources/TerminalNotificationStore.swift (3,099 lines) holds the records, several unread kinds (manual, panel-derived, restored) and per-workspace indexes. A separate SidebarUnreadModel (~line 278) is a coalesced, equality-guarded projection so notification churn does not re-render the sidebar; its comment names issue #2586. The ring is a static CAShapeLayer on the terminal view (Sources/GhosttyTerminalView.swift ~10601-10965). Banners go through UNUserNotificationCenter. Hooks in cmux.json (notifications.hooks) get a JSON envelope on stdin with an agent object (kind, category turn-complete|needs-permission|idle-reminder, pending, isSubagent) and can switch effects (record, desktop, sound, command, paneFlash) off.
- **Reception:** The most praised feature on cmux.com and in the Show HN thread; a typical quote: notification when a terminal waits for input is the reason to switch. Complaints: recency-based reordering of workspaces changed the shortcut numbering (HN, issue #205, fixed by an opt-out); 'weird popup' banners on workspace switch (issue #923); acknowledged-notification dismissal bugs (fixed in 0.65.2 #20547).
- **Evidence:** docs/notifications.md; Sources/TerminalNotificationStore.swift:278; Sources/GhosttyTerminalView.swift:10601; README.md (Features); https://cmux.com/blog/show-hn-launch

### Rich sidebar metadata and a writable status API (attention-status, confidence high)

- **What the user sees:** Each workspace row shows branch, linked PR number/state, cwd, listening ports, the latest notification text, agent spinner, and optional status pills, progress bars and log lines set by scripts or agents (cmux set-status, set-progress, log). A 'compact agent status' mode collapses the row to one glyph for the loudest state: error, needs input, running through subagents, waiting on a background command/scheduled wakeup/CI, running, starting, unread, PR open/merged/closed, idle, branch. The glyph shows only PR open/merged/closed, never CI results.
- **How it works:** Ports: shell integration sends report_tty + ports_kick over the socket; Sources/PortScanner.swift coalesces for 200 ms then runs a burst of 6 kernel-table scans with no subprocesses. Branch/PR: zsh/bash integration (Resources/shell-integration/cmux-zsh-integration.zsh) runs watcher loops and sends report_git_branch/report_pr; there is also a shared in-app GitHub PR poller. The CMUX_NO_GIT_WATCH=1 opt-out exists because of 'sleep' process churn and security-agent audit volume on managed Macs (docs/shell-integration.md). The spinner is compositor-driven; the compact-mode pulse is a Core Animation opacity loop capped at 30 Hz that stops when occluded or on Reduce Motion (docs/configuration.md).
- **Reception:** The sidebar is the reason people switch from Ghostty. It is also where the worst performance bugs landed: issue #2487 (65-101% CPU with many workspaces; hiding the sidebar dropped it to ~5%), where every metadata update recomputed all rows through a merged ~19-signal publisher.
- **Evidence:** docs/configuration.md#sidebarcompactagentstatus; https://cmux.com/docs/api (Sidebar metadata commands); Sources/PortScanner.swift; docs/shell-integration.md; docs/subagents-panel-plan.md (t3code-style fixed-shape rows)

### Feed: inline permission / plan / question approvals (attention-status, confidence high)

- **What the user sees:** A right-sidebar queue (Ctrl-4) of every agent's pending permission requests, ExitPlanMode decisions and AskUserQuestion prompts. Choices include Once / Always / All tools / Bypass / Deny, and plan choices Ultraplan / Manual / Auto. The same choices appear as buttons in the macOS banner, with 'Other...' typed replies and one button per question option; typed replies on turn-complete banners also work. Double-click a row to jump to the terminal.
- **How it works:** Claude's PermissionRequest hook (sync, timeout 125 s) runs 'cmux hooks feed --source claude'. The CLI forwards a feed.push socket frame; FeedCoordinator (Sources/Feed/FeedCoordinator.swift) parks the hook on a semaphore keyed by request_id (up to 120 s); the decision comes back as feed.permission.reply and the hook prints the agent's decision JSON. Banner buttons use UNNotificationAction / UNTextInputNotificationAction (FeedCoordinator.swift ~1585-1640). Soft-wait: on timeout it emits {} and the agent falls through to its own TUI prompt. Always/Bypass use the agent's suggested permission rules or setMode, which is why the wrapper launches Claude with --allow-dangerously-skip-permissions. Codex hooks stay telemetry-only because Codex runs approval hooks before its own auto-reviewer. Events are kept in a 2,000-item ring plus ~/.cmuxterm/workstream.jsonl.
- **Reception:** Cited as the thing that makes a human-as-scheduler workflow work (https://blog.debedb.com/2026/07/26/herdr-and-cmux-two-shapes-of-the-same-agent-multiplexer/). Open bugs: Feed panel main-thread hang on open (#4034); a blocking feed.push held a control-socket slot (fixed in 0.65.1).
- **Evidence:** docs/feed.md; Sources/Feed/FeedCoordinator.swift; Resources/bin/cmux-claude-wrapper:2017,2067; CHANGELOG.md 0.64.23 (inline banner replies)

### Socket + CLI control plane, reconnectable event stream (automation, confidence high)

- **What the user sees:** Every action exists as a CLI command and a v2 JSON socket method: workspaces, splits, send text/keys, read screen, notify, browser, sidebar metadata, 'cmux identify', 'cmux capabilities', and 'cmux current' / 'Find Work' (workspaces, agents, attention, PRs). 'cmux events --cursor-file ... --reconnect' streams model events; the CLI explains CLI/app version skew instead of printing method_not_found.
- **How it works:** Unix socket at ~/.local/state/cmux/cmux.sock (older docs: /tmp/cmux.sock). Access modes off / cmuxOnly (peer PID must descend from the cmux process via LOCAL_PEERPID) / allowAll. Remote relay is deny-by-default (RemoteRelayCommandPolicy). Events carry a monotonically increasing seq and a boot_id; after restart, stale cursors get a resume-gap marker; frames are mirrored to ~/.cmuxterm/events.jsonl. Categories: window, workspace, pane, surface, notification, feed, agent (agent.hook.<HookEventName>), program_status.
- **Reception:** Community builds on it (pi-cmux extension, k1Low/mo, skills). Cost of the approach: control-socket stalls under agent load (#5757, #4917, fixed piecemeal), and dispatch_sync to the main thread deadlocked every CLI command when the UI was stuck (#2586).
- **Evidence:** https://cmux.com/docs/api; docs/events.md; docs/cli-contract.md; Sources/TerminalController+SocketClientCapability.swift; AGENTS.md (Remote CLI relay)

### cmux.json: custom commands, action registry, workspace layout recipes, automations (automation, confidence high)

- **What the user sees:** Per-project .cmux/cmux.json (searched upward) and ~/.config/cmux/cmux.json define palette commands (shell command, confirm flag, keywords) and 'workspace' recipes: a tree of splits holding terminals and browsers with cwd, env, color, setup command and restart policy (new / confirm / recreate / ignore). A nightly action registry binds actions to shortcuts and tab-bar buttons. Separately, ~/.cmuxterm/automations.json holds event rules: when an event matches (agent.needs_input and so on) and where filters hold, then notify / rpc / run / webhook, with rate limits, a loop guard and a dry-run (cmux automation test).
- **How it works:** Schema-validated JSON, applied live (Cmd+Shift+,), with fallback to the next valid config plus a 'Schema Error' palette row. Automations run in Sources/AutomationEngine.swift; run actions get an owned process group with a 60-300 s timeout; webhooks refuse credential headers over HTTP and strip them on cross-origin redirects; rules already in the firing chain are skipped.
- **Reception:** Positive among power users ('primitives, not a solution'; the Zen of cmux in README.md). Adds surface area and many settings; cmux config doctor exists to validate them.
- **Evidence:** https://cmux.com/docs/custom-commands; docs/automations.md; Sources/AutomationEngine.swift

### Agent Hibernation (idle agents cost nothing) (other, confidence high)

- **What the user sees:** Opt-in (and always-on as a safety net under memory pressure): background, idle agent terminals are killed and replaced by a lightweight placeholder with a Resume button; visiting the tab runs the native resume command. Defaults: maxLiveTerminals 12, idleSeconds 5, confirmation window ~60 s. 'cmux agent hibernate|wake surface:3' works manually. After a wake, the tab shows a banner with Retry / Show command if the agent does not come back within 90 s.
- **How it works:** Planner (Sources/App/AgentHibernationPlanner.swift) picks the oldest-idle candidates beyond the live limit; Controller (Sources/App/AgentHibernationController.swift) samples the terminal tail plus a process fingerprint and cancels on any change; it sends SIGTERM to the agent's process group scoped to workspace and surface. Eligibility requires hooks to have captured a resume command, an idle lifecycle, no unsent input and no background work. Background work is detected by scanning up to 32 MiB of the Claude transcript tail for backgroundTaskId, async_launched and <\task-notification> markers (Sources/App/AgentHibernationTranscriptGuard+BackgroundWork.swift) plus a process-scope check. Pressure triggers: macOS critical pressure held 120 s, the app footprint reaching 16 GiB, or aggregate use over 50% of RAM. A 30 s repeating timer runs while enabled.
- **Reception:** Introduced because of the memory crisis (#5731). In practice it rarely fires for Claude: idle_prompt notifications arriving ~60 s after every reply were classified needsInput (#14308), and restored sessions stay 'running' until their next Stop (#13024). Users ask for a manual 'Sleep' action that stays asleep (#9873) and a render-only suspend tier (#5497).
- **Evidence:** docs/agent-hooks.md#agent-hibernation; Sources/App/AgentHibernationController.swift:178; Sources/App/AgentHibernationTranscriptGuard+BackgroundWork.swift; https://github.com/manaflow-ai/cmux/issues/14308; https://github.com/manaflow-ai/cmux/issues/13024; https://github.com/manaflow-ai/cmux/issues/9873

### Session restore and agent auto-resume (other, confidence high)

- **What the user sees:** After relaunch or reboot, windows, workspaces, splits, cwd, scrollback and browser state return, and Claude/Codex/etc. terminals run their native resume command (claude --resume <id>) automatically (setting terminal.autoResumeAgentSessions). cmux session move transfers a stopped Claude session, with its git checkout, to an SSH host. cmux recover and the Vault list interrupted sessions.
- **How it works:** Hook events write per-agent session records (session id, surface id, cwd, pid, lifecycle, sanitised launch command) to ~/.cmuxterm/<agent>-hook-sessions.json. The sanitiser keeps model/sandbox/config/cwd flags and drops prompts, credentials, old session selectors and non-interactive commands (docs/agent-hooks.md). Surface ids are persisted and reused on restore; workspace ids are re-minted, so surface id is the binding key. Resume bindings set through the CLI/socket need user-approved signed command prefixes.
- **Reception:** Persistent weak spot. Examples: multiple sessions not restored (#4782: only one 'active' Claude session per workspace could keep its binding); on macOS 27 after a reboot 3 of 4 worktree sessions did not resume (resume cd'd into the repo root instead of the session cwd, and reused PIDs blocked restore; #19306); a fatal crash killed ~20 sessions and the next launch silently skipped restore, leaving the state in a -previous file (#9825); a partial restore overwrote the good snapshot after a power loss; closed tabs left claude processes alive because the SessionEnd hook had a 1 s timeout (#9573).
- **Evidence:** docs/agent-hooks.md; docs/agent-session-tracking-spec.md; https://cmux.com/docs/session-restore; https://github.com/manaflow-ai/cmux/issues/4782; https://github.com/manaflow-ai/cmux/issues/19306; https://github.com/manaflow-ai/cmux/issues/9825

### Terminal chat view and agent chat (beta) (chat-input, confidence high)

- **What the user sees:** Command palette 'Open terminal as chat' renders a Claude or Codex session that is already running in a terminal as a chat (turns, tool calls, thinking). The composer types the prompt into that terminal agent and Stop/Esc interrupts it. Permission prompts, questions and pickers stay in the terminal. 'New agent chat' starts a chat-native session in a browser surface; each chat is its own workspace tab, so the sidebar is the session list. A separate TextBox composer under terminals is also available. This is behind the feature flag isAgentChatUIEnabled.
- **How it works:** agent-chat/ is a Bun sidecar serving a React app on a loopback port behind an unguessable token path. For the terminal view it looks the surface up in the hook session stores, tails the agent's own transcript (Claude projects/<slug>/<session>.jsonl, Codex rollout files) and normalises it into AgentEvents (agent-chat/adapters/transcript.ts). Input is sent with mobile.chat.send (bracketed paste and submit) over the control socket, and the optimistic prompt is replaced by the transcript's own copy once it lands. Chat-native sessions use adapters: persistent 'claude -p --input/output-format stream-json', 'codex app-server' (JSON-RPC), 'pi --mode rpc', and generic ACP. Colours come from the Ghostty config. The sidebar deduplicates nothing here: it is a second UI over the same PTY.
- **Reception:** Still beta and flagged; no strong public reception found. The iOS app uses the same chat model and hook-driven session registry (docs/agent-session-tracking-spec.md).
- **Evidence:** agent-chat/README.md; Sources/ContentView+AgentChatCommandPalette.swift; Sources/TerminalController+MobileChat.swift; CHANGELOG.md 0.65.1 (agent chat panes notify when a turn finishes)

### Agent messages (cross-session channel) (orchestration, confidence high)

- **What the user sees:** 'cmux agent message <workspace> "text"' sends text from one agent or person to the agent in another workspace. 'cmux agent inbox' lists messages (queued -> delivered -> read, or failed). It can be disabled globally, per agent or per workspace.
- **How it works:** Delivery goes through the recipient's own hooks, never by typing into the terminal, so it cannot land in a half-typed prompt or press Enter. Claude: an async asyncRewake hook checks about every 2 s, opening a short socket connection each time; an idle session wakes with the message as a system reminder, a busy one sees it at its next step, and a submitted prompt gets it as context. Codex hooks cannot wake an idle session, so it waits for the next hook. Delivery is held while the recipient waits on a human. The recipient sees a framing line that the message is not an instruction from its operator. Bodies are text-only, 32 KiB max, control characters rejected; 1,000 per-surface settings and 2,000 read messages are kept (Sources/AgentMessageCenter.swift; docs/agent-messages.md). It is also exposed over the socket (agent.message.send|list|claim|ack|mark_read|poll|settings).
- **Reception:** New (the changelog places it in 0.64.x/0.65); no review found. The idle inbox-wait hook leaked memory (fixed in 0.65.1).
- **Evidence:** docs/agent-messages.md; Sources/AgentMessageCenter.swift; Resources/bin/cmux-claude-wrapper:2063; CHANGELOG.md 0.65.1 (memory growth in idle inbox-wait hooks, #18632)

### claude-teams: Claude Code teammates as native splits (orchestration, confidence high)

- **What the user sees:** 'cmux claude-teams' launches Claude Code in teammate mode; teammates spawn as native cmux splits with sidebar metadata and notifications, without installing tmux. Codex Teams does the same for Codex app-server subagents up to depth 2.
- **How it works:** CLI/cmux.swift (claude-teams, ~line 6726 and 26954): sets CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1, defaults teammate mode to auto, prepends a private tmux shim to PATH that translates tmux window/pane commands (split-window, send-keys, ...) into cmux socket operations, and patches NODE_OPTIONS (a restore module). The Codex variant starts a private codex app-server on localhost and a watcher (CodexTeamsAppServerProcess.swift). Plain Claude subagents (Task/Agent tool) are NOT teammates: cmux tracks them only as approximate child-run bookkeeping from PreToolUse/SubagentStop (Sources/Mobile/AgentChat/AgentChatSessionRegistry+ChildRuns.swift, which admits a FIFO fallback when ids are missing). docs/subagents-panel-plan.md says there is no first-class subagent tree.
- **Reception:** Marketed on the README; depends on an experimental flag and tmux-compat emulation, with fixes such as tmux compat commands failing with rate_limited (#12832) and OMO pane respawn issues. Loom's subagent tree (running rows with elapsed time and a live transcript panel) is stronger than cmux's for plain subagents.
- **Evidence:** CLI/cmux.swift:21707; CLI/cmux.swift:26954; Sources/Mobile/AgentChat/AgentChatSessionRegistry+ChildRuns.swift; docs/subagents-panel-plan.md; README.md

### Scriptable in-app browser pane (browser-preview, confidence high)

- **What the user sees:** A browser split beside the terminal. Agents can navigate, snapshot the accessibility tree with element refs, click, fill, evaluate JS and read console/network via 'cmux browser'. It can import cookies/history from 20+ browsers so panes open signed in, and an iOS Simulator pane exists too. It renders HTML files on Cmd-click and has multiple profiles.
- **How it works:** WKWebView panes (Packages/macOS/CmuxBrowser) with a command surface ported from vercel-labs/agent-browser (docs/agent-browser-port-spec.md). Surface-bound commands need explicit --surface handles and never infer focus (skills/cmux-browser/SKILL.md).
- **Reception:** Called the better browser versus Herdr's plugin (https://coles.codes/posts/herdr-vs-cmux/). It also dominates the memory complaints: in issue #5731 the audit found 166 browser panes all rendering, with a ~3.7 GB WebKit tree across 263 processes; the memory master issues #4188 and #2962 also include WebView growth.
- **Evidence:** README.md; docs/agent-browser-port-spec.md; skills/cmux-browser/SKILL.md; https://coles.codes/posts/herdr-vs-cmux/

### Vault, global search, Fork Conversation and checkpoints (context-knowledge, confidence medium)

- **What the user sees:** A session index with a recency-first All Sessions view, status dots and filters. Search operators include agent:, repo:, ws:, before: and after:. Cmd+Opt+F global search finds text in open Claude/Codex transcripts and in terminal scrollback, and Return opens the match. Right-click Fork Conversation opens a branch of the session in a new split, tab or workspace. Checkpoints support fork-from-checkpoint (cmux vault fork).
- **How it works:** Sources/Search/SearchIndex.swift is a SQLite actor with an FTS5 table (chunks_fts) fed by transcript and scrollback documents. Fork launches the agent's own fork command (Claude --fork-session is recognised in Sources/CachedAgentProcessIdentityValidator.swift:225). Agents are registered through vault.agents in cmux.json with detect, sessionIdSource, resumeCommand and forkCommand templates (docs/vault.md).
- **Reception:** Well received feature requests (e.g. #4927 'park a workspace' wants zero live cost plus searchable titles). Vault sidebar beachball at large session counts was fixed in 0.64.21.
- **Evidence:** Sources/Search/SearchIndex.swift; docs/vault.md; CHANGELOG.md 0.64.23, 0.65.1 and 0.65.0; https://github.com/manaflow-ai/cmux/issues/4927

### Diff viewer with review comments handed to the agent (review-git, confidence medium)

- **What the user sees:** A diff viewer window with a branch-base picker, per-repo review comments on changed lines, viewed-file tracking, filters, collapsed generated/large diffs, Cmd+F, and lazy syntax grammars. The comment set can be attached to the terminal TextBox to hand to an agent.
- **How it works:** Native diff view (Packages/macOS/CmuxDiffComments, CmuxGit). Details beyond the changelog were not read.
- **Reception:** No direct reception found; the reviewr comparison suggests the 'since the agent's last turn' diff scope is what users actually want.
- **Evidence:** CHANGELOG.md 0.64.15 (#5768 review comments), 0.65.0 (#15536, #15576); https://coles.codes/posts/herdr-vs-cmux/ (Herdr's reviewr plugin offers a 'last turn' diff scope that cmux lacks)

### SSH workspaces, Cloud VMs and the iOS companion (remote-mobile, confidence medium)

- **What the user sees:** 'cmux ssh host' makes a remote workspace with a bundled daemon that keeps terminals alive across reconnects, SSH agent forwarding, browser panes routed through the remote network, and scp image drag. Also 'cmux ssh-tmux' and mosh. Pro users get Cloud VMs; the iOS app (TestFlight beta) mirrors terminals, notifications and chats. Another Mac under 'My Devices' can mirror workspaces.
- **How it works:** Go remote daemon (daemon/remote, Packages/macOS/CmuxRemoteDaemon), iroh-based transport and relay workers, and an iOS app sharing the registry/versioned-pull model in docs/agent-session-tracking-spec.md. Not read in code depth.
- **Reception:** Strongly marketed, but remote support was the reason one reviewer left for Herdr before cmux's daemon landed in June (https://coles.codes/posts/herdr-vs-cmux/). A fatal crash on 'system.top' recursion killed all sessions (#9825).
- **Evidence:** https://cmux.com/ (FAQ); https://cmux.com/pricing; docs/remote-daemon-spec.md; CHANGELOG.md 0.65.0

## UX patterns worth borrowing

- Single attention shortcut pair: jump to the latest unread (Cmd+Shift+U) and a 'snooze to oldest, go next' cycle (Ctrl+Cmd+U); focusing a view marks it read, so there is no separate dismiss step.
- The sidebar row's third line is the last notification text (what the agent said or asked), not just a status word; the row tooltip carries the full preview. This beats Claude's generic 'waiting for your input' body, which was the origin of cmux.
- Compact status mode: one glyph for the loudest state (error > needs input > running via subagents > waiting on background/CI > running > starting > unread > PR/branch > idle), modelled on the Claude desktop session list. Pulse animation capped at 30 Hz via Core Animation, stopped when occluded or with Reduce Motion.
- Fixed-shape rows (identity line, activity line, metrics line) and a collapsed status vocabulary, borrowed from t3code (docs/subagents-panel-plan.md): changing data never changes row height, and all in-flight states share one steady colour.
- Right-sidebar 'Feed' as a unified decision queue across all agents, mirrored as banner buttons (Allow once, Deny, option labels, 'Other...' text field), with a soft-wait of ~120 s before falling through to the agent's own prompt.
- Command palette whose entries come from config (cmux.json commands/actions), including 'Find Work' (workspaces, agents, attention, PRs), 'Go to Workspace' ordered by recent focus (opt-in), and per-tab actions such as Turn Off Agent Messages.
- Scrollbar markers for each submitted agent prompt (click to jump), 'jump back to the pane where you last sent a prompt' (Cmd+Shift+B), and Cmd+[ / Cmd+] focus history. The earlier agent turn rail was removed because its 16 pt gutter misaligned terminal text (PR #20060).
- Groups with an anchor workspace, pinned top-level rows, per-workspace colour and description, Cmd+Shift+T reopen closed item, and a 'Click by Hint' keyboard overlay (beta).
- Declarative workspace recipes: one JSON tree of splits, terminals and browsers with cwd/env/setup and a restart policy.
- Reconnectable event stream with seq + boot_id + cursor file, and an append-only JSONL audit log of everything; hooks and automations consume it.
- Resume failure is visible: a 'did not resume' banner with Retry / Show command, and the sidebar row says so.

## Anti-patterns

- Sidebar rows subscribed to a merged observation publisher or an observable store caused a never-settling SwiftUI layout loop at 100% of a core and 1.7-8.9 GB RSS (#2586 on 2026-04-04, still recurring on 0.64.12-0.64.20 as #8843 and #2487). cmux's own fix rule: below a LazyVStack/ForEach boundary, rows get immutable value snapshots plus closures, never an ObservableObject/@Observable; rows are Equatable with .equatable(); and no state mutation from body (skills/cmux-debugging/references/runtime-pitfalls.md). Loom should adopt this as a written rule and a test.
- Eager per-workspace resource creation: the master issue #5731 measured a 128-workspace session at ~22 GB RSS: 112 live Ghostty surfaces (a four-thread set each), 3.3 GB IOSurface, 166 browser panes all rendering, ~60 agents respawned within 70 s of launch, and a session snapshot autosaved every 8 s on the main thread. Lesson: idle records must be data, not views or processes. Loom's no-live-terminal-for-idle-records rule already avoids this; keep it.
- Polling in many places: per-shell sleep loops for git/PR (managed Macs complained about audit volume), a 1 Hz TimelineView for custom sidebars, a 30 s hibernation timer, a ~2 s hook poll for messages, an idle hook with memory growth, and 'openThread' loops that burned ~90% of idle CPU (fixed in 0.64.21). Loom's no-polling rule should stay a hard gate.
- Wrapping the CLI with a 2,459-line bash shim in PATH plus env hacks (NODE_OPTIONS, --allow-dangerously-skip-permissions, --settings merging, a tmux shim). It produced a 100% CPU wrapper loop with custom Claude paths and a 1 s SessionEnd timeout that leaked claude processes (#9573). Loom owns the launch, so it should keep injecting only documented flags and hooks.
- Inferring state from notification types: Claude's idle_prompt, sent ~60 s after every unanswered reply, was mapped to needsInput, so finished chats looked blocked and could never hibernate (#14308). Restored sessions were stuck at running until their next Stop (#13024). Only real blockers (permission, question, plan) should be 'needs you'.
- Decorating the real terminal's geometry (the turn-rail gutter shifted text 16 pt) was reverted (PR #20060). Keep decoration outside the PTY view.
- Restore degrading silently: skipping restore after a crash and leaving the state in a -previous file (#9825); a partial restore overwriting a good snapshot (comment on #9825); resume landing in the repo root instead of the worktree (#19306); stale pid reuse blocking restore.
- Reordering rows by recency changes shortcut numbering, a cognitive burden (HN feedback; issue #205 became an opt-out). Keep Loom's Active section ordering predictable and make jump shortcuts independent of position.
- Monolith source files (ContentView.swift 18k lines, CLI/cmux.swift 46k, AppDelegate 21k) next to a very wide product (terminal, browser, simulator, computer use, cloud VMs, iOS, JS sidebars, extension kit) produced a release cadence of roughly two stable releases per week and thousands of open issues. Reviewers call it a 'buggy mess' early on and 'ugly but indispensable' later.
- Agents die with the app (a fatal crash killed ~20 sessions at once); the only durable path is tmux or the cloud daemon. Loom's explicit 'Quit stops all, no surviving daemon' contract is at least predictable, but a crash should still leave resumable records and an honest 'ended' state.

## Ideas for Loom

### Actionable approval and question notifications (Allow once / Deny, one button per AskUserQuestion option, typed reply) with an advisory soft-wait (cost M)

- **Inspired by:** cmux Feed + inline banner actions (docs/feed.md; Sources/Feed/FeedCoordinator.swift ~1585-1640; CHANGELOG 0.64.23)
- **Gain:** Resolve most approvals from the banner without switching to Loom or looking at the terminal. With 3-6 parallel sessions this removes a context switch per approval and shortens the time agents sit blocked.
- **Fit:** Fits fluency and verified outcomes if the banner is dismissed and 'Allowed' is shown only after the hook response is accepted, using the same path Loom's in-app approval boxes use. The decision hook should be advisory: after ~2 minutes it returns no decision and the CLI's own prompt takes over (cmux uses 120 s). Keep 'Always' and 'Bypass' out of banners (cmux exposes them; that widens the trust surface) and require the in-app box for persistent rules. Typed replies only enabled when state is Ready/Waiting. Conflict: none with the 'never replace the CLI interface' rule since the CLI still gets a normal hook decision. Unverified: which hook(s) Loom's approval boxes already use.
- **Risks:** Notification actions can be tapped after the session moved on (stale request ids; must check the request is still pending). Hook timeout interplay with Claude's own timeout. A mistaken one-click Allow on a destructive tool; show the tool name and path in the banner body.

### Card line for 'what it is asking / last said', plus a distinct 'Waiting on background work' state (cost S)

- **Inspired by:** cmux sidebar latest-notification text and compact-status table (docs/configuration.md#sidebarcompactagentstatus); hibernation background-work guard (Sources/App/AgentHibernationTranscriptGuard+BackgroundWork.swift)
- **Gain:** A glance at the sidebar answers 'does this need me, and for what' without opening the session; 'Finished' stops lying when a background command, monitor or async subagent is still running; the Cmd+J queue becomes triage rather than hunting.
- **Fit:** Fits accurate status, with no new reads: the text comes from the hook payload (Notification/PermissionRequest) or the transcript tail Loom already reads incrementally, and background work is a derived flag from the same incremental pass (keep a per-session set of unfinished background launch ids instead of rescanning; cmux rescans up to 32 MiB). It must not use idle_prompt to claim 'needs you' (cmux issue #14308). Drift: the transcript fields (backgroundTaskId, async_launched, <\task-notification>) are undocumented, so treat them as best-effort and surface a drift notice if unknown shapes appear instead of showing false 'Finished'. Keep the third line fixed height, as cmux/t3code rows do.
- **Risks:** Undocumented transcript schema (drift). Long or sensitive question text in a sidebar card (truncate; respect a privacy toggle). Misclassifying a CI wait as idle.

### Chat lens over the real PTY session (toggle Terminal <-> Chat, same process) (cost L)

- **Inspired by:** cmux 'Open terminal as chat' (agent-chat/README.md 'Terminal chat view'; agent-chat/adapters/transcript.ts; mobile.chat.send)
- **Gain:** Gives the chat-centred reading and writing experience (rendered markdown, collapsed tool calls, a real composer with multi-line editing, history and attachments later) while the session stays a normal Claude Code CLI with full resume, hooks and subagent semantics. Long transcripts become scannable; prompts can be composed and queued comfortably.
- **Fit:** The only chat approach in this research that keeps the 'real CLI session' contract: the terminal remains the source of truth and the chat is a lens over the transcript. Loom owns the PTY, so the composer writes bracketed paste plus submit directly (no socket RPC) and Esc sends an interrupt. Gates for predictable behavior: the composer is enabled only in Ready/Idle; permission prompts, pickers and slash-command dialogs show 'answer in terminal' (or Loom's approval box); the optimistic message is confirmed only when the transcript echoes it, otherwise a failed-delivery indicator appears. Resource rules: render only visible turns, page the transcript by bounded tail reads, and draw nothing when hidden; no second agent process. Drift: depends on the transcript JSONL schema, so detect unknown record types and fall back to the terminal view. Conflict: the user must opt in to a chat-first window, since the previous contract said never to replace the CLI interface.
- **Risks:** Transcript schema changes; composer text lost or misdelivered when the TUI is in a modal state; two input surfaces create 'which one has focus' ambiguity; markdown rendering cost on very long sessions.

### Side chat as a read-only fork linked to the parent card (cost M)

- **Inspired by:** cmux Fork Conversation (CHANGELOG #7259, Sources/CachedAgentProcessIdentityValidator.swift:225 recognises --fork-session) and Vault fork-from-checkpoint (CHANGELOG 0.64.23). cmux has no side chat; fork is the closest primitive.
- **Gain:** Ask clarifying questions about the current conversation (why did it choose X, summarise the diff so far, draft the commit message) without adding turns or tokens to the main thread; the long-standing ChatGPT-style side-thread wish with the main context preserved.
- **Fit:** Implement as a Loom-owned second session started from the parent session id with Claude's fork flag (check `claude --help` at runtime and degrade with a drift notice, never pin a version), shown as a child under the parent card like a subagent but flagged 'side', and opened in the chat lens. Make it read-only by default (plan or restricted tools) so a side question cannot edit the worktree. Costs nothing when idle: it is just another stopped session record. Cost note: a fork re-reads the parent context, so the first answer costs a full context read, which the Usage page should show. Unverified: whether prompt caching is shared across a fork; test before promising it.
- **Risks:** Token cost surprises on long contexts; the fork flag or its semantics changing; users expecting the side chat answer to flow back into the main thread (it will not). Requires the chat lens or at least a compact composer to be pleasant.

### Idle parking: a manual 'Sleep' action first, then an opt-in auto-park with a background-work guard (cost M)

- **Inspired by:** cmux Agent Hibernation (docs/agent-hooks.md; Sources/App/AgentHibernationPlanner.swift, AgentHibernationController.swift) and user requests #9873 (manual Sleep) and #4927 (park a workspace)
- **Gain:** Honours the 'sessions that cost nothing when idle' wish for the many half-finished sessions a heavy user keeps open. Wake is one click, with the ended-screen snapshot already shown in the meantime.
- **Fit:** Loom already has the hard parts: Loom-owned run scope, verifiable Stop, resume of the same conversation, and the ended-screen snapshot. What is missing is the policy. Take cmux's safety checks (idle for N minutes, not visible, no unsent input, no unfinished background work, no running subagents) but avoid its costs: fire from state-change events plus a single one-shot timer per idle session instead of a repeating timer; use the incremental background-work flag from the previous idea rather than a 32 MiB rescan; require the wake to be verified (cmux checks for hooks or a live process within 90 s and offers Retry / Show command) and reported as a verified outcome. Default: manual Sleep only, with auto-park opt-in, because a mistaken kill loses background work.
- **Risks:** Hidden background work killed (monitors, detached shells, long CI waits); unsaved input; resume failing after CLI updates; users surprised when a working-looking card was parked. Mitigate with explicit 'Parked' state and a wake banner.

### Design Loom's planned cross-session message channel on cmux's delivery model, without the polling (cost L)

- **Inspired by:** cmux agent messages (docs/agent-messages.md; Sources/AgentMessageCenter.swift); herdr's wait verb (https://blog.debedb.com/2026/07/26/herdr-and-cmux-two-shapes-of-the-same-agent-multiplexer/)
- **Gain:** Lets one session hand a short result or question to another (planner to implementer, reviewer back to author) under the user's control, so multi-session workflows stop needing copy-paste. A 'wait until session X is Ready' verb would let the user's own scripts orchestrate.
- **Fit:** Keep cmux's good parts: deliver through the recipient's hooks rather than typing into its prompt; explicit states queued -> delivered -> read | failed; hold delivery while the recipient waits on a human; opt-out per session and per project; text-only with a size cap and control characters rejected; frame the text as 'not an instruction from your operator' to reduce prompt-injection. Drop the polling: cmux wakes idle Claude sessions via an asyncRewake hook that polls every ~2 s, and it leaked memory in idle sessions. Loom can deliver at the next UserPromptSubmit/Stop hook with socket push, and wake an idle session only with an explicit user approval (the existing open-session approval pattern), verifying receipt from the transcript. Authority: each message or each sender-recipient pair is user-approved or covered by a rule the user wrote; show every message in a log.
- **Risks:** Prompt injection between agents; message storms; delivery only at hook boundaries means idle recipients may never see it without a user-approved wake; hook semantics changing across CLI versions.

### Cross-session transcript search backed by one SQLite FTS5 index, built from reads Loom already does (cost M)

- **Inspired by:** cmux global search (Sources/Search/SearchIndex.swift: chunks + chunks_fts; Vault operators agent:/repo:/ws:/before:/after:)
- **Gain:** Find the session where something was decided or a command was run (a ticket key, an error message, a file path) in seconds across all projects, then resume or fork it. Directly serves the vault-and-memory way of working and the many sessions per ticket.
- **Fit:** Feed the index incrementally from the same FSEvents-triggered transcript reads that power Usage, index only user and assistant text (not tool output or terminal scrollback, which cmux also indexes and which is large and sensitive), cap the DB size, and add nothing when the search UI is closed. Deletion must be verifiable: the permanent-delete flow has to purge that session's rows and report it, otherwise the index becomes a copy of deleted data. Operators for project/ticket key/date match Loom's session metadata.
- **Risks:** Index growth and rebuild time on large histories; a second copy of sensitive conversation text on disk (document it, offer an off switch and exclusion by project); transcript schema drift breaking extraction.

### Sidebar performance budget as a test: row snapshots, no body-time mutation, hidden means no work, and 1/10/100-session regression runs (cost S)

- **Inspired by:** cmux #2586/#2487/#8843 and the follow-up budget fixture issue #9812; skills/cmux-debugging/references/runtime-pitfalls.md
- **Gain:** Protects the property that makes Loom usable all day (low CPU, no beachballs with 30+ sessions) as v2 adds more per-card data (branch, PR, last-said text, waiting state, side chats). One regression can erase the advantage over cmux.
- **Fit:** Pure alignment with 'very low resource use'. Rules to write down: (1) cards take immutable value snapshots plus action closures; no observable store below a lazy list boundary; (2) rows are Equatable and the call site keeps .equatable(); (3) no state writes from body or from the projection feeding ForEach; (4) per-card extra data arrives through one coalesced, equality-guarded projection, not a merged publisher; (5) status animations are Core Animation based, capped, and stop when occluded; (6) timers only while something is visibly animating. Add a fixture that creates 1/10/100/200 sessions and asserts idle CPU, thread-count slope and return to baseline after repeated show/hide of the window (the shape cmux's #9812 proposes).
- **Risks:** Needs a repeatable synthetic load harness without launching real CLIs; the user's rule that heavy tests and on-screen measurements run only when the computer is idle.

The issues are still open, but the code has moved.
- #9573 (1 s SessionEnd timeout leaking claude processes) is stale: injected lifecycle hooks have timeout 5 at HEAD and no timeout:1 exists in the wrapper or settings builder. #9825 is CLOSED (2026-08-27), so 'all open' is wrong.
- The #5731 measurements are from v0.64.14. At HEAD the 8 s session autosave runs on sessionPersistenceQueue and skips unchanged writes, so 'autosave on the main thread' is no longer true.
- Pricing: $40 and $160 are the figures shown under the Yearly/Monthly toggle. Monthly-billing prices on the same page are Pro $50 and Max $200. Do not quote $40 as the plain monthly price.
- coles.codes author left cmux for herdr in June and stayed on herdr after two months. The 'pick cmux for local Mac' line is advice to readers, not the author's retention choice. The Reddit OP's 100% CPU was fixed by upgrading 0.64.20 to 0.64.21 (leaked openThread loops), not by the sidebar fix.
- Hibernation is not an idle timer. Routine hibernation is off by default and only evicts the oldest idle background agents once live restorable agent terminals exceed maxLiveTerminals (12). The 'idle N minutes then park' framing in the Loom idea is Loom's own design, not cmux's.
- Lifecycle hook delivery in cmux is not CLI-to-socket call per hook. Injected Claude lifecycle hooks go through a zsh spool/enqueue script with a 0.5 s response timeout that fails open; only PermissionRequest (125 s), inbox-wait and auto-name are direct CLI invocations. Loom should not copy 'hooks call a CLI that talks to a socket' as a latency model.
- License: GPL-3.0-or-later applies to the app, but web/, the Cloudflare workers and relay services are BSL 1.1. The GitHub API license field reads NOASSERTION.
- The claim that the wrapper launches Claude with --allow-dangerously-skip-permissions is sourced only from docs/feed.md; a grep of Resources, CLI and Sources found no literal flag. Treat it as documented, not code-verified.

### Missed by the report

- Claude Code's own Stop and SubagentStop hook input has background_tasks (type shell/subagent/monitor/workflow, status, description) and session_crons (Claude Code CHANGELOG 2.1.145; typed in claude-code mods/types/claude-code.d.ts StopHookInput). cmux caches it as hadPendingBackgroundWorkAtStop to gate idle_prompt and drive the 'waiting' hourglass. This is a documented, cheap signal for Loom's 'waiting on background work' state, without transcript scanning.
- Claude's Stop hook also carries last_assistant_message, so the 'last said' sidebar line needs no transcript read (same d.ts).
- The injected hooks include an async auto-name hook on Stop (timeout 120, Resources/bin/cmux-claude-wrapper:2072) that may run a summarization subprocess; cmux auto-names sessions. The report does not mention it.
- The agent-chat sidecar fetches a model catalog from https://cmux.dev/api/agent-models (ETag, 1 h TTL, cached at ~/.cache/cmux-agent-chat/models.json), a network dependency for the chat UI that the report does not mention (agent-chat/README.md).
- Socket access has a password mode in addition to off/cmuxOnly/allowAll, and managed-device policies can force the mode (docs/configuration.md, docs/managed-device-policies.md). The wrapper's hook spool design (CMUX_CLAUDE_HOOK_SPOOL_DIR, 256 KiB payload cap, flock-based forwarder) is the real hot path for lifecycle hooks.
- The Feed has a standalone TUI (cmux feed tui, OpenTUI via Bun) and exposes feed.item.received/completed plus agent.hook.<HookEventName> on the events stream (docs/feed.md); non-Claude agents have different Feed support (Codex telemetry only, Hermes has pre_approval_request, OMP/Campfire/Rovo lifecycle only).
- A cmux.next/nightly channel and many 'cmux-app-ffi-*' pre-releases are published daily on GitHub, while stable is v0.65.2. Several freezes in #2586 were seen on nightlies that the stable build did not have (e.g. 0.64.x nightlies vs stable 0.63.2), which matters when judging how much of the CPU history reached stable users.
- Open PR count (1,632) alongside 1,698 open issues indicates a very large unmerged queue, relevant to the 'fast feature growth' reading.
- Process: issues like #14308, #19306 and #5731 are 'Confirmed customer report' entries filed from in-app feedback (Gmail-sourced), i.e. cmux triages through an automated feedback pipeline, so issue counts overstate independent bug reports.
