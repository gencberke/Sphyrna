# F4 — move-only splits of the large actors

Stage [F](../STAGE-F.md) · wave 1 · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice).

## Goal

Lower the cost of the next changes (CP4 deletion, usage, startup work) by splitting the three large `LoomCore` files along their responsibilities. Move-only: no logic change, only the access-level relaxations a split forces (stored properties cannot live in extensions).

## Context (verified in planning; line ranges approximate)

- `SessionCatalog.swift` (1,266): public types 1-148; actor 151-991 (sessions 180-345, runs 347-516, projects 517-655, titles 656-720, paged queries 721-830, private helpers 830-991); `CatalogDatabase` (schema, migration, SQLite helpers) 992-1266.
- `SessionRuntime.swift` (1,305): types/state 110-240 incl. private `CodexServer` class 202-227; queries 277-322; start/resume 330-446; stop/respond 448-514; shutdown 520-559; launch helpers 563-690 (Claude 596-690); Codex launch 690-835; Codex plumbing 855-1150; idle companion 1152-1182; observing runs 1184-1270. ~570 lines Codex.
- `ProcessSupervisor.swift` (1,476): state 25-62; registry 101-240; environment/helper jobs 241-345; launch 347-500; `adoptConversation` 502-625; scope/sampling API 638-668; stop API + shutdown 669-905; `sample(runID:)` 927-1003; stop pipeline 1011-1209; signal escalation 1210-1272; ownership sampling/guarantee/idle scopes 1273-1340; scope management 1342-1420; ledger/leader exit/catalog finish/restore 1422-1476.

## Scope

Write: `Sources/LoomCore/SessionCatalog*.swift` (new `CatalogDatabase.swift`, `SessionCatalog+Sessions.swift`, `+Runs`, `+Projects`, `+Titles`, `+Paging` or a similar grouping), `Sources/LoomCore/SessionRuntime*.swift` (`SessionRuntime+Codex.swift` for all Codex-only code incl. `CodexServer`, `SessionRuntime+Claude.swift` for the Claude launch helpers), `Sources/LoomCore/ProcessSupervisor*.swift` (`+Shutdown`, `+Scopes`, `+Sampling`, `+EnvironmentJobs`, `+CatalogCommits` or similar), `docs/ARCHITECTURE.md` §2 group table and §9 hotspots. Out of scope: any logic change, tests (they must pass unchanged), other files.

## Done when

- Do the three splits in this order and keep the tree building after each: SessionCatalog, SessionRuntime, ProcessSupervisor. Report each as its own part (the planner-reviewer commits them separately) with the list of moved line ranges.
- `git diff` shows only moves plus `private` → `internal` / `fileprivate` relaxations; no reformatting of moved code. A reviewer can verify with `git diff --color-moved=zebra --color-moved-ws=ignore-all-space` or a sorted-line comparison; include that evidence (e.g. per file: lines removed vs added, and the sorted-line set difference is only access modifiers and `extension` headers).
- Same tests green: `SessionCatalogTests`, `SessionCatalogV2Tests`, `CatalogScaleTests`, `SessionRuntimeTests`, `SessionRuntimeCodexTests`, `SessionLifecycleTests`, `ProcessSupervisorTests`, `OwnershipBoundaryTests` (if present), `RunScopeTests`, `ClaudeHookTests`.

## Checks

`swift build` after each split; the suites above (`--filter` with a regex of suite names); `git diff --check`.
