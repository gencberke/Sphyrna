# OPT1 — optimizer fixes for the core (deletion and usage)

Run 1 optimizer pass · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice). Source: the stage-closing strict review of `db06305..cfaefff` (Sources/LoomCore, Sources/loom-app, Sources/LoomLaunchOptions), 7 Oct 2026. No release blockers were found; these are the should-fix and minor items.

## Items

1. **Retry cannot fix leftovers at `verifying`.** `ConversationDeletion.verifyAndForget` only checks; `advanceDeletion` refuses to go back; a file that reappears after `provider_data` (a run that moved to another card by `/clear` and keeps writing `debug/<id>.txt`, or a start that raced the request step) leaves the record at `verifying` with `leftover_files` forever, which breaks contract §8.7 (retryable). Fix: when `verifying` finds leftovers, re-plan with the live-session check, execute the deleter and verify once more inside the same step (or move the record back to `provider_data` for this one failure). Regression test: a file recreated between `provider_data` and `verifying` (failpoint) → first attempt fails visibly, Retry completes.
2. **A missing config folder counts as success.** `removeProviderData` and the verify step skip when `FileManager.fileExists(atPath:)` is false, which is also false for an unmounted volume or a permission error. Fix: treat the folder as absent only when `lstat` gives `ENOENT` and its parent folder exists; otherwise fail the step as `config_unavailable` (visible, retryable). Test with a temp tree where the parent is missing.
3. **Delete needs a working Claude CLI.** `deletionCandidate` resolves the toolchain (login shell + `claude --version/--help`) just to find the config folder; with Claude removed from PATH no conversation can be deleted, the error is raw, and the preview spawns processes. Fix: resolve the config folder without running the CLI — the explicit profile folder (evidence `--claude-config` / toolchain profile when one already exists), else `CLAUDE_CONFIG_DIR` from the captured environment if a toolchain was already resolved in this app run, else Loom's own environment, else `~/.claude` — through `ClaudeProfileLayout`, the same rule as the usage index. A refusal is a `deletionRefused` with a readable reason. Test: no toolchain resolver call happens for preview/delete (fake resolver that fails).
4. **Usage refresh repeats full scans.** `ClaudeUsageIndex.snapshot` recomputes the 7-day `activityWindow` on every call; `UsageModel` makes 7 snapshot calls per refresh in the 7-day view and 26 in the 24-hour view (one per hour), and builds an `.all` snapshot just to set `hasHistory`. Estimated ~160 ms (7 d) to ~600 ms (24 h) per refresh at 50k messages/week on the utility queue, after every finished turn. Fix: compute the activity window once per refresh; build the hour bars and day bars from one bucketed query (a `snapshot`-level API that returns per-bucket totals for an interval and bucket size, e.g. `buckets(range:size:)`); replace the `hasHistory` snapshot with `SELECT EXISTS(SELECT 1 FROM msg)`; skip session counting for the bar buckets. Keep every number identical (existing usage tests plus a test that the hour and day bars equal the per-interval snapshots on a fixture). Record before/after timings on a generated database in `plans/experiments/run1-OPT1-usage-refresh.json`.
5. **Input can reopen during a deletion.** `SessionLifecycleController` reopens the input gate after an idle evaluation (`inputGate.reopen`), reading through unfenced catalog calls, so after an unverified deletion stop (record at `stopping`, input closed) a later idle stop can undo the deletion's close (contract §8.1). Fix: idle evaluation skips conversations with a pending deletion, or the deletion's close cannot be cleared by `reopen`. Test.
6. **The usage index keeps deleted ids.** `ClaudeUsageIndex.forget` adds three case variants of every provider id to a `forgotten` table that is never pruned, leaves the session's `symbol` row, and the usage database has no `secure_delete`, so deleted ids and encoded paths persist (CP4 plan: no permanent tombstone list; DP-CP4-6 default: keep token counts without id or path). Fix: delete the session's `symbol` row(s) and any file rows' paths for it; store forgotten ids only as SHA-256 digests (lowercased id) so the re-link guard still works without keeping ids; `PRAGMA secure_delete = ON` and a `wal_checkpoint(TRUNCATE)` after a forget; update the case-variant registration in `AppDelegate+Usage.swift` if the index lowercases itself. Test: after forget, no id bytes in the database or WAL (trace test like CP4-B's), totals unchanged, a re-read of a surviving transcript does not re-link.
7. **Cheap extras.** A stop that fails with `sessionNotRunning` because the run exited at that moment counts as stopped (re-check the run is gone). If a `/clear` adoption moves the run between reading it and stopping it, do not stop the run that now serves another card (re-check ownership right before the stop). Tests where cheap.
