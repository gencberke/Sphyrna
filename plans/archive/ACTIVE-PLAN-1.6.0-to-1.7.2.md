## 1. Founding Goals & Production Guarantees

### 1.1 Three Founding Goals of 1.6.0 ([D-83](../../DECISIONS.md))

1. **Light.** RAM, CPU, disk, and energy never tire the user, while every function stays.
2. **Sessions, not harnesses.** Sphyrna is the one central place that manages every session, whatever its harness, so work can pass between Claude and Codex, and sessions can find (read-only) or ask to open (with user approval) the sessions they need.
3. **Cost out of sight.** Subscription quota and context cost stay invisible. Nothing enters a session's context beyond the project's own instructions, except that the session knows it runs inside Sphyrna and can use some of its functions (`<= 300` characters in the plugin skill description; no appended system prompt, no hook stdout).

### 1.2 Six Acceptance Criteria for 1.6.0

1. **Visual fidelity:** Every surface matches its window in `design/reference.html` in both appearances (`Ink` and `Paper`) and all three tone casts (`Neutral`, `Warm`, `Cool`), and `docs/ARCHITECTURE.md` §11 matches what the code draws.
2. **Full gate:** `scripts/check.sh --full --idle` passes on the integrated head: release build, staged release-tree symbol check, all test targets including window tests, ownership/Stop/Quit/deletion suites, and real-Claude checks.
3. **Resource budgets & Chat stream parity:** `O-01` budgets are set from fresh C8 measurements and met; CPU40 holds (total `<= 40%` of one core at 1 MiB/s visible terminal output); and a visible Chat stream costs no more than the terminal for the same output at 600 and 6,000 chars/s. **[D-92](../../DECISIONS.md):** the budgets are set from the RC pool's C8 and met; Chat's parity moves after 1.6.0 (3.8× and 2.5× the terminal today).
4. **Session service:** One `SessionService` owns every session's lifecycle and transition state regardless of face or harness. No session is lost across face changes or app relaunches, and a session can list sessions (`"$LOOM_CLI" sessions`) and ask to open one (`"$LOOM_CLI" open`) with user approval.
5. **Cost & context guards:** Every model call Sphyrna makes on its own (`get_usage`, `generate_session_title` capped at 2,000 chars, and Remora's one background brief per day) is listed, measured, and under its ceiling; a session's context holds only the contract's additions; automated guard tests fail if either grows.
6. **Optimizer closure:** Mandatory closing review on Claude Opus 5.5 `max` / `gpt-6-astra` `xhigh` ([D-06](../../DECISIONS.md)) is complete and all blocking findings are closed. **Done** (23 Oct): 3 Blocking findings fixed and re-checked (`evidence/optimizer-160/FINDINGS.md`).

### 1.3 Pre-v2 Production Guarantees Carried Forward

- **CP1 (Ownership & launch):** Every provider process runs inside a per-run `LoomRunHost` scope (`SPAWN_PTY` or `SPAWN_STDIO`); Loom owns and stops only what it started; zero orphan processes on Stop, Quit, or crash.
- **CP2 (State & resume):** Honest state from hooks and stream wire (`Ready`, `Working`, `Waiting for you`, `Failed`, `Not running`); automatic idle stop is off ([D-38](../../DECISIONS.md)); same-session `--resume` preserves conversation, model, mode, and effort.
- **CP4 (Deletion & retention):** Verified permanent deletion of a single conversation's local Claude files using the CP4-A allowlist ([D-37](../../DECISIONS.md)), half-done delete recovery at launch, "Remove from Sphyrna Only" for protected folders ([D-69](../../DECISIONS.md) (10), DP-CP4-7), and configurable session cleanup review in Settings → Sessions (30-day review interval, 15-day minimum stale wait; nothing deleted without user confirmation).
- **CP5 (Terminal engine & CPU40):** SwiftTerm engine with dirty-rect layer backing store, 12 fps working indicator hint, and total CPU `<= 40%` of one core at 1 MiB/s visible output ([D-07](../../DECISIONS.md)).
- **Stage L (Clean loom line):** Daily-use app promoted only into the clean `~/Documents/github/loom` tree (`scripts/release/promote.sh`), signed with the stable local identity ([D-25, D-29, D-47](../../DECISIONS.md)), public on GitHub ([D-56](../../DECISIONS.md)).
- **Stages F, I, U, H, R (Hardening & macOS integration):** Production builds exclude active Codex execution while keeping Codex entries visible and non-startable ([D-28, D-69](../../DECISIONS.md)); Dock badge, menu bar item with status badge, approval notifications, Open at Login, project colours, conversation tabs, subagent tree, and single login-shell environment capture at launch (DP-CP4-8). Stage R's remaining items (first-run/empty states, crash/Force Quit guarantees, `O-01` budgets, release checklist) fold into 1.6.0's evaluation.

The profile (`evidence/core/budgets/run-c5b5dd3/`, against `evidence/core/c7/baseline/`) puts half of the busy time in the display cycle: SwiftUI's focus bridge rebuilding the key-view loop (22 %), `.textSelection` (14 %) and the row measurer; the memory is one tall row per message.
   - Candidates, by cost: a slower or cost-aware flush than 80 ms (about −40 %, a choppier stream); no selection while a message streams, and what makes the focus bridge rebuild; rows of settled blocks instead of one row per message (memory; larger and riskier).
   - The closing review's long-block cost: a fence or a tight list with no blank line is the open tail on every flush, O(n²) per message; the C8 fixture never makes one. Add two cells first (a 300-line fence; a four-backtick fence holding three-backtick ones with blank lines).
