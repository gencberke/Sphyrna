# I4 — WindowServer cost of the working indicator (R-A)

Stage [I](../STAGE-I.md) · wave 3 · protocol: [RUN-1](../RUN-1.md#protocol-for-every-implementer-slice). Depends on I1 (`IndicatorView.swift`). Exclusive measurement: hold the build slot for the whole measurement so nothing else builds.

## Goal

Know what the chase indicator costs the render server, and lower it only if the cost is real.

## Context ([I scan §5](../experiments/run1-planning-scans/I-identity.md))

- `ChaseDots.LayerView.apply()`: `CAKeyframeAnimation` on `opacity`, `.discrete`, 8 values, duration 0.8 s, repeat forever, on each of 8 dot layers; removed when not animating or windowless.
- `proc_pid_rusage` on WindowServer returns EPERM. Readable without sudo: `ps -o time= -p <pid>` (10 ms resolution), `top -l 2 -s 1 -pid <pid> -stats pid,cpu,time,idlew,power`, and the WindowServer resource-coalition counters via `proc_pidinfo(pid, 20)` + `coalition_info_resource_usage` (`cpu_time`, wakeups, `gpu_time`) as `scripts/cp5-gpu-attribution.py:62-120` already does for GPU.
- Hint candidate: `animation.preferredFrameRateRange = CAFrameRateRange(minimum: 10, maximum: 10, preferred: 10)` after `repeatCount`; effect on a discrete animation is unverified. Also evaluate `NSVisualEffectView.state = .followsWindowActiveState` for the sidebar glass (today `.active`).

## Scope

Write: `scripts/perf/indicator_cost_lib.py` (`ws_sample()`: ps TIME delta + coalition cpu/wakeups/gpu deltas), `scripts/perf/indicator_cost.py` (WindowServer columns, an interleaved A/B mode for two packages), `Sources/LoomCatalogUI/IndicatorView.swift` (the hint, behind a token in `LoomTheme.Motion`), `SidebarBackground.swift` only if measured better and visually identical, evidence file `plans/experiments/run1-I4-indicator-windowserver.json`. Out of scope: indicator design.

## Done when

- Measured, ≥5 interleaved 60 s pairs per condition on an idle desktop: chase running (1 and 3 working rows, window active, sidebar open) vs static (window inactive / sidebar collapsed); WindowServer CPU and GPU deltas with median and spread, app-side cost beside it, `NSScreen.maximumFramesPerSecond` recorded.
- If running − static exceeds noise: packages with and without the hint compared the same way; the hint stays only if it lowers the cost without visible change. If not above noise: no code change, recorded.
- Glass state evaluated the same way or explicitly skipped with reason.

## Checks

`py_compile`; `swift build`; two packages (`run1-I4-base`, `run1-I4-hint`) built in the slot; measurement run in the slot with 90 s cooldowns.
